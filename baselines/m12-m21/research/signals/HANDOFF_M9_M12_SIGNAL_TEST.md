## 2. 新旧差异：区分目录主版与真正的改动基线

### M9

交易过程为：**旧支撑与卖压衰竭重叠 → 全新复验首次H/L合格时EX转历史 → 首轮完整补回确认 → 有效期间固定锚价成交。**

| 比较项 | 目录主版M9 | 冻结v8基线 → 本次新版 |
|---|---|---|
| 支撑TTL | 3秒 | 6秒 → 不变 |
| 首轮复验窗／保持 | 500ms／100ms | 500ms／10ms滞回保持 → 不变 |
| 形成预算 | 种子确认后5秒 | 种子确认后8秒 → 不变 |
| 滚动750ms SELL上限 | 严格低于`0.65V0` | 严格低于`0.95V0` → 不变 |
| EX合法交接后的退出归属 | 保留历史定义，不作为此次单改动对照 | 旧EX当前态退出仍可能继续否决 → 改为历史事件；不再独立否决已合法交接的新复验 |

v8已有的单轮20%恢复、10ms保持、EX观察总量≤49%／单桶≤30%、交接前SELL≥50%退出、EX确认起3秒代理freshness，均照旧。不能把这些参数相对目录主版的差异计作本次新改动。也不能替换为P_EX主版阈值、P_RF两轮或COMMON末100ms严格恢复算法。

### M12

交易过程为：**近时两侧真实受击、归一化冲击可比 → Bid严格恢复且Ask仍薄 → 两组件当前有效时配对 → 有效期间固定Bid锚价成交。** 损失差异是被观察的结果。

| 比较项 | 目录主版M12 | 冻结第三轮基线 → 本次新版 |
|---|---|---|
| Bid恢复／Ask恢复上限 | ≥50%／≤30% | ≥50%／≤40% → 不变 |
| Ask自身损失比例下限 | 5% | 2% → 不变 |
| 两组件确认间隔上限 | 750ms | 1500ms → 不变 |
| 归一化冲击比`uA/uB` | `[0.25,4]` | `[0.10,10]` → 不变，含端点 |
| 归一化损失比`dA/dB` | `[0.25,4]` | `[0.10,10]` → 删除筛选，只保留诊断 |
| 跨侧关系推导的Bid损失下限 | `dB≥0.0125` | `dB≥0.002` → 同时删除；Bid自身材料性下限保留 |
| 独立轮窗／组件TTL | 500ms／3秒 | 500ms／3秒 → 不变 |

本版不是再扩大损失比范围，而是该比值不再拥有准入、择根或失效权。`u_i=H_i/Q0_i`、`d_i=L_i/Q0_i`各按本侧初始深度归一化。两侧仍须`H_i≥m_i`且`L_i≥m_i`，其中`m_i=max(0.5,0.0001Q0_i)`；Bid保留`dB≥mB/Q0B`，Ask保留`dA≥max(0.02,mA/Q0A)`。

## 3. M9：确认与失效重点检查

以下是供模块后续核对的定义预期，本次没有执行这些场景。

### 阶段、时钟和首选证据

1. 只在旧S与原生EX当前有效时配种子，冻结原Bid锚P、V0、S/AP/EX身份及cursor。同token最多一个本分支活动root；占用期间已见种子不能事后倒选。
2. `dS=cS+6s`；局部EX代理从`cEX`起计3秒，交接前`dSeed=min(dS,cEX+3s)`。代理须在原生EX有效时建立，不能等原生EX过期后补造；自然750ms到期与压力恢复等硬退出必须区分。`dForm=cSeed+8s`另行冻结。
3. 第一R由cursor之后首个合格顺序的新同P SELL开启500ms窗。跨阶段采用`(available,input_seq,subindex)>seed_cursor`；不能擅加`received>cSeed`要求，也不能把无法证明顺序的旧包当新证据。
4. q为第一R首次同时达到H、L材料性资格且事实已可得的输入键，要求`q.available<dSeed`及`<dForm`。第一笔小SELL不是q；q也不是信号确认。第一R失败不能跳过。
5. 合法q后仍须完成首轮500ms窗、20%恢复及v8滞回保持。完整确认`cR<dForm`，封口可得不晚于窗尾加50ms，发布前所有当前守卫通过。新期限为`min(cR+8s,cAP+20s)`；q、配对、下单或回执均不重启期限。

### 边界与容易遗漏的退出路径

| 检查项 | 应有行为 |
|---|---|
| 同输入首次取得H/L资格，同时滚动SELL达到`0.50V0` | 先应用交接前失效，结束root；不得先转历史再救活。无可信子序时不能假设交接在先。 |
| 合法q之后SELL从`0.40V0`升至`0.70V0` | 旧50%当前态退出只作历史记录；其余守卫通过时允许继续，仍须完成R。 |
| 合法q之后SELL达到`0.95V0` | 当前余波守卫立即结束；等号也失效。 |
| q后旧EX自然到期，或新AP导致旧EX当前态结束 | 不单凭旧EX当前态变化否决；真实SELL仍进入95%滚动检查，所有原时钟不变。 |
| q后旧S自然到期 | 合法交接后可继续观察；旧S已记录硬反证仍有效，不能替换历史S身份或让无关新S续命。 |
| 迟到证据证明原AP/EX形成不成立、来源错误或质量丢失 | 仍结束；历史身份不豁免真实性。无法判断退出原因或因果阶段时UNKNOWN结束。 |
| 滚动量统计 | 沿v8来源及去重政策计全token SELL，保留q前仍在750ms窗内的成交；不清buffer，不只计锚P的H。 |
| `m≥0.95V0` | 按基线结束无法满足量预算的复验，不放宽材料性门槛。 |
| 滞回保持 | `r≥0.20`启动10ms；`r<0.16`清计时，`r<0.08`撤销held，新低同时清两者。已有held在`0.08≤r<0.16`不撤销，但封口仍需`r≥0.20`。不得改为末10ms连续≥20%。 |
| 原P消失或量不再为正 | 结束；不另加COMMON 40%恢复floor，也不允许原档恢复后复活。 |
| 第一R失败／后续轮失败 | 第一R不合格或补回失败结束；确认后的合格后续轮补回失败结束，不合格后续轮依冻结基线不自动否决。新好轮不续期。 |
| 截止等号 | `q.available=dSeed`不交接，`cR=dForm`不确认，`now=deadline`结束。 |
| 完整输入发布边界 | 可信子序按序处理，q后子项可用交接后规则；候选和执行须等整个frame处理完，不能避开其余已知反证。 |

分阶段退出规则必须覆盖`on_fact`、滚动检查、source-end传播、代理结束及引用注册等所有消费路径。不能只删一个50%判断，仍让另一结束回调无条件否决；也不能统一忽略所有`HARD_INVALID`。

## 4. M12：确认与失效重点检查

### 组件形成、配对和时钟

1. 只计同token直接SELL击Bid、直接BUY击Ask，不能复用M9互补映射成交政策。每侧固定原档，以首笔新受击开500ms窗，Q0须为成交前量，保留完整同档路径和真实H，不滑窗挑选最佳段。
2. Bid末尾连续100ms恢复率≥0.50，期间新低或跌破0.50重置保持，封口`rB≥0.50`；Ask封口`rA≤0.40`且`dA≥0.02`，不新增Ask稳定保持。两侧各自H/L材料性条件仍须满足。
3. 水位完整、实际组件发布可得`c_i≤e_i+50ms`。从自身窗尾e_i起检查数量守卫，覆盖发布前、配对前和当前等待；不能只看发布或配对时快照。
4. 配对要求同token/generation、固定原价`P<A`、`abs(cA-cB)≤1500ms`、`0.10≤uA/uB≤10`及两组件当前有效。原档不必仍为最佳档，但必须持续存在。
5. 按`(较晚组件键, Ask组件键, Bid组件键)`升序取首个合法配对；组件键为`(confirmed_available,input_seq,subindex)`。每个Ask只发布一个root，不以损失比、恢复差或执行结果择根。
6. 组合c为实际完整发布边界，不回填。`deadline=min(cB+3s,cA+3s)`，要求`c<deadline`；从配对时重新加3秒、新好轮换组件或恢复后复活均不允许。

### 边界与残留筛选排查

| 检查项 | 应有行为 |
|---|---|
| `uA/uB=0.10`或`10` | 端点可接受，其余条件仍须通过；超出范围仍拒绝。 |
| 损失比超过旧上下限 | 不因该比值拒绝、排序、择根或失效；仅保留诊断值。 |
| 旧双比值函数或缓存 | 不得保留`comparable(u,d)`、默认d比区间、预筛选缓存或后续回调中的隐含d过滤；各条配对路径一致。 |
| Bid损失小于原推导下限 | 不再要求`dB≥0.002`或主版的0.0125；仍需`LB≥mB`。零损失或无真实受击不能形成轮次。 |
| Bid确认与守卫 | 确认要求50%恢复；轮后`FB=QminB+0.40LB`，Qbid≥FB且原P存在有效，Qbid<FB结束。等于FB不失效。 |
| Ask确认与守卫 | 确认要求恢复≤40%；轮后`FA=QminA+0.50LA`，必须`0<Qask<FA`。达到FA等号、超过FA或原A消失均结束。 |
| e_i至c_i期间曾破界，发布前又恢复 | 仍拒绝发布，不用终点快照抹掉路径反证；后续不能复活同一组件。 |
| received与available跨窗 | received在窗内的合法事件归形成统计，跨窗事件归轮后路径；未知次序标UNKNOWN，不能把处理晚等同于轮后发生。 |
| 两确认相距恰1500ms | 间隔条件允许，但必须当前有效且组合c严格早于原deadline；发布延迟不能回填或补TTL。 |
| 同边界确认与失效 | 先处理已知失效、到期及完整frame，再判断配对或执行；不得先发候选逃过反证。 |
| 后续合格轮反证 | 合格Bid严格恢复失败或合格Ask严格稳定恢复≥50%结束对应组件；未达H/L门槛的轮不自行构成恢复失败，但即时数量守卫照常生效。 |
| 去掉d筛选后更早遇到另一Bid | 依原最早键规则消费Ask，不为复现旧结果改选更晚Bid；旧新root归属可能不同。 |

定义算例：两侧Q0=100、H=20，故u比=1。Bid最低99、末量99.8，LB=1、rB=0.80；Ask最低80、末量84，LA=20、rA=0.20。其d比=20，旧第三轮拒绝，本版在完整路径及所有其他条件通过时可配对；FB=99.4、FA=90。Ask若在窗尾至发布之间曾达到90，即使发布时回到84，本版仍拒绝。此例只是SOP已有公式的预期，不是观测结果。

## 5. 共用的执行分层与不可混同项

交易语意统一为**信号有效期间在固定锚价P成交**。信号确认c、截止d、执行准入a、成交f分别记录。价格用于识别原档与执行合法性，不添加价格推进条件；自有成交不能补作缺失的形成证据。

| 层次 | 交接要求 |
|---|---|
| Maker | 已确认且当前有效后，在合法P以post-only申请并等待。队列、资金、最小量、市场时段和发送余量属于独立执行配置。 |
| Taker | 只有当前信号有效且P可主动取得对手量时才可申请；不自动切换方式、追价或续期。 |
| 真实可行性限制 | 两版均保留原Bid P正量守卫。正常未交叉同token盘口下，原Bid正量与同P主动买入没有共同准入状态。按合同记录`TAKER_NO_ADMISSION_UNDER_POSITIVE_ORIGINAL_BID_GUARD`，不删除守卫制造成交。 |
| 到期／失效 | 阻止新的本地准入并通知执行端处理在途或未成交部分；已发生成交必须保留，按有效、失效后、顺序未知分别归属。撤单请求不等于已撤成。 |
| 数量口径 | 信号形成与执行受限分开；不能把400ms发送余量等执行门槛混成信号确认条件，也不能把意向或ACK视为成交。 |

M9输入为冻结v8已核验互补映射及去重口径，M12为冻结raw-path-r3直接成交口径。不得为了统一框架而默默改成同一成交集合；缺少来源、覆盖、原档路径或因果顺序不等于无成交。
