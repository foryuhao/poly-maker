# “没有BUY记录”的证据边界

日期：2026-11-11。用于M21 v1.1的输入与阶段交接；只读源码和SOP，不是采集验收、行情测试或交易执行。M1–M20及COMMON参数不变，不新增M编号。

## 1. 三种“零”不能互换

1. **已处理的合格直接成交记录中没有BUY@A。** 这是M21可定义的观察条件，必须说明输入版本、固定A、接收区间、可得发布边界和缺口处理。
2. **本地收到的全部原始消息都已处理且没有BUY@A。** 需要额外的队列、原始批次及处理前沿证据。只有某个过滤后事件表为空，不能推出这一项。
3. **市场在这段时间绝对没有发生BUY@A。** 当前本地记录和源时间字段不足以证明这一项；未观测的远端延迟、遗漏或来源语意仍可能存在。

M21只研究明确覆盖合同下第一项的盘口模式，不把它宣传成第三项。输入在本地已知不完整时，第一项也只能是UNKNOWN，不能用空数组或sum=0代替合格负证据。固定250ms覆盖桶和50ms关闭延迟分别是所选研究规则，不能当作交易所逐笔完整性保证。

## 2. 本轮只读源码中可见的限制

| 位置 | 已读到的行为 | 不能由此推断 |
|---|---|---|
| [feed.py](../../research/maker_signals/feed.py)的`_trade` | 直接/镜像经济视图共用seen_trades；一个identity已见就continue，不再发布NORMALIZED_TRADE | 筛选mirrored=false后没有BUY，不等于原始直接消息没有BUY；先来的镜像可能占据身份 |
| 同文件`_depth`、BBO分支及`Flow.coverage`的写入位置 | 深度或一致BBO更新会给该token添加coverage记录 | 每桶有coverage不能单独证明TRADE无过滤、无缺失或全部已处理 |
| 同文件`apply`、`publish` | 一个原始rows批次处理期间atomic=true，最终再publish | 这只是读到的旧Feed发布组织；不能证明M21已有实现，也不能保证任意新消费者保持相同批次边界 |
| [service.py](../../src/polymaker/marketdata/service.py)的`_handle`和`_on_last_trade` | JSON解析失败可返回，非dict行可跳过；parse_last_trade返回None或token不在books时直接返回 | 仅依赖下游TRADE行不能解释每一条原始消息为什么缺席；这些分支本身没有发出GAP，不代表运行中发生过丢失或整个系统没有其他监测 |
| 同文件原始队列与ResearchEvent调用 | 原始消息保留一次received，拆行回调共用；TRADE payload不带原始帧身份 | 仅凭本地event_seq或同时间戳，不能证明某条记录是原始批次的最后一行 |

本次没有读取录制、日志或其他运行进程。源码hash仅登记本次读到的文件，不能当作当前服务加载版本，更不能宣称已经发现实盘故障。

## 3. 存在性守卫与成交量去重各做什么

M21的零BUY是一个存在性条件：形成期间只要出现一份合格、因果已知的直接BUY@A证据，root就不满足；不需要先把同一事件所有镜像、腿或多次分发加成一个精确总成交量才能否定“零”。反复收到这份证据也不会恢复为零。

因此，应在直接来源尚未被镜像合并或价档/方向过滤丢掉的阶段核对该守卫，或使用保持等价来源集合的输入。不能为了保留root，仅因NORMALIZED_TRADE已经有一条mirrored=true而忽略随后直接BUY的存在。另一token的镜像本身不自动当作本token直接BUY；两者身份与完整性仍按冻结输入合同判断。

已证实同一原始事件的重发，可按其首次直接接收记录归属窗口；若原事件明确在root开始前，纯重发不创造形成期新BUY。但transaction_hash相同或价格/数量/时间相同，单独都不是足够证明。重发归属不明、来源集合丢失或解析失败时，保留UNKNOWN，不能静默去掉后宣称零。

Bid的H及比较比值仍要求原SOP的直接成交量去重。存在性检查能够较早否定一个root，不意味着成交量和经济身份要求被放宽，也不把同一经济事件当成多份独立证据。

## 4. M21 v1.1的发布与晚发现规则

R1和最终R2事实均只能在当前原始输入批次已完整处理后发布。该批次所有行只按真实received和冻结输入键处理，不插值；同批后行的BUY必须先进入形成守卫，不能先发候选或订单，再把它改名为确认后的BUY。没有原始批次/等价原子交接边界时，本版能力为UNAVAILABLE。等待真实批次完成若超过原50ms关闭余量或形成截止，就按原期限失败，不能延长。

本规则不允许提前读取下一条尚未可得消息。当前批次完整也不等于整个远端流完整；发布时仍按COMMON的水位、质量和所有已知输入进行检查。存在已知缺口、来源丢弃或无法解释的待处理形成输入时，不能以“目前没看到BUY”为由通过。

最终发布时固定available确认时刻c及确认输入键。一个**之后可得**的BUY@A，只有同时满足`received>c`、输入键晚于确认键，才属于允许出现的“确认后新BUY”。如果received<=c且该事件归属于root开始之后，它是在确认后才发现的形成期/交接期证据，应在当前发现时刻终止，记录`FORMATION_BUY_DISCOVERED_AFTER_CONFIRMATION`；这覆盖两轮之间以及第二轮结束e2到确认c之间，不只覆盖两个500ms统计窗。等时刻不算新的阶段。

不得将终止时间倒填成received，也不得删除此前提交或成交；撤单在途照常保留。已知形成期BUY若在发布前发现，则直接拒绝root。因果可得时刻改变的是何时能采取行动，而不是允许把旧接收事件改成新方向接替。

若BUY确实在c后才接收且后处理，它属于本SOP接收时钟下的新流量；仍须通过来源时序、质量和数量guard。不能单凭较旧的源时间倒改统计窗口，也不能因received较新就宣称它对应市场上刚发生的成交。这正是“本地记录未观察到”与“市场从未发生”之差。

## 5. 供测试模块核对的边界例

| 已知事实 | v1.1处理 |
|---|---|
| 形成期间原始直接BUY已出现，但其NORMALIZED_TRADE被较早镜像占位抑制 | 零BUY不成立；不能从mirrored=false筛选后的空集通过 |
| 一个批次前行满足R2关闭，后行是直接BUY@A | 先完成该批次，再检查；不发布候选，不制造一次瞬间合法提交 |
| R2终点1000ms，确认1030ms；BUY于1020ms接收、1040ms才可得 | 在1040ms结束；虽不属于R2统计窗，仍不能称为确认后新BUY；保留此前实际成交 |
| 同样确认1030ms，BUY于1031ms接收、1040ms可得 | 新阶段BUY本身不结束，仍检查Ask上界、Bid底线、质量与原截止 |
| 确认1030ms，后处理BUY的received也为1030ms | 不满足严格新阶段条件，不能靠输入行号制造正时间间隔 |
| 只有BBO更新、PONG或另一token消息证明连接活着 | 不足以单独支持本token直接BUY的合格零记录 |
| 原始批次身份、成交过滤范围或关键接收时钟缺失 | UNAVAILABLE/UNKNOWN，按字段能力及运行质量分别标记；不能填零 |

这是规则算例，没有执行策略、回放或模拟。推荐附带有限审计字段：`direct_presence_input_contract, direct_origin_evidence_ref, original_batch_id, batch_complete_key, formation_buy_presence, absence_publication_key, late_formation_buy_received, late_formation_buy_available, input_filter_scope, input_gap_reasons`。不复制逐tick日志，也不由本任务新增采集。

## 6. 对研究顺序的影响

M21仍为SPEC_ONLY，暂居新候选第10；加强边界可能减少可用样本，不能推断胜率改善。未核验实际输入合同以前，能力只能标待核验或需要原始重建。原先M1–M20的缺流规则不在本轮重定义；M21 v1与v1.1须按各自SOP hash隔离，数值门槛和3秒期限不变。
