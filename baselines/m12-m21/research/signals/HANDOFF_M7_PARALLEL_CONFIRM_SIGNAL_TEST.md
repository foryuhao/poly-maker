## 2. 与原版的差异：唯一改动是顺序

| 项目 | 目录主版M7 | 冻结v7基线 → 并行确认新版 |
|---|---|---|
| AP2起点要求 | 暂停与新S都确认后，AP2首笔才能开始 | 同样要求先有S → 只要求AP2原首笔严格晚于暂停确认，不再要求晚于S确认 |
| 候选确认 | 合法AP2确认时支撑仍有效 | 改为S与AP2都当前有效的首个完整输入发布边界；允许AP2先确认再等S |
| 新承接受击轮 | 500ms、100ms保持、恢复≥50% | 100ms、10ms滞回保持、恢复≥40% → 不变 |
| 暂停窗口 | 500ms，两个250ms桶 | 500ms，两个250ms桶 → 不变 |
| 暂停BUY量上限 | 单桶≤20%V1、总量≤35%V1 | 单桶≤35%V1、总量≤50%V1 → 不变 |
| AP计算身份 | 主版引用LEGACY_COMMON普通AP | v7私有局部AP，完整750ms → 不变；不加入共享AP滚动退出 |
| 原期限 | S确认后8秒、AP2原截止、AP1根20秒的最小值 | S确认后8秒、AP2确认后750ms、AP1确认后20秒的最小值 → 不变 |

相对冻结v7没有新增数值放宽。100ms轮、40%恢复、10ms保持和35%／50%暂停量界是已有基线参数，不应计作本次顺序修订的效果。原SOP、历史备选和外部运行版本均保留。

新组合是两条链的联合：

- `AP1 → 全新承接S`。
- `AP1 → 暂停确认 → 全新再攻AP2`。
- `live(S) ∥ live(AP2) → 联合确认 → 有效期间固定P成交`。

“并行”表示允许独立形成：S可以在暂停期间完成，也可与AP2观察重叠或晚于AP2完成。**不要求S晚于暂停，不要求两个统计窗有正时长重叠；也不允许省略暂停、使用旧S或在只有一份证据时确认。**

## 3. 承接与再攻的顺序检查

### AP1、暂停和输入时钟

统计窗用received、右开区间；因果可得键为`K=(available,input_seq,subindex)`。沿冻结v7直接成交及已核验互补映射／去重口径，AP、暂停、S一致计量，不能双计镜像。AP、暂停和S均须完整覆盖、合法封口，组件确认可得不晚于各自窗尾加50ms；记录真实可得时刻，不回填。缺覆盖、来源、前置量或可证明顺序时为UNKNOWN，不当作零输入。

空闲时首个可引用私有BUY AP作为AP1，冻结ID、c1/K1、V1及`dRoot=c1+20s`。每token本分支最多一个root，忙碌期间见过的根不事后回选。AP1确认后观察完整500ms暂停，两个250ms BUY桶各≤0.35V1、总量≤0.50V1；暂停失败或未知结束root。

暂停实际确认记cp/Kp，之后只作历史。其旧局部750ms自然TTL不能限制整个AP2完成，暂停后BUY增加也不自行撤销已完成的暂停；形成真实性反证和质量失败仍有效。不能将这个暂停替换为完整EX。

### 承接S：必须是AP1之后的新证据

| 检查项 | 应有行为 |
|---|---|
| 原锚冻结 | K1之后第一笔能匹配正量Bid档的SELL冻结P；P不必一直是买一，但冻结后必须有可见Bid量。不能换档重试。 |
| 跨阶段新输入 | 按原输入键gate；不重复计AP1旧记录，也不额外加入`received>c1`筛选。无法证明先后为UNKNOWN。 |
| 真实受击材料性 | 同P首SELL开100ms窗；前置Q0>0，H为同档SELL，L=Q0−Qmin，H、L均须≥`max(0.5,0.0001Q0)`。 |
| 保持算法 | r≥0.40启动10ms计时，r<0.32清计时，r<0.16撤销held，新低同时清两者；封口须held且r≥0.40。已有held在`0.16≤r<0.32`不撤销，不能改成连续末10ms≥40%。 |
| 首选轮次 | 未达H/L门槛的轮可按v7跳过，但不换P；任一合格却恢复失败的轮结束root。首个合格且稳定的新轮固定为S。 |
| 支撑确认与维护 | 记cS和`dS=cS+8s`，保留`cS−round.start≤15s`来源界及封口最多50ms延迟。S形成不能清空已经开始的AP2 watch；选定S后不能换ID、续期。 |

S的40%是受击轮恢复门槛，不是一个新增的COMMON 40%数量floor。15秒来源上界也不替代100ms轮及封口延迟限制。当前仍按原P正量、合格失败轮、质量和原期限维护。

### AP2：必须从暂停确认之后真正开始

私有AP完整750ms，冻结对侧最多三档初始深度D>0：方向量≥`max(1,0.0001D)`、方向份额≥65%、至少2条方向记录、三个250ms桶至少2个有量且末桶有量、最大单笔≤方向量95%。不能缩短窗口或移窗截取。

| 检查项 | 应有行为 |
|---|---|
| 观察器占用 | 每方向无进行中watch且无有效同向私有AP才开新watch。AP1仍有效时不能另开BUY watch；暂停确认不清AP1，也不另建一套AP观察器绕过占用。 |
| 普通不合格watch | 完整关闭但不满足AP形成要求时没有AP事实，按v7释放watch等待下一次真实开窗；不把单笔BUY或普通不合格watch直接当AP2。缺覆盖或迟到为UNKNOWN，不能按普通不合格跳过。 |
| 首个合格再攻 | 对AP1之后首个新的合格私有BUY AP事实，检查其原`start_key>Kp`。只在结束或确认时刻晚于cp不够。 |
| 起点等号／早到再攻 | `start_key≤Kp`不合法，结束root，不能跳过这个合格再攻再选后面的AP；不能清窗口、移窗或重贴晚起点。 |
| 同available输入 | 有可信seq/subindex则按完整键严格排序；无法证明先后为UNKNOWN。满足起点关系仍不能绕过AP观察器占用。 |
| AP2早于S完成 | 不再检查`AP2.start_key>S确认键`，不因S尚未形成而报EARLY_REATTACK；仍检查root、已冻结P、已选S及质量。 |
| 固定AP2 | 合法AP2确认c2后冻结ID和`d2=c2+750ms`；等待S时继续维护，不能转历史等待、换成AP3或在同次处理回用为另一AP1。 |

沿用`restart_after_failed_attack=false`。一次导致root结束的再攻不能同时重启自身；“解除S先完成”不等于取消首选事实、失败终止或去重规则。

## 4. 联合确认时点与固定截止

候选只能在S和AP2都已完成、且同时仍有效的**首个完整输入发布边界c**确认：

`deadline = min(cS+8s, c2+750ms, c1+20s)`，要求`c < deadline`。

通常c为两组件确认时刻的较晚者；若完整frame或共同可引用边界更晚，必须记录真实c，不能回填。AP2先完成时，等待S已经消耗其750ms寿命；S先完成时也消耗自身8秒寿命。不能从联合确认、下单或ACK重新加时。

以下沿SOP定义算例说明，所有量、路径、来源及其他守卫假设合格，不是观测结果：

| 事件 | 相对AP1确认的时刻 | 意义 |
|---|---|---|
| AP1确认 | 0.00s | 根截止20.00s；原AP1同向占用仍保留 |
| 暂停确认 | 0.50s | Kp实际可得，暂停转历史 |
| AP1自然到期 | 0.75s | 不单凭自然到期结束历史根；同向AP占用释放 |
| AP2首笔开始 | 0.80s | 严格晚于Kp，使用原完整750ms窗口 |
| 新S受击轮 | 1.50–1.60s | 完整100ms新承接 |
| AP2确认 | 1.55s | AP2截止2.30s，此时只有AP2，尚不能确认候选 |
| S确认与联合发布 | 1.60s | 两者均有效，固定P及引用，截止`min(9.60,2.30,20.00)=2.30s` |

原v7会因AP2起点早于S确认而拒绝这类顺序；新版允许，但完整观察均保留。若S到2.30s才可得，到期等号先处理，不得确认。若组件早已可得但实际完整发布边界到了2.30s，同样不能回填成更早确认。

S早于暂停完成也可以参与，只要它是AP1后新证据且一直有效；S窗与AP2窗不重叠也不构成拒绝理由。全流程还受AP观察器占用、事件空档和可得延迟影响，不能把名义窗口相加宣称固定时间内必能形成。联合后信号寿命最多750ms，可能更短。

## 5. 失效条件与阶段归属

| 事件／边界 | 应有行为 |
|---|---|
| 暂停尚未确认时出现私有或共享反向AP_SELL | 按原策略结束root，不能以后用成功S/AP2恢复。 |
| 暂停已确认，尚无已确认AP2时出现反向AP | 不仅凭反向AP删除暂停历史；S、原P、质量等守卫照常检查，进行中的BUY watch仍按原完整窗口判断。 |
| AP2已确认后出现导致其退出的反向AP | 所需当前AP2结束，整个root结束；联合确认前后均适用。 |
| 私有AP当前维护 | 保留750ms原TTL、反向AP、质量/generation等来源退出；不偷偷加入共享P_AP每250ms份额60%／半量／末桶空量退出。 |
| AP2先完成，S尚未完成 | 只等待；d2到达或AP2失效即结束。不能将AP2历史化、换AP3或续期。 |
| S先完成，AP2尚未完成 | 只等待；dS到达或S失效即结束，不能用后来的好S替换。 |
| 同P合格受卖轮恢复失败 | 不论形成或当前阶段都结束；未结束的轮不因暂时未恢复提前认定失败。 |
| 不合格受卖轮 | 按冻结规则跳过，不等于可忽略原P消失、质量或原期限。 |
| 原P丢失／质量或generation异常／历史形成被证伪 | 结束，必要证据不可判断则UNKNOWN；不得因另一链同批成功救活。 |
| AP1或pause纯自然TTL到期 | 已确认为历史的证据不单独否决root，根20秒截止仍不变；真实性反证仍须处理。 |
| 任一期限等号 | `now≥dS`、`now≥d2`（相应组件已固定时），或`now≥dRoot`均结束；无联合后重新计时。 |
| 后续好S、同向新AP | 不替换已选S/AP2，不续期，不重复确认。 |
| 同一frame先成立后失效 | 处理完整frame及所有已知反证后才发布；例如S合格而随后P消失，最终不能发布候选。 |

统一顺序为当前输入质量／历史反证、数量及合格失败轮、原截止，然后形成可用事实、最后尝试联合发布。AP1/pause是历史，S/AP2是必须当前有效的证据；不能用统一的“依赖源结束”回调把两类混同，也不能统一忽略历史证据的真实性问题。

## 6. 执行方式与最小反馈字段

信号已确认且当前有效后，Maker可在合法固定P以post-only申请等待；Taker仅在P有真实可主动取得对手量且信号有效时申请。保留原Bid P正量意味着正常未交叉同token盘口下，同P Taker买入没有共同准入状态，应记录执行受限，不能删除原档守卫制造成交。

400ms发送余量、市场时段、预算、队列及延迟属于独立执行配置，不能反向成为本版形成条件。信号寿命不足某执行配置不等于信号未确认。失效先于同边界新准入；保留在途与真实成交及实际价格，顺序未知单列，不因撤单请求删账，不自动换方式、追价、续期或定义成交后平仓。

后续反馈只保留小型摘要及必要证据引用，不复制行情或逐tick日志：

| 范围 | 必要内容 |
|---|---|
| 版本和来源 | strategy/variant/version、SOP及参数hash、冻结基线hash、实际实现身份、输入与执行合同、未适配或UNKNOWN原因。 |
| 证据身份 | token/generation、AP1/pause/S/AP2原ID、固定P、V1、暂停两桶及总量；S的Q0/H/L/r/held与路径引用。 |
