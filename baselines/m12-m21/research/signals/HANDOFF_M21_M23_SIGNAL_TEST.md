## 3. M21确认与失效重点检查

### 单轮起点和确认

1. 空闲时按输入顺序检查直接SELL。事件前best_bid P与best_ask A的正量可证、P<A、同generation，且前250ms Ask覆盖和平稳条件通过时，以首笔合格SELL冻结P/A/Q0/a0及t0。初量须来自输入键更早、received不晚于SELL、source timestamp严格更早的明确原档报量，更新链连续；不能用成交后量倒推。
2. Ask前置窗`[t0−250ms,t0)`所有已知状态须满足`abs(Qask−a0)≤0.05a0`。a0是实测首笔前量，不能择优调整；这个前置窗不要求零BUY或零SELL。起点不合格不建root，只有新的真实SELL能重新检查。
3. 形成窗固定为`[t0,e)`，e=t0+500ms，原P/A全程存在，不随最优档变化换锚。已有root不另开重叠窗，形成失败不能等下一段漂亮路径补救。
4. Bid要求`H≥max(5,0.10Q0)`、`L=Q0−Qmin≥max(0.5,0.05Q0)`；末100ms连续恢复≥0.50，封口r≥0.50，新低重置稳定段。不能混用旧滞回held算法。
5. Ask冻结`g=max(0.5,0.10a0)`；末100ms持续`0<Qask≤a0−g`，封口D=a0−aend≥g。g≥a0时没有正量解，结束root。D为净减量，不是累计负跳变或可识别的逐单撤单。
6. 从t0至实际发布c（含边界），原A的直接BUY存在性必须为零；必须覆盖形成窗、e到c及发布原批次后行。原始直接记录在镜像／方向过滤前或等价完整来源集合上核对，过滤后空集、仅深度覆盖均不能证明零BUY。
7. P、A各须有窗内明确末量事件：输入键晚于本窗全部计量SELL，source严格晚于这些SELL最大source，received仍在`[t0,e)`，封口时已可得。两档可由不同事件报量；BBO、别档刷新、重建快照不能代替。

所有输入先沿COMMON处理质量和来源；未知不能填零。同token最多一个形成或等待root，不重用旧SELL或窗口。

### 发布、量界与阶段交接

窗口水位完整、当前原始批次全部处理后，在首个合法边界发布，要求`e≤c≤e+50ms`。缺少原批次身份或等价原子边界为UNAVAILABLE，超过封口延迟不等待后续好轮。冻结：

`F=Qmin+0.40L`；`U=a0−0.50D`；`deadline=c+3000ms`。

从e到实际c及随后等待全程，原P/A和质量有效，`Qbid≥F`且`0<Qask≤U`。轮后守卫按received≥e的路径检查，形成窗内合法输入仍用于形成统计，不能把处理晚误当窗后发生。中途破界又恢复不能发布。

| 重点边界 | 应有行为 |
|---|---|
| Bid封口r≥0.50 | 末量至少比F高0.10L，确认与floor存在共同状态；仍须检查e到c路径。 |
| Ask封口D>0 | aend比U低0.50D；Qask=U仍有效，严格大于U才结束。不要套用M12的Ask等号失效规则。 |
| Bid当前量恰等于F | 允许；Qbid<F结束。原P消失、质量异常不能由等号规则豁免。 |
| 发布原批次后行出现BUY@A | 先作为形成反证，不得提前发布后改称新阶段BUY；同完整边界失效先于确认。 |
| 确认后真正新的BUY@A | 须同时received>c且输入键>确认键；本身不结束，仍检查A存在、U及质量。 |
| BUY在c后才可得，但received≤c且首次接收归属本root | 属于形成反证，发现时结束；不倒填过去取消时间，不删除已有成交。received=c不能靠较后行序改为新阶段。 |
| BUY是已证明的t0前历史或原始重发 | 按真实首次接收归属；来源不明为UNKNOWN，不能静默去重或错当确认后新BUY。 |
| 后续SELL继续，但Ask未再次平稳／退量 | 不要求再出现共同响应；仍维护F/U及后续合格Bid轮严格稳定，合格Bid恢复失败结束。 |
| Ask出现补量 | 只按固定U、原档及质量等本版守卫处理，没有额外Ask RF退出或第二次前置平稳要求。 |
| 新好S、撤供或重复响应 | 不改F/U、锚或deadline，不重复确认；now≥deadline结束。 |
| 结束后再起 | 只能由received和输入键都晚于结束的全新SELL重新检查起点；执行额度不因新root自动重置。 |

定义算例：Q0=100、H=20、Qmin=80，Bid末量92且严格保持合格，则L=20、r=0.60、F=88；Ask a0=100、末量80且末100ms合格，则D=20、U=90。其他来源、零BUY、前置平稳及路径均通过时，单轮可以确认。等待中Bid=88或Ask=90允许；Bid<88、Ask>90或原档消失均结束。此例不证明市场中已产生该信号。

|---|---|---|

| 预加托与交接 | Δ≥max(5,0.20B)，100ms种子，首SELL前80%底线，合法首SELL后20%底线 | 不变，旧Fpre失败不能用较低F救回 |
| 验证与数量来源 | 首SELL后完整500ms，窗内全部SELL后的明确原P末量 | 不变，允许L=0不等于允许缺少数量路径 |

## 5. M23确认与失效重点检查

### 预加托、零SELL和首笔交接

1. 空闲时首个合格明确报量更新，在更新前已存在的best_bid P形成B→B+Δ，B>0、Δ≥max(5,0.20B)。前后量须连续可追溯；`price_change.size`是新总量，Δ用前后相减，不能把新出现的更高档当原档加托。
2. 冻结P/B/Δ/generation、前后量来源及增量事件t0。后续加量不扩大Δ、不移动B或重开计时。从t0到合法首SELL交接前持续守`Fpre=B+0.80Δ`、原P与质量。
3. 种子窗`[t0,t0+100ms)`，水位和完整批次处理后一次检查发布，`t0+100ms≤cS≤t0+150ms`。窗尾到发布中途破Fpre即失败，不能等回补择时确认。种子不授权成交。
4. 从t0至cS含边界，P上首次直接接收归属该区间的SELL须为零；同received、同批较前行的SELL也检查。过滤后空集或深度完整不代表成交完整；晚发现本区间SELL在发现时结束，原始重发按可证首次接收归属，未知归属为UNKNOWN。
5. cS后P上首笔可信直接SELL，须received>cS、输入键>种子确认键，且received与available均严格小于cS+750ms。首笔来源、阶段或截止不合格即结束，不挑下一笔；到期无首SELL也结束。
6. 处理该笔前Fpre一直有效，确认合法性后才切`F=B+0.20Δ`。若深度先破Fpre、SELL后可得，不能按事后source排序或低F救活；无法证明先后为UNKNOWN。
7. 首SELL前量Q0R须有明确P数量来源：输入键更早、received不晚于SELL、source严格更早，连续链有效；不能以B或B+Δ填缺失Q0R。tR为首SELL.received，验证窗`[tR,e)`，e=tR+500ms。

### 完整验证、发布与等待

完整500ms内统计同P去重直接SELL的H及明确数量路径最低量，`L=max(0,Q0R−Qmin_observed)`。确认需H≥max(5,0.50Δ)、H≥L，以及从合法首SELL交接开始始终Q(P)≥F、原档及质量有效。末100ms下限仍保留，但不是额外独立证据。

窗内须有明确P报量，输入键晚于全部计量SELL，source严格晚于这些SELL最大source，received仍在`[tR,e)`，封口时已可得。缺少末端证明不能由窗外回补、BBO或别档更新时间补足。无数量路径为UNKNOWN，不能填L=0。

水位越过e、原始批次处理完整后在首个合法边界发布，要求`e≤c≤e+50ms`且`c<cS+3s`。先检查全部已知反证、e到c的F路径及质量，再确认；`deadline=cS+3000ms`保持。由原窗口和首SELL条件只能推导`500ms<c−cS<1300ms`的名义关系，不代表实测耗时或成交保证。

| 重点边界 | 应有行为 |
|---|---|
| SELL.received=cS，即使输入键更晚 | 仍属种子零SELL边界，不作为合法新SELL交接。 |
| 首SELL的received或available恰等于cS+750ms | 到期等号拒绝；只在源时间早或只在received早都不够。 |
| 首SELL前Q=Fpre | 等号允许；Q<Fpre已经结束，不能随后切F救回。 |
| 同批SELL与跌量 | 仅在可信顺序下，合法SELL先交接才按F处理后续跌量；先破Fpre后才见SELL仍结束，顺序不可证为UNKNOWN。 |
| H恰等于max(5,0.50Δ)或H=L | 量界等号允许；H<L仍拒绝。取消最低L不取消真实H。 |
| 完整路径L=0或末量高于B+0.50Δ | 可以继续检查其他条件；不以旧损失下限或旧上界否决，也不要求补一个RF轮。 |
| Q(P)=F／Q(P)<F | 等号允许，严格跌破结束；任何中间破界后恢复都不能抹掉。 |
| 原始price_change批次中先破F后恢复 | 逐原数组顺序检查，结束；不能仅检查批次末态。健康完整book是一份状态，不把内部赋值的短暂清空当消失，重建generation则结束旧root。 |
| 封口后才取得窗外末量／组件发布超e+50ms | 不补认旧验证，不回填确认；迟到和缺证按质量合同处理。 |
| 确认后新SELL／补量 | 只继续维护F、原档、质量/generation/tick和原截止；不重验形成H、H≥L或RF稳定，也不抬F、改Δ或续期。 |
| now=cS+3s | 到期优先，不新准入，不从验证确认或回执另加3秒。 |
| 结束后再起 | 仅received与输入键都晚于结束的全新合格加托可起新root；旧加托与SELL不复用，执行额度不自动重置。 |

沿SOP的定义算例：B=100、Δ=50，Fpre=140、F=110。首SELL前Q0R=150，完整H=30，最低及末量145，则L=5；来源、时序和全路径均合格时新版可通过，原版会被L≥25及末段Q≤125的要求排除。若最低110，L=40>H，虽未破F也仍拒绝；若没有真实SELL，则H失败。允许更高留存不能等同于已证明成交或结算优势。

## 6. 两版不能混同的证据与时钟

| 项目 | M21 | M23 |
|---|---|---|
| 零成交证明的方向与范围 | 原Ask A的直接BUY，从首SELL t0到完整确认c含边界；前250ms平稳窗不要求零BUY | 原Bid P的直接SELL，从加托t0到种子确认cS含边界；之后必须有真实新SELL验证 |
| 真实受击与损失 | H和L都有材料性下限，严格Bid恢复≥50% | H有下限、H≥L；L可为0，不要求RF恢复 |
| 窗内末量 | P和A各有晚于全部计量SELL的明确数量来源 | P有晚于全部计量SELL的明确数量来源 |
| 当前量界 | Bid低于F结束；Ask高于U结束；两者等号允许 | 合法交接前Fpre，之后F；等号允许，没有末段数量上限 |
| 确认后BUY | 真正新BUY@A可发生，但仍守A/U；形成期迟到BUY仍是反证 | 不增加Ask方向确认，Ask只按质量／结构和实际执行合法性检查 |

两者都只计本版所需的同token直接成交，不把互补镜像当另一份直接证据。输入received统计窗、available可得边界与source数量先后各有用途，不互相替代；没有source先后证明或完整批次不能按经验补齐。原SOP的窗内末量要求保留，没有改成窗外复核，也没有新增M17式逐笔100ms复核。

## 7. 执行分层与最小反馈字段

共同目标为**信号有效期间在固定锚价P成交**。信号确认、原截止、执行准入、真实成交分开记录；价格用于原档和执行合法性，不新增价格推进方向条件。

- Maker：当前信号有效且P被动挂价合法时，以post-only申请等待。
- Taker：仅在P有可主动取得对手量且信号仍有效时申请。两版保留原Bid正量／F，正常未交叉同token盘口下与同P Taker买入没有共同准入状态，记录执行受限，不能删底线或换价制造成交。
- 资金、最小量、队列、市场时段、400ms发送余量和提交额度属于另选的执行配置；执行受限不倒改信号确认。新root不自动解除执行额度。
- 同边界失效优先于新准入，停止未发意向并通知处理在途／未成交部分。实际成交、真实价格及顺序未知的暴露均保留；取消请求不等于取消完成，不自动切换方式、重发、续期或定义成交后平仓。
