# M421 设计草案

2026-11-20。本文记录已确认的方案和实施前的验证口径。

## 行情、信号和执行

M421 接收同一份行情。M4 与 M21 保留各自的信号判断，正式信号统一输出为 M421 交易意图。意图至少包含市场、方向、正式产生的事件顺序、信号标识、截止时间和可复核的有效性证据。原始检测器来源随记录保留，用于日志、回放和归因。执行器对所有意图应用同一套 M21 执行规则。

- **定价**使用新鲜的同 token 卖一，提交前复核卖一与行情新鲜度。
- **有效期**以信号自身截止和市场交易截止中的较早者为上限。证据提前消失时停止尝试。M4 接入时拟从正式产生起最多保留 3 秒，仍须提供可复核的证据失效条件，并在影子回放中验证映射。
- **重试与补单**仅在明确零成交且信号仍有效时重试。有成交后停止补单，订单结果未决时先核对并保留资金。
- **价格保护**要求每次真实 POST 的签名限价满足 `0.50 ≤ 价格 < 0.95`。越界时可在意图有效期内等待，条件恢复后重新校验。

## 预算和方向名额

M421 每场共用 10 USDC，单信号最多 5 USDC，YES 和 NO 各一个名额。两个检测器共用预算及方向名额。

1. 候选阶段不占预算或名额。正式信号按产生顺序竞争同场同向名额。两条信号在同一帧同时成立时，按固定事件顺序裁决，使实盘与回放可以复现。
2. 首条正式信号取得预算及名额，价格越界等待期间保留占用。后来的同向信号按原产生顺序等待，同时继续检查有效性。
3. 首条信号在真实 POST 前失效且能够确认未发送时，释放预算及名额。后续仍有效的同向信号中，顺序最早的一条接手并重新校验。
4. 一旦发生真实 POST，该方向名额在本场归原信号。同一信号可按统一规则重试，即使明确零成交，后续同向信号也不接手。发送结果未决时继续保留资金占用，先核对原订单。

## 影子回放

- 用同一份录制行情和同一时钟，对照两套原始检测器的正式信号、顺序及证据。单独记录 M4 切换到 M21 执行语义后发生的价带拦截、证据失效和有效期耗尽。
- 验证先后顺序、同帧裁决、POST 前失效接手、POST 后归属、零成交重试、部分成交停止及未决订单核对。
- 比较消费延迟 P95/P99、意图送达时的年龄和因证据过期而拦截的次数。按检测器来源统计正式信号、提交与确认成交，保留同向竞争记录。

## 切换和回退

M421 在策略注册表中与 M4、M6、M21 并列。启用 M421 时，开场名单只允许 M421。它独立使用 `m421-ledgers`、`m421-journal` 和 `m421-latest.json`。旧市场按保存的策略和对应账本恢复，原订单继续按精确身份核对。

工作树的 `config/m4-live/strategies-additions.toml` 为 M421 单独启用的配置。部署时须先让旧版本进程退出，再同步新代码与名单，避免旧进程热读未知策略标识。切回 M21 时将该文件的名单改为 `["M21"]`，其他名单保持为空。同场沿用已落盘的开场决定，撤下 M421 会拦截该场后续买入，M21 在下一新场获得新额度。M421 已有订单、账本与未释放的预留继续保留。

本次直接使用离线测试和模拟请求验证执行与切换。上线前需确认使用新版 runner，并检查新场只出现 M421 的正式信号、账本和 POST。
