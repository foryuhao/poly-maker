# 多策略 Taker 共享资金池架构变更 SOP

版本 2，2026-11-18（北京时间）。已实施 M4 与 M6 接口及共享资金池，实盘切换待人工排期。随代码提供的名单只启用 M4。

## 1. 目标与现状

M4 与 M? 在同一实盘进程内复用账户身份、行情、时钟、定价和 BUY-only FAK 执行。每个策略使用独立的预算、方向名额和交易账本。用户通过人工管理入池名单控制同时运行的策略数量。资金池按账户统一验资和预留。

现有 M4 已经通过不可变 `Opportunity.price_risk` 传递价带及越界处理规则。预算和方向名额虽在 `config/m4.toml` 声明，部分运行校验仍写死 5／10 USDC，交易账本按市场 slug 寻址并以 M4 身份恢复。当前账户读数检查本场账本占款，窗口结束记录为等待平台结算。改造的主要工作是把策略约束贯通到最终发送边界，增加策略账本路由和跨场资金预留。 [策略配置](../../config/m4.toml) · [Opportunity](../../src/polymaker/m4_types.py) · [最终发送校验](../../src/polymaker/m4_live_budget.py) · [账本恢复](../../src/polymaker/m4_live_startup.py) · [账户读数](../../src/polymaker/m4_execution.py)

## 2. 策略配置、交接和账本

| 配置项 | M4 | M6 |
| --- | --- | --- |
| 来源 | `config/m4.toml` | `config/m6.toml` 的 `[live_taker]` |
| 单信号计划含费预算 | 5 USDC | 1.50 USDC |
| 每方向独立信号名额 | 1 | 1 |
| 每策略、每场总风险上限 | 10 USDC | 3.00 USDC |
| 策略身份、归因和账本归属 | 保留 M4 的现有归属 | 独立身份及账本 |
| 签名限价和越界处理 | `0.50 ≤ 限价 < 0.95`，首次拟 POST 越界即永久放弃 | `0.01 ≤ 限价 ≤ 0.19`，可在原信号有效期内等回价带 |

- 策略通过 `Opportunity` 交付下单意图。保存现有的市场／token／方向、机会身份、锚定价、信号计时原点、截止时刻和证据引用。新版本快照同时包含策略与版本、策略配置版本或指纹、归因和逻辑账本标识、单信号预算、场预算、方向名额和价格风控。已有信号时钟和任务证据格式须可恢复。执行层从快照取规则并核对开场记录，账本路径由执行层根据已登记的身份选择。
- 开场调度器读取人工启用的策略名单和各自 TOML，在场开始时冻结名单及配置快照。策略发出的 `Opportunity` 须匹配该场登记的身份和约束。行情、时钟、开场记录和停机状态由公共设施提供。
- 每个策略、每个市场使用独立交易账本。任务、占款、YES／NO 名额、禁买标记及盈亏归属于原策略和市场。同向信号的重试和补单复用原任务与名额。同一市场、同一 token、同一方向可以有来自不同策略的订单。用已保存的订单身份将查询、成交和费用精确归回原任务，同一成交只记一次。
- 人工入池从下一新场起生效。退池或单策略停机即时阻止该策略新增、重试和补单，已发送订单留在原账本核对。该策略本场的资金预留仍按原时刻到期。策略故障按策略和市场隔离。人工总停机、账户余额保护、共享行情与资金等公共依赖异常仍按各自原有作用域拦截新买入。

## 3. 开场验资与旧场预留释放

1. **T15 前一次验资。** 冻结本场启用名单和各自场预算。使用新鲜且身份核验通过的账户余额和可用授权额度，计入尚未到期的旧场预留后，可分配资金须严格大于全部启用策略的场预算之和。M4（10）和 M6（3）同时启用时，须 `>13 USDC`。旧场有完整 13 USDC 仍占用时，按同一资金口径须 `>26 USDC`。
2. **同一扣款只计一次。** 开场以 `min(核验余额, 可用授权额度)` 为资金上限。扣减旧场预留时，仅对有证据表明已反映在该资金上限里的归属扣款做抵扣，余额和授权额度变化本身不足以证明归属。证据不足按足额旧场预留核算。同一场的策略各自使用预留额度，后续每次拟发送仍检查共享资金和策略限额，预留不给订单透支权限。
3. **原子保存开场决定。** 在共享资金记录中按账户和市场保存唯一决定。资金充足时，同一事务写入 `OPEN`、名单、快照和所有策略预留。资金不足、资金读数无效或 T15 前没有完成有效开场决定，本场记为 `SKIPPED` 并保留原因。同场重启读取已保存的决定，避免重复预留。验资未通过的场次整场跳过，资金在场中改善也不补开。已有 `OPEN` 的场次仍走现有行情准备、信号质量与 T240 截止。
4. **旧场结束后 120 秒释放。** 在开场记录持久保存市场结束时刻和 `release_at = 市场结束时刻 + 120 秒`。可信市场时钟确认到期后，将该场各策略的本地预留从资金池扣减项中移除，可重复执行而只生效一次。重启保留原 `release_at`，核实当前时钟后处理已到期记录。平台负责结算，释放事件只记本地预留变化，真实可用资金取自新鲜余额和授权额度。
5. **旧单继续按原归属核对。** 旧场 `ACK`、`UNKNOWN`、`SETTLING`、成交和历史预算证据保留在原账本。到期释放资金池预留不改写这些事实，也不触发旧场补买。新场独立计算自身预算、名额和网络状态。核对旧单仍使用本执行器的精确订单身份。

例如，13:00–13:05 场的预留在 13:07 到期。13:05 新场验资时须计入旧场的未到期占用。若验资未通过，13:07 到期后仍保持跳过，13:10 新场按当时的名单、资金和未到期预留重新验资。

## 4. 复用的执行行为与审计口径

- 正式信号仍在 POST 签名限价检查前生成。`CANDIDATE`、`OPPORTUNITY_IDENTIFIED`、持久任务、真实 POST、`ACK`／`UNKNOWN`／`SETTLING`、最终 `CONFIRMED` 分开记。开场资金跳过单列。若仍能观察，记录正常生成的正式信号及未下单原因。缺失行情或准备覆盖的区间记观测缺口。
- 单信号计划含费约束仍为 `已确认含费成本 + 待确认匹配预留 + 拟签名本金 + 按限价估算的手续费 ≤ 策略配置的单信号预算`。选量继续向下寻找合法数量并核对原有 gross risk 口径与策略场预算。实际价格改善带来的增量成交和费用继续照实入账。
- 保留 0.1 份步长、签名本金分精度、至少 5 shares 或名义金额严格大于 1 USDC、交易所 FAK BUY 本金至少 1 USDC。M? 配 1 USDC 时沿用同一公式。若手续费为正且无法构造合法订单，记录对应的预算或最小量原因、零 POST。
- M4 动态定价延续原信号时钟，前 10 秒用锚定价加当时 1 tick，其后用新鲜同 token Best ask。M6 从首次尝试起用新鲜同 token Best ask，保留原结构和截止时间。每次真实 POST 前检查快照价带、官方 tick、安全时限、签名去重和网络保护，`UNKNOWN` 先核对。
- 同场恢复以开场记录、当场 settings、已保存任务和不可变证据为准。旧格式 M4 账本用原身份和保存策略恢复，包含历史固定价、等待至 T240 和历史首次 Best ask 越界规则。前瞻价带观察保持原起算、样本口径和里程碑。
- 巡检按策略、市场和独立信号对账，提交与追加次数按真实 POST 计，成交覆盖与含费 PnL 仅用最终确认记录。首版保留现有 M4 巡检及数据入口，对新路径补读；资金事件单列 `OPEN`、`SKIPPED`、到期释放、可分配金额、策略预留、余额读数时间及证据来源。

## 6. 人工切换与回滚

1. 离线通过后再定切换窗口。切换前保存版本、配置、运行 PID／启动时间、最近场次开场与账本状态、停机标记，以及仍在 120 秒窗口内的历史场。准备前一兼容版本的恢复方式。
2. 按五分钟场边界交接账户的唯一发单进程，确认前一进程已退出发送路径后再由用户启动新版本。首个新场如有尚未到期的旧场，先按其保存配置登记应计预留；若无法核对，跳过受影响的场次，等原预留期结束后的新场。保留历史核对能力和现有停机标记。
3. 用 PID、启动时间和实际运行日志验证已加载策略快照交接、开场验资和释放策略。核对新场 settings、任务和计划中的身份、策略约束及来源。第一笔自然信号出现后对账到真实 POST 和最终状态；若尚无信号，继续记录运行与开场验证，发单验证保持待完成。
4. 发生错误归因、重复预留或发送、绕过 T15／T240、价带或预算违规、资金错误释放、旧账本恢复失败，立即执行对应作用域的禁买并留存证据。停止新版本发单后，原订单仍按所属账本核对。回退的旧版本若读不懂新账本，等受影响场次结束且其资金预留期届满，再由用户在后续新场启用兼容的旧入口，同时保留新账本的核对通道。用恢复后的实际日志确认版本和状态。

## 7. 评审结论与待定事项

目前的业务规则足以进入实施。资金释放已采用场末加 120 秒，M4 和 M? 的风险、账本和资金池职责已确定。实施时确定快照字段名、数据库路径及运行标识，离线验收验证其语义。切换时间由用户另定。M? 的具体策略实现、配置及首次入池时间随该策略交付确认。回滚方案和首版仅用 M4 切换属于本 SOP 的实施建议。

## 8. M6 Taker 入池评审

M6 复用基线冻结的 RF＋LW 信号，以 BUY FAK 执行。新鲜 Best ask 须在闭区间 `[0.01, 0.19]`，越界时可在原信号有效期内等待。单信号含费和保守资金预留均不超过 1.50 USDC，单场不超过 3.00 USDC。每场每方向限一个独立信号，明确零成交后仅在原信号有效时重试。部分成交停止补单，有待确认匹配时保留资金并核对最终状态。

按现有 FAK 校验离线遍历整个签名限价区间。单笔同时满足 1.50 USDC 的计划含费上限及资金预留上限、签名本金分精度、0.1 份步长和 1 USDC 最低本金时，费率系数 0.07 下可覆盖 0.01 tick 的全部 19 个价位及 0.001 tick 的 121/181 个价位。费率系数 0.05 下分别为 19/19 和 129/181。

现有资金预留采用 `本金 + 2 × 本金 × 费率系数 + 0.000001 USDC`。每笔资金预留限定在 1.50 USDC 内，两方向各一笔的占用合计可由 3.00 USDC 场预算覆盖。细 tick 仍可能因精度无法形成合法订单，例如 0.187 的最小合法数量为 10 份，本金 1.87 USDC。逐信号验收应核对官方 tick、不可变限价、时限、发单资格与未成交原因。 [FAK 最低本金](../../src/polymaker/m4_live_budget.py#L29) · [预留算法](../../src/polymaker/execution/taker_fees.py#L27) · [官方现行费率](https://docs.polymarket.com/trading/fees) · [费率变更公告](https://docs.polymarket.com/programs/fee-and-rebate-changes-november-2026)

## 9. 实施入口与审计

- `config/m4-live/strategies.toml` 是入池名单。移除策略或创建 `runtime/trading-control/m4-strategy-stop.json` 或 `m6-strategy-stop.json` 后，本场该策略的发送闸门持续关闭。账户总停机使用原有标记。
- `research_outputs/m4_live/taker-pool.sqlite3` 保存开场、预留、释放和退池记录。M4 沿用 `ledgers/` 和 `journal/`。M6 使用 `m6-ledgers/` 和 `m6-journal/`，已有 M6 模拟账本仍由基线读取。
- 巡检报告的 `shared_taker_pool` 提供开场记录和独立的 M6 逐场信号对账。运行 `ops/m4_taker_pnl.py --strategy M6 --output-dir <目录>` 单独计算 M6 已裁定含费盈亏。原 M4 统计及价带观察继续读取原入口。
- 同场恢复保持已冻结的配置及订单身份。M6 恢复后继续核对原订单。重启使原现场盘口证据无法继续引用时，停止原任务的新增 POST。
