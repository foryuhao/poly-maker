# 跨市场 Session 独立性与启动恢复（2026-10-17）

## 用户边界与问题

用户再次明确：每个 Session 是独立交易周期，上个周期的日志不应阻止下个周期运行。
本次覆盖旧的 OBI 跨市场恢复扩展；保留同市场防重复启动与账户并发独占。

12:50 场在 account_identity 阶段被 OBI_PRIOR_SESSION_UNRESOLVED 阻断。
账户状态仍指向 12:10 场异常 Session `093f3786d7f54e2695f4538c605cc417`。
旧 recover_fence 先跟随这个指针，读取旧市场日志并清理旧候选，最终仍无条件抛出阻断；
因此不同市场之间形成了日志与旧异常状态依赖，违反用户指定的 Session 边界。

## 修改

- recover_fence 只查当前 funder + 当前 condition ID 对应的市场恢复标记。
- 当前目标没有自己的标记时，返回新周期预检；不跟随账户文件的历史 fence/session 指针。
- 前一市场 UNRESOLVED、前一市场标记丢失或损坏，不阻断另一个目标市场，也不读取旧 JSONL。
- 继续持有同一账户的排他锁，不能并发启动第二个交易 writer。
- 继续检查新周期的当前官方账户、资金、持仓、订单、盘口及时间条件，不导入旧周期的信号、成交或盈亏账本。
  资金口径沿用用户此前批准的官方启动余额策略，不在本次修改。
- 当前市场已有标记时，仍执行原同市场清理与 OBI_RESTART_NORMAL_DISABLED，不重放旧信号或重发旧候选。
  账户指针明确属于当前市场但该市场标记丢失时，仍以 OBI_RECOVERY_FENCE_MISSING 阻断。
- 不删除、改写历史日志或市场标记，不将旧异常历史状态伪造为 CLOSED。
  新周期真正创建后才按原流程记录自己的恢复指针与状态。
- 不修改补仓、最低金额、库存阈值、反转撤单、固定期限与日志格式，不自动启动交易。
