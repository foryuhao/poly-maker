# Taker 修复剩余敞口容忍方案（2026-10-21，已实现）

本文件保留用户确认的方案；代码实现与离线验证见
[实施记录](reviews/20261021_taker_residual_tolerance/README.md)。运行配置与运行状态未改。
本方案更新旧 pilot 的“任意实收超目标就停单”约定；交易所实收份额硬上限仍未得到证明。

## 已确认口径

- 判断对象是整个 Session 的实际净敞口：`Delta = YES - NO`，包含此前保留的小残仓。
- 完整核对后 `abs(Delta) <= 2.5`：结束当前 REPAIR episode，回到 NORMAL；恰好 2.5 包含在内。
- 补不足、仍与首腿同向且 `abs(Delta) > 2.5`：继续原 SL 腿修复，保持原首次价格上限。
- 补多后反向且 `abs(Delta) > 2.5`：用户已确认按现有 FIFO 建立反向 REPAIR 腿继续修复，
  从原 HD 状态按 TP/SL/T180 规则运行。新方向真正进入 SL 时才建立该方向的新价格锚点。
- 用户已确认保留并行撤 TP、发送 Taker SL；旧单核对、成交经济确认和实际费用核对完成后才能回 NORMAL。
- 回 NORMAL 仍受原 NORMAL 开仓截止时间、资金和敞口准入约束；残仓、成交成本与手续费保留。

这是一项剩余敞口状态规则，不改变成交数量/金额的核对精度。2.5 的单位为份，
不代表 2.5 美元，也不是允许每个订单无条件多买 2.5 份。

## 代码现状与真正阻断点

`rdp_sm.py::MIN_REPAIR_EXPOSURE` 已为 Decimal 2.5，`repair_required()` 使用严格 `> 2.5`。
`update_repair_episode()` 已支持确认后带小残仓回 NORMAL，`install_reverse_episode()` 已支持
确认后的反向大残仓按全 Session FIFO 建立新腿。因此不需要另设一套独立的 2.5 参数。

当前阻断在此前的 Taker 验证保护：

1. `TakerOrderTruth.observe_trade()` 把实收超过 `quantity_upper_bound` 锁存为故障。
2. `TakerTruthBook.observe()` 又对任意实收超过目标设置整场停单。
3. 故障锁存导致 `truth.complete` 和安全关闭不能通过，已有的 NORMAL/反向 REPAIR 分支无法执行。

12:10 场即是目标 5、预算 1.60、实际收 5.161291、最终净敞口 0.161291，却先被第 1 项锁住。

## 修改范围

### 1. Taker 真值与策略处置分开

在 `rdp_sm_taker_truth.py` 中保留全部原始实收和状态，不裁剪数量。
显式接受实收不确定性的 pilot，将数量预留值与交易所保证的硬上限区分。
仅超过计划预留或目标不再自动成为永久真值故障；先暂停新增订单并继续终态、旧单和费用核对。

已有明确硬上限的离线场景仍验证其约束；价格超限、订单/成交身份冲突、实际本金超预算、
实际费用超预留、终态矛盾等保护保持。
旧的“任意多买即停单”分支改为核对完成后按 Session 净敞口分流，不能只改其中一个判断。

### 2. 在途份额与资金预留随事实更新

在 `rdp_sm_sl_ledger.py` 中，已观察到的 MATCHED/MINED 实收即使超过原数量预留，
也必须完整进入执行敞口和风险区间；不能仍按旧的 5 份估计或将其裁掉。
未证实终态、未确认经济成交或未知费用继续保留相应风险和资金预留。

发单前仍执行现有 5 份敞口风控及 max_order_size/资金准入。已发出订单实收不确定时，
由真实在途事实更新风险区间并暂停新单。最终确认后的超限仓位沿用现有只减风险的准入，
不以新容差扩大后续新单风险额度。

### 3. 修复规划和执行复用现有状态机

在 `rdp_sm_sl_taker.py` / `rdp_sm_taker_execution.py` 中明确数量预留的用途，
保留原预算、最小合法量、500ms 重试间隔、固定初始卖一加一跳上限及并行 TP 交接。
不机械把单笔预留改成“目标加 2.5”：旧 TP 在途时，这会改变原敞口准入，
而且反向剩余大于 2.5 的情况按本次确认也应进入新 REPAIR。

actor 发现已观察到的超量后停止本次新增 BUY，继续核对，不根据 MATCHED 或 ACK 直接回 NORMAL。
等待全部核对成功，再由 `rdp_sm_execution.py` / `rdp_sm_path_repair.py` 的既有 episode
完成/反向安装逻辑处理。部分成交仍留下同向大残仓时，核对完成后继续原 SL。

### 4. 日志与验证状态同步

日志区分“实收超目标、等待核对”“容差内回 NORMAL”“同向继续 SL”“FIFO 反向 REPAIR”及真正故障。
记录目标、实际份额、原数量预留、确认前后 Session 净敞口、核对是否完成及阈值 2.5。
pilot 状态说明同步去掉旧的任意超目标停单描述，仍注明实收份额硬上限未证明；
不将这项策略调整标记为交易所技术条件已全部验证。
