# TP独立执行、15秒Sigma与NORMAL双向报价评估

日期：2026-10-20。状态：用户已确认A/B/C，已完成本地实现及静态检查。未启动或重启交易进程，未发送订单，未运行测试。

## 1. 用户已提出的修改

1. TP参考SL的独立执行方式改造，保留整体策略逻辑与风控约束。
2. Sigma窗口从30秒改为15秒，至少5个有效相邻样本对、累计有效观测时长至少10秒；WS重连清空样本。
3. NORMAL恢复信号侧BestBid、对侧BestBid−N×Tick的双向Maker BUY。

NORMAL当前新入场边界为T15–T120；TP/HD在T180受时间SL约束，T240停止新修复。文中所有期限维持原有session时钟，不将165秒解释为新的通用交易截止。

## 2. 用户确认的三项口径

三项均已确认：使用下述N公式及非法整批跳过处理；NORMAL/TP/SL统一15秒新Sigma；NORMAL等待成熟后再按新信号双向入场，不采用未知Sigma的默认N。

### A. N的定义

建议沿用现行TP距离换算：`N=max(1, ceil(sigma_15/tick_opposite))`，Sigma仍是现行每平方根秒的概率价格波动估计，距离沿用现行TP隐含的一秒尺度；15秒仅改变估计窗口，不额外乘sqrt(15)。Tick使用被偏移那侧Token的实际tick。

例：Sigma=0.021、对侧tick=0.01，则N=3。若tick=0.001，则N=21，而非按另一侧tick取3。建议不额外加N上限，不向合法价格边界夹价；按原最小金额/股数/价格条件核验，非法整批跳过。增加上限或夹价会改变用户提出的波动距离，需另行定义。

### B. 15秒Sigma的使用范围

建议NORMAL报价、TP首次报价及SL冲击分支统一使用15秒口径，并统一当前/as-of历史计算实现。SL的2–3秒冲击观察期、1.5倍Sigma阈值、2 tick下限、0.06回撤阈值保持。

需要确认：现行Sigma也用于SL。缩短估计窗口和成熟条件会改变其数值、可用时刻，继而改变部分SL触发时刻，即使SL公式与硬风控不变。若用户要求SL行为基准保留30秒，则需同一行情历史维护独立的15秒报价Sigma和30秒SL Sigma，并保留后者的历史覆盖。

### C. Sigma未知、或对侧订单不合法

建议NORMAL只在Sigma已成熟、两腿都合法时整批进入，不退回单向、不以Sigma=0/N=1代替未知值，不增加原定股数凑名义金额。

例如对侧Bid=0.21、tick=0.01、Sigma=0.021，则对侧价0.18；5股名义金额0.90低于现行本地1USDC约束，整批不发。恢复双向会使原先合法的单向信号因另一腿非法而被过滤，这会改变交易覆盖。

## 3. Sigma实现边界与预热效果

- 仍使用真实WS概率价格样本，每个真实秒桶保留最后有效价格，排除当前未完成秒；读缓存不制造样本，缺口不补成零波动。
- 现行相邻点时间差不超过5秒的有效性规则保留；至少5对与至少10秒须同时满足，不能用5个紧邻tick冒充10秒历史。
- 数据带market/generation/as-of边界。历史回放只取当时已知价格，不能使用未来数据给旧信号重算Sigma。
- WS重连清空概率样本；已经接受的TP价格不因Sigma未知而改价。重建后的盘口、tick、资金及旧单仍按原约束管理。
- 行情在NORMAL前后连续采样，本次可增加统一的Sigma就绪状态/原因观测，不在进入TP时重启采样。
- 若NORMAL以成熟Sigma作为准入，通常其后首次TP已经有成熟历史；但重连、样本缺口或有效时长不足仍能使TP等待，不能保证完全消除预热。
- 首次Sigma成熟需至少10秒有效时长，考虑已完成秒桶、收包和调度，实际等待可更长。应尽早订阅本市场行情，仍不早于T15入场、不延长T120入场边界。
- 窗口缩短会提高估计响应速度，同时增加估计抖动；不承诺N更小或收益更高。

## 4. TP独立执行的具体边界

参考SL的事件驱动协调与独立网络任务，采用同一进程内唯一订单写入协调器。复用订单身份、签名、持久化、资金/在途Delta预留、定向事实核对及UNKNOWN恢复能力。

TP执行目标仍受同一HD→TP/SL规则控制。首次生成合法TP目标后，准备并发起POST不等待非必要REST/普通诊断；恢复必需的持久记录和提交前本地校验保留。签名、网络回执、定向事实读取不阻塞风险事件的处理。

**不直接复制SL的连续追价行为。** TP首次价格仍按现行bid−N×tick计算；接受后固定价格，盘口或Sigma变化不触发追价。明确拒单与UNKNOWN分别处理；UNKNOWN不释放承诺、不盲目重复提交。TP不新增同向替换重叠。

TP→SL继续由已存在的SL执行器接管：及时请求撤销旧TP，按所有旧单/在途单可能成交的区间判断新SL准入；不先等整个账户关闭，但也不把旧TP当作已消失。新旧单都可能成交，实际翻向后保留FIFO成本、时间与普通HD接续。T180/T240独立边界及≤2.5股停止新修复保持。

本次未授权改变TP锁存/利润率条件、首次TP的额外保本利润上限、SL阈值、NORMAL的NONE撤单规则。上述修改不会自动修复已经登记的“TP标签下首次报价可能锁亏”问题。

建议观测时标：历史价格条件、首次可决策经济事实、模式识别、Sigma就绪、合法目标生成、签名/持久化就绪、真实POST、ACK、撤单请求/证明、MATCHED与经济证明。使用同一单调时钟，明确缺失阶段与失败原因，不以任务创建冒充POST。

## 5. NORMAL双向恢复需补齐的实现

### 批量和风险

- 同一信号事件，一次HTTP批量提交两笔BUY/PostOnly订单；批量传输不保证两笔同时接受或成交。
- 保留既有股数算法，当前基准为各5股。两腿独立校验tick、价格、最小股数/金额和最大单量，整批核验资金。
- 所有可能单边成交的情形都纳入Delta区间：若当前delta=d、两腿数量qYES/qNO，新增订单的可能区间为`[d−qNO,d+qYES]`；不能假定双成交后净为零以绕过±5限制。
- 沿用NORMAL现行周期预算门槛：按提交股数每股1USDC核验。5+5股对应10USDC门槛，而当前单向5股为5USDC；20USDC总上限不提高。
- 一腿拒绝/UNKNOWN时，及时管理另一腿并保留未决占用；不补发缺腿，不降级单向“完成本轮”。

### 期限和撤单

共享原信号事件+2秒期限；有效反转撤销两腿，NONE/同向保留，不追价、不因N/Sigma改变续期或改价。原批次未安全结束时不并发新NORMAL批次；连续同向episode一次认领规则不变。

### 双侧成交到修复的账务衔接（必须修改，非可选优化）

当前`begin_repair_episode`直接使用`quotes[0].outcome`作为方向，`update_repair_episode`把原窗口全部成交数量和成本相加；它们建立于单向开仓前提。双向恢复后，原样使用会把反侧单独成交的方向记错，或把YES5+NO3错误记录成8股单向原仓。

建议在NORMAL关闭并取得原有严格经济/订单证明后，按真实成交FIFO配对，分开保留已配对部分与未配对残仓的方向、股数、实际成本及取得时刻。残仓≤2.5沿用停止新修复规则；>2.5由真实残仓建立普通HD。只成交对侧也按该真实方向处理，不按OBI意图固定方向。后来证明升级不重置持有时间或重复重启HD。

示例：YES5、NO3实际成交后，3对单列，剩YES2按小敞口规则处理；YES3、NO5则剩NO2；若仅NO5成交，后续普通修复原仓是NO5，尽管原信号可能为YES。不能在NORMAL两腿还可能继续成交时提前把残仓当作最终独立修复目标。
