# REBALANCE 盈利修复方案

> 历史草案：当前逻辑见 [REPAIR v4：以整体正EV为目标](RDP_REPAIR_EV_DESIGN_20261018.md)，[v3](RDP_REPAIR_RISK_PNL_DESIGN_20261018.md)也已保留为历史版本。当前限定 Buy Only、Maker Only，无额外费用扣减项；允许接受残仓及受控超量，不强制每轮配平。本草案中的 SELL、主动成交、FOK/FAK、费用假设及强制等量配平规则已不适用。下文保留原方案与历史证据，不作为当前实施规范。

日期：2026-10-18，北京时间。当前为设计建议；未修改生产交易代码、订单权限或配置，未启动交易。沿用 15 USDC Session 上限和 NORMAL `committed + 实际下单股数 × 1.00 <= 15`。

## 推荐决策

将 REBALANCE 改成由开仓成交事件驱动、有净收益限价和总时间预算的单轮退出控制器。优先争取在原信号窗口内锁定小额正收益；窗口过期后转为明确的风险退出，不继续按市价抬价补仓直至五分钟结束。确认、merge 与盈利认定独立完成。

“每笔正收益”“一两秒必退出”“只做 maker”不能同时由交易程序保证；成交仍取决于流动性。现有日志也没有验证 OBI 的预测半衰期恰好为一两秒。2 秒应作为第一版要检验的策略窗口，而非已经测出的市场规律。

基础版保留 maker-only，以止住无收益约束的补仓并验证事件路径。若秒级经济退出是核心目标，建议另设 **仅 repair 的限价主动成交模式**：满足扣费后盈利门槛才用 FOK/FAK；NORMAL 保持 post-only。主动亏损退出和卖出原侧另为显式能力，不因本方案自动开启。

## 盈利价格边界

以该轮真实开仓成本为基准，而非全 Session 两侧平均成本，也不用旧轮次盈利补贴新轮次。

设实际配对数量为 Q，已分配开仓成本 C_entry，补仓总支出 C_repair，实际/保守估计费用 F，必要固定成本预算 K：

`配对净收益下界 = Q − C_entry − C_repair − F − K`

将净收益目标设为 `Q × epsilon`，只有净收益下界满足目标才属于盈利修复。第一版候选 `epsilon=0.01 USDC/对`，5 对目标为 0.05；这是拟验证参数，不是历史最优值。费用和实际到账数量未知时，不能按零费用或毛数量宣称净正收益。未到账返佣不进入准入。

等量、同价且已知每股总费用预算 f 时，补另一侧 BUY 的上限可简写为：

`repair_buy_limit = floor_tick(1 − entry_cost_per_share − epsilon − f − K/Q)`

实际代码应按全深度、净到账量和费用精度验算整笔收益；不能只检验一档价格。候选 Maker 买价取不穿价且不超过盈利上限的最积极价格，例：`min(repair_buy_limit, opposite_ask − tick)`，并保留 post-only 防穿价保护。若上限低于当前 Bid，不能把低价挂单视作高概率快速成交。

例：YES 0.60×5，目标净赚 0.01/对，忽略额外固定成本、且该次修复无费用时，NO 最多 0.39。NO 0.45 即使瞬间成交也毛亏 0.25，禁止归入盈利修复。对侧变贵时不随 Bid 上调到盈利限价之上。

若支持卖出原侧，收益边界为 `原侧 SELL 净回款 − 对应开仓成本 >= 目标收益`，同例最低卖价约 0.61，另加费用。SELL 只有在交易账户确认可卖数量和授权充分时才可用，不根据 MATCHED 标签推断 token 已可卖。

## 时钟与状态机

维护两个时钟：最终开仓信号 `t_signal` 和首次可信成交观察 `t_match`。盈利窗口候选为 `deadline = min(t_signal + 2秒, t_match + 1秒)`。取短窗口用于约束继续依赖原信号的持有时间；后续每次重挂、回执、确认都不能重置窗口。若首次成交观察已超过 `t_signal + 2秒`，立即归为过期风险处理；当前出现 8/13 的原因需要通过 user WS 新证据重新测量。

|阶段|行为|退出条件|
|---|---|---|
|入场前准备|准备本轮退出价格、合法数量、资金预算和签名上下文；仅预签，不发送未获成交支持的对侧订单|无合法修复数量/资金或实时链路未就绪，不新增方向仓位|
|开仓在途|处理 ACK、成交、撤单等独立事件；只有身份和数量可信的增量成交才增加待修复量|不把 POST ACK 当成交，不由全 Session 关闭完成触发下一阶段|
|盈利修复|有可信成交即尝试盈利退出；先判断是否存在可执行的净正主动成交，否则放一张价格受限 Maker 单|原窗口到期、鲜明反转、硬数据故障、达到盈利修复量或需进入风险退出|
|到期风险退出|撤掉未成交的开仓余量，停止依赖原信号，评估最快可实施的减仓路径；有净正机会仍优先执行|成功减少/覆盖风险，或因流动性、资金、未知状态不可执行|
|后台确认/合并|维护 MATCHED/MINED/CONFIRMED/FAILED 和真实成本，安全确认后合并释放额度|未确认收益只算暂定锁定，不记已实现净利润|

盈利修复中不再每次给予独立 3 秒，更不重试到 T300。第一版最多一次有效重报价，只有价格改善或可执行性改变才重报，绝不为行情静默 100ms 反复撤单。硬断线、序列不连续、tick 变更、来源矛盾和原窗口过期仍须执行保护；行情静默不等于发生了价格变化。

风险退出必须另行定损失预算，不能一边要求永远盈利一边无限等待。建议回放候选为每股最大可接受损失 1/2/3 tick、总处理观察窗 3/5 秒；并不是现在批准亏损成交或保证届时一定平掉。所有退出仍受实际余额、卖出数量、15 USDC 和订单未知状态约束。若无法在预算内退出，进入明确异常持仓状态、停止新增敞口并持续管理，不把它计作盈利成功或零风险，也不靠补另一侧超过 15 来绕过限制。

## 事件驱动及执行层变更

1. 接入认证 user WebSocket，按精确 order_id/trade_id/market/token/side/size/price 登记增量成交，REST 周期缓存负责复核和断线补全。先测 user WS 与当前 REST 的真实提前量，不承诺必定达到某个外部延迟。
2. 将撮合风险账本和最终确认账本分开：可信 MATCHED 可在严格限额下触发对冲，CONFIRMED 仍决定最终收益与资金释放。FAILED/RETRYING、迟到成交、重复和乱序必须有显式路径。原腿失败而对冲腿成功会形成新风险，必须停止新增并处理孤立对冲腿；不把其抹成零库存。
3. 同一轮允许开仓收尾与受控修复并行，不等待整轮 `_verify_close()` / `_wait_for_confirmation()` 返回才开始修复。**这是新的并行执行契约，不是删掉旧关闭保护。** 必须先证明数量预留、在途操作和资金不重复使用。
4. 预热 tick/version、市场和手续费约束，去掉每轮 repair 准备中的重复串行 GET；后台更新约束并按版本失效。事件处理、报价和最终准入使用本地一致证据，保留签名与落盘要求。
5. 每轮只有一条活动退出路径。对侧 BUY 与原侧 SELL 竞争同一待退出数量，不能各发全量等待“谁先成交”。切换前旧订单在途/剩余风险继续占用；撤单 ACK 不自动等于全部数量可复用。未知订单没有解决时不可重复发送同一风险预算。

最小内部字段：`entry_lot_id / t_signal / t_match / profit_deadline / entry_matched_qty / entry_confirmed_qty / entry_cost / entry_rest_max / exit_filled_qty / exit_reserved_qty / pending_order_ids / fee_context / constraints_revision`。匹配状态升级不再次累加成交数量。

## 数量和资金

保持现有 15 美元准入，再增加“可合法退出”的必要检查。标准补仓应覆盖真实未配对量，而非把有风险但不足阈值的差额当成新的 NORMAL 机会。

- 不因为待修复量小于 5 股就自动遗忘；先累计真实成交及检查合法路径，不能机械补成 5 股。
- 不为满足 1 美元名义额自动扩大修复数量并反向开出新敞口。本阶段配对优先，不携带 Favorite 目标仓位到退出完成条件中。
- 对 5 股、每对目标 0.01 的纯配对路径，若盈利限价低于 0.20，就没有满足 1 美元 BUY 最低额的等量 5 股报价。23:20 的 0.91 开仓应在这种模式下被挡住；若以后要保留，只能另行证明卖出路径或新的数量设计，不默认扩股。
- 部分成交、净到账数量、最低量、精度、费用和所有在途订单都进入同一数量守恒检查。
- 正利润配对仍须核对实际现金；亏损退出可能需要额外额度，不能拿“一美元/股”预留当成放宽 15 美元上限的授权。

## maker-only 与主动成交的边界

Polymarket 官方说明：post-only 若会立即撮合则拒绝；FOK 要么立即全量成交，要么不成交；FAK 立即成交可用部分并取消余量，价格上限仍可限制成本。因此秒级成交不能由 maker 挂单程序保证。

推荐可选执行顺序为：

1. 若真实可执行深度、费用与净到账量满足盈利门槛，且已明确开启 repair 主动成交能力：用有价格上限、数量精确受控的 FOK 完成 5 股修复。FAK 只在零碎剩余量已有处理规则后启用。
2. 否则发一张受盈利上限约束的 post-only 单，在原窗口内争取成交，最多一次有效改价。
3. 窗口结束进入风险退出，不将盈利修复上限悄悄变成无上限追价。风险退出权限、损失预算及可卖库存能力须单独实现与验证。

NORMAL 仍保持 maker-only。对侧 BUY、原侧 SELL 的选择必须考虑真实可卖量和结算限制；不能为了方案看起来有两个出口而假设两者都立即可用。主动成交需读取适用市场实际费参，正的一分钱毛价差可能被手续费吃掉，未到账返佣不能补进收益门槛。

官方机制来源（核对日期 2026-10-18）：[订单类型与价格限制](https://docs.polymarket.com/trading/place-orders)、[实时用户事件与断线恢复](https://docs.polymarket.com/trading/realtime-order-updates)、[订单/成交生命周期与余额要求](https://docs.polymarket.com/concepts/order-lifecycle)、[费用](https://docs.polymarket.com/trading/fees)。网站文档与当前项目固定 SDK/CTF 路由可能存在版本差异，开发时需在所用 SDK 的真实边界做契约测试，不能直接复制新 SDK 示例代替验证。

## 验证及实施顺序

先实施可审核的价格和时钟约束，再实施低延迟并行修复：

1. **盈利限价与单轮总时限**：保留 maker-only，在仿真中断言 13 轮中的 10 个首笔负毛收益补仓报价被正确拒绝，23:25 第三轮不因新修复逻辑突破资金限制。这只验证逻辑，不代表旧亏损会变为新利润。
2. **实时事件与双账本**：先 shadow，不发新类型交易，测可信成交观察延迟、可用数量和旧 REST 差异；补足 tick、逐帧 L2、成交量、order/trade 状态和真实撮合时间。
3. **严格事件回放**：包含原 48 个审查市场的全部 NORMAL 提交、无成交、未配平和网络故障，不只选盈利配对。对未记录的前 2 秒行情及排队位置标记未知，不能用未来成交价格回填，也不能把触及限价等同于 maker 成交。
4. **参数候选**：净目标 1/2 tick；盈利窗口 1/2/3 秒；风险退出损失预算 1/2/3 tick。按时间切分训练/留出，实际费用、延迟和部分成交进入模拟。第一版 1 tick、2 秒仅是工程起点。
5. **逐级启用**：先验证 maker 版本与 15 美元、数量守恒；若独立开启盈利主动成交，再验 FOK/FAK 和卖出能力。通过观察再扩大样本，不因回放看似盈利直接宣称实盘可复现。

主验收指标：所有真实开仓中“原信号 2 秒内、扣成本后锁定目标正收益”的比例；全部开仓的最终净收益均值、亏损尾部及超时未解决敞口。未配平、迟到失败、超时和未确认全部保留在分母及风险统计中。另测可信 MATCHED 到 POST 开始的本地调度延迟（候选 p95≤100ms）、撮合完成延迟、CONFIRMED 延迟、拒单/改价次数及异常风险持续时间。100ms/2s 是待验收目标，历史数据没有证明已能达到。

当前持久化日志不足以算出新方案的可信胜率、总收益或最佳止损阈值。能确认的是旧方案没有盈利价格约束、等待确认超出短信号窗口、重复关闭影响执行机会；不能确认的是改成新方案后哪一笔一定能提前成交获利。
