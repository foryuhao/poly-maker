# OBI 网络准入更新（2026-10-17）

后续修正：DELETE 按关闭批次统一逻辑身份，覆盖当前订单与全部已知订单的重叠范围；
详见 [重叠撤单修复](RDP_CANCEL_DEDUP_FIX_20261017.md)。以下原始去重描述由该修正补充。

本更新覆盖 2026-10-16 基线中以历史 p95 / 信号年龄加 p95 阻断准入的规则。
适用于 `obi_v1` 的 NORMAL 和 REBALANCE。保持当前同步 SDK + 专用线程池。

## 请求统计与准入

- GET、POST、DELETE 分别记录并统计，30 秒 p95 只作为诊断。
- `max_rtt_p95_ms` 保留旧配置名，但现在表示单次慢请求阈值，默认 500 ms。
- 最近 5 秒，每种方法最后最多 3 个独立操作中，至少 2 个成功请求超过阈值，暂停新批次。
  不足 3 个时，2 个独立慢操作也触发。单个慢请求只告警。
- 同一组订单的 DELETE 重试共享操作 ID，不能算成多个独立慢操作。
  每个实际 HTTP 请求仍单独记录耗时；同一操作在近期窗口内任一次慢请求都会保留慢标记。
- 连接/传输异常、408、5xx、429 直接暂停；普通业务 HTTP 拒绝、鉴权错误和本地校验异常分别记录。
  它们由原有业务/账户/订单状态检查处理，不伪装成传输超时。
- 最近请求的异常证据与 p95 分离；首次暂停时消费触发证据，旧慢请求不会在每次读取状态时重新触发暂停。

## 状态与恢复

`NORMAL → PAUSED → PROBE → NORMAL`

1. 首次暂停 2 秒。持续故障可延后当前暂停截止；在恢复阶段再次失败，暂停增加到 4 / 8 秒，最大 8 秒。
2. 故障发生时清空探测恢复历史。暂停结束后，需要故障之后连续 3 次成功且不慢的 `/time` GET；
   这 3 次均在最近 5 秒内，最新一次距现在不超过 2 秒。
3. 原有 GET 预热样本数要求（默认最近 30 秒至少 10 个）继续生效。其他 GET 不能代替 `/time` 的恢复证明。
4. PROBE 使用真实策略信号，最多一批真实订单在途；不额外发送测试订单或测试撤单。
5. GET 只证明只读连通性；写接口置信状态单独记录，缺少近期样本显示 UNKNOWN。
6. 只有真实恢复批次的 POST 和该批自然发生的写请求全部成功且不慢，并通过官方关闭核对，才回到 NORMAL。
   单个恢复写请求偏慢则保留 PROBE，继续单批验证；再次达到故障条件则重新暂停。
7. 订单结果未知或撤单未确认时保留在途批次，GET 成功和暂停计时结束都不能解除订单关闭屏障。
   后续显式官方关闭核对成功，才释放该批次。

## 发单与活动订单

提交前仍核对 100 ms 信号年龄、100 ms 接收时效、报价/方向、Tick、账户、资金、行情代次及原有订单屏障。
移除 `signal_age + historical_p95` 硬门槛；兼容字段 `max_signal_plus_rtt_ms` 不再影响准入。

NORMAL 截止仍为原信号 + 2 秒，REBALANCE 截止仍为 POST + 3 秒，慢请求不能延长期限。
活动订单不因旧 p95、单个慢请求、只读样本老化或“已有一批在途”而提前撤单。
到期、盘口失效、明确传输/服务故障、日志失败、执行故障及市场截止仍请求关闭；
429 仅暂停新批次，避免因限流额外制造立即撤单流量。原有撤单/核实流程继续执行。

## 配置

`config/config.toml`、`livecfg/config.toml` 均显式设置：

```toml
[rdp_sm.obi]
max_rtt_p95_ms = 500.0
network_recent_window_sec = 5.0
network_slow_sample_count = 3
network_slow_trigger_count = 2
network_pause_sec = 2.0
network_max_pause_sec = 8.0
network_probe_interval_sec = 0.5
```

后台探测频率为“请求完成 + 0.5 秒”。判断读取当前状态，不为每次判断额外发请求。
配置随新进程加载；本次开发没有启动、重启实盘交易。

## 可观察性

- `sm_network_request`：请求 ID、逻辑操作 ID、批次 ID、方法、路径、开始/完成 monotonic 与 wall 时间、耗时、HTTP 状态、错误类型与分类。
- `sm_network_slow_request`：单次慢请求告警。
- `sm_network_transition`：前后状态、原因、触发操作、暂停时长和截止。
- `sm_network_batch`：批次开始、未解决或完成，以及该批写请求状态。
- `sm_obi_close_requested`：首次关闭原因、时刻、截止与适用的盘口/网络证据。

传输线程只保存内存诊断事件，执行协调器将其转交已有异步日志 writer。
终端显示网络状态变化、慢请求警告和首次关闭原因；逐请求明细保留于 JSONL。
不记录凭证、签名正文或异常响应正文。
