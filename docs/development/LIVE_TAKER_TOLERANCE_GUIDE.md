# 实盘 Taker 容差与新策略接入指南

整理于 2026-11-19。适用于接入 M4／M6 共用 BUY-only FAK 执行器的策略。生产复盘以北京时间记录，历史场次以各自保存的 settings、任务计划和订单证据为准。

## 接入时先定义容差的作用域

每项容差都写清比较对象、单位、边界是否包含、触发后的动作和日志证据。把三类决定分别定下来。

| 类别 | 接入时写清的内容 | M4／M6 的经验 |
| --- | --- | --- |
| 共用算术和执行保护 | 时间量化、签名金额格式、官方 tick、订单身份、去重、资金和最终发送时限 | 复用已验证的实现，在策略正常入口和真正发送边界各做回归 |
| 策略证据及动作 | 信号依赖哪些深度、成交和互补视图，何时失效，用哪种定价，明确零成交如何重试，部分成交是否补单 | 同一条倒序消息对两种信号的影响可以不同。策略须明确证据失效后已准入任务如何处理 |
| 硬边界 | 市场、策略、token、方向、order／trade ID、签名价带、最小量、预算、市场截止和停机 | 严格核对身份及限额。近似匹配订单会造成错记、漏记或重复下单 |

接入评审时记录与现有策略的差异。数值相同的规则也要区分作用对象。例如 20 ms 的源时间回退、20 ms 的本地积压阈值、信号有效期和可用 HTTP 时间分别验证。 [多策略 Taker 接入 SOP](../architecture/MULTI_STRATEGY_TAKER_CUTOVER_SOP_20261118.md)

## 行情时间与倒序

保留交易所源时间、应用收包单调时钟、消费开始时间、信号成立与截止、签名准备和原生 HTTP 发送边界。每条原始输入保留帧序号、连接代与帧内位置。按这些时点区分上游源时间倒序、应用内等待和行情本身过期。采样日志计数只代表采到的诊断，全帧统计需要独立录制。

- **统一整数微秒比较。** 将两个时间点分别量化为整数微秒再做差，避免在 Unix epoch 上用浮点直接相减。M4／M6 当前实现的源龄范围为 `[-2 000, 500 000]` μs，本地盘口收包年龄为 `[0, 200 000]` μs。M6 曾把恰好领先本地 2 ms 算成约 2.000093 ms，导致边界输入被误拒。回归同时验证输入、盘口新鲜度及发送路径读取该盘口时的判断。 [共用微秒计算](../../src/polymaker/m4_live_numeric.py) · [M6 实盘输入](../../src/polymaker/m6_baseline/signals.py)
- **限定忽略倒序的条件。** M4 的入口对源时间回退不超过 20 ms 的旧更新跳过，并保留当前盘口。M6 依赖档位变化、直接成交和互补成交归因，实盘条件更窄。晚到源时间须严格晚于该 token 最近有效盘口的源时间，当前连接代须有可用盘口。该 token 每项增量的方向、价位、数量及随附 BBO 均须核对为无变化，单独的 BBO 更新须两侧一致。满足条件时记录 `LATE_QUOTE_NOOP_IGNORED`，保持原盘口时间、成交覆盖和信号截止。其余倒序按原规则使相关证据失效，成交、快照和 tick 更新不适用这项例外。 [M4 实盘输入](../../src/polymaker/m4_live_numeric.py) · [M6 实盘输入](../../src/polymaker/m6_baseline/signals.py)
- **保留帧内因果。** 同帧先删再补即使最终档位相同，也须保留中间变化。旧消息与更新后的盘口相同，仍可能改写先前档位变化的时间。无法证明的倒序使该 token 证据失效后，按原规则从完整快照恢复。后续快照、增量和重启均不能延长或恢复已终止的信号。依赖完整成交流的策略可参考 M1 对不确定成交量设保守上界的做法，按自身证据链另行验证。 [M6 盘口与成交适配](../../src/polymaker/m6_baseline/_signal_v7/feed.py) · [M1 时序复盘](M1_SIGNAL_TIMING_AUDIT_20261101.md)
- **积压单独治理。** M4／M6 的共享 reader 使用 O(1) 最早待处理帧查询和 64／32 帧高低水位背压。验收同时看队列峰值、收包到消费的帧龄分布、源龄、重连恢复和信号一致性。运行日志缺少实际峰值时记为未观测。M4 准入后按签名限价撮合，切到 Best ask 定价时仍须有新鲜盘口。M6 执行保留原信号有效期，发送前还要检查同 token 的新鲜 Best ask 与签名价一致。放宽时序阈值会改变信号口径，消费者积压应在收包和调度路径解决。 [共享行情接入](../../src/polymaker/taker_runner.py) · [发送边界](../../src/polymaker/m4_live_budget_market.py) · [背压运行复核](../../research_outputs/m4_taker_watch/reviews/20261119T023617-backpressure-restart/review.json)

## 签名精度、资金和余款

1. **算出合法的签名组合。** 用十进制和官方核验的同 token tick。现有 FAK BUY 使用 0.1 份步长，签名本金 `价格 × 份数` 必须是整分，并同时满足交易所本金至少 1 USDC 及「份数至少 5 或名义金额严格大于 1 USDC」。在合法格点中向下找最大可买份数。独立四舍五入签名两腿会改变有效限价。发送前复核实际签名价格、数量、预算和当场价带。 [精度与选量](../../src/polymaker/m4_live_numeric.py) · [最小买入与风控](../../src/polymaker/m4_live_budget.py)
2. **把计划预算、保守预留和实际支出分开。** 用 `已确认含费成本 + 待确认匹配占用 + 拟下单含费计划成本` 核对单信号计划预算，同时检查各策略的保守预留上限、场风险和现金。M6 的 1.50 USDC 同时限制单信号计划成本和保守预留。成交以实际份数、本金和手续费入账，价格改善可能带来更多份数。签名限价下界约束拟签名价格，低于该下界的合法改善成交仍完整入账。 [预算与预留](../../src/polymaker/m4_live_budget.py) · [实际资金上限](../../src/polymaker/m4_live_numeric.py)
3. **数值核对误差仅用于核对。** 当前共用实现用百万分之一单位核对份数和本金，用每条 maker leg 0.00001 USDC 的费差核对手续费。先对市场、token、方向、成交及所属订单身份，再比较经济数据。实际本金和含费支出仍须满足签名金额及保守预留。 [成交证据校验](../../src/polymaker/m4_live_numeric.py) · [精确订单恢复](../../src/polymaker/m4_live_budget_reconcile.py)
4. **分开确认余款、当前无合法数量和待确认占用。** M4 允许合法余款按原任务补单。确认余款不足最小本金时记 DUST。若只是当前 tick 和价位下无法构造合法数量，则按原规则等待，避免反复写准备记录。M6 看到正匹配先暂停，有最终确认的正成交就结束该信号的新买入，余款保留。明确零成交或待匹配最终失败后，按各策略的原时限和保护重新判断。多腿策略另行定义实际持仓尾差的处置阈值，跨任务保留真实份数和成本。 [M4／M6 余款状态](../../src/polymaker/m4_live_budget.py) · [多腿残余敞口案例](RDP_SM_TAKER_RESIDUAL_TOLERANCE_20261021.md)

金额回归保留这两个例子。`0.92 × 5.4 = 4.968` 违反本金分精度。M4 预算 5 USDC 时向下选 5 份，按案例费率计划含费 4.62576 USDC。M6 签名价 `0.187` 时，满足 0.1 份步长和整分本金的最小正数量是 10 份，仅本金就需 1.87 USDC。1.50 USDC 预算下记录当前无合法数量，保留信号及原因供对账。 [离线数值对照](../../research_outputs/m4_taker_watch/reviews/20261119T030020/m6-source-order-replay/shared-execution-evidence.json)

## 发送和恢复

按独立信号保存 `CANDIDATE`、`OPPORTUNITY_IDENTIFIED`、持久任务、签名准备、真实 HTTP POST、`ACK`、`UNKNOWN`、`SETTLING` 和最终 `CONFIRMED`。签名前失败、`UNSENT` 和有证据证明请求体未发出的准备单列。完成率使用至少有一笔最终确认成交的独立信号数除以准入信号数，重试归原信号。

- **超时按发送阶段处理。** 请求体已发送、响应头超时，继续按精确订单 ID 核对并保留占用。查询 HTTP 200 也须检查返回的订单及成交证据是否足以给出终态。明确零匹配的回执或可核验的发送前失败才能支持相应的零成交确认。收到 ACK 或待确认匹配时保留资金，最终确认后再记成交，失败后依原策略规则释放。 [订单核对](../../src/polymaker/m4_live_budget_reconcile.py)
- **重启保留原任务边界。** 同场读已保存的设置、定价时钟和方向名额。每次真实 POST 复核保守市场时钟、最早下单时点、截止、网络、资金和停机。旧场按精确身份继续记账。场末后 120 秒释放的是共享资金池的本地场预留，未决订单仍保留原账本的证据和占用。 [共享资金池](../../src/polymaker/taker_pool.py) · [发送与恢复](../../src/polymaker/m4_live_budget_market.py)

## 下一个策略怎么验收

1. **交付一张容差表。** 每项写规则来源、比较对象、单位、边界、触发动作、需要保留的证据和日志标识。至少覆盖源时间、收包年龄、队列等待、信号截止、新鲜报价、签名精度、费用、余款、订单未决和恢复。标明直接共用的代码及新策略有意采用的差异。
2. **同输入同钟重放。** 保存原始帧及录制覆盖，按帧和连接代对照盘口、直接及互补成交身份、候选与正式信号、失效原因和拟下单结果。覆盖纯重复、实质变动、删后加、倒序成交、多 token、重连和水位压力。每个关键边界验证刚低于、恰等于及刚高于。录制里未出现的边界单独构造用例并标明证据性质。
3. **模拟从计划到终态。** 覆盖价格和 tick 变化、精度无解、预算刚好够或差一单位、改善成交、余款、明确零成交、发送前及发出后超时、`ACK`／`SETTLING`、T240 和同场重启。用模拟网关与临时账本检查真正发送边界，核对同一签名只发一次和未确认资金的保留。历史核对使用 SQLite `mode=ro`、`query_only` 和精确所属日志。
4. **按实际运行证据移交。** 由用户切换。用新 PID、启动时间和新进程实际输出的策略标识核实加载。M6 此次在 `sm_session.signal_input_policy` 记录 `IGNORE_PROVEN_NOOP_QUOTES_WITHIN_20MS_V1`。首批场次检查心跳、行情和新旧场隔离，首个自然信号逐笔对账到真实发送及最终状态。没有自然信号时，执行验证状态保留待完成。

接入评审可以直接照这行填写，逐项给出测试和运行证据。

| 规则及共用依据 | 比较对象、单位和边界 | 容差内动作和超界动作 | 保持有效的证据 | 验收用例和运行标识 | 验证状态 |
| --- | --- | --- | --- | --- | --- |
| 源时间年龄，复用 `age_us` | 当前墙钟减交易所源时间，单位 μs，闭区间 `[-2 000, 500 000]` | 区间内进入后续质量检查，越界按源龄阻断 | 不改变信号时钟、队列水位或报价年龄 | 两端各测三点，检查行情和发单前盘口判断 | 分别填写离线、运行加载和自然信号验证 |

## M21 接入验收

M21 使用冻结的 `M21_ENDPOINT_COFLOW`。候选对应原始联合轮开始，正式信号对应冻结检测器确认。后者才能交给共用 Taker。M21 独立记录策略身份、方向名额、账本、日志和 PnL。 [M21 实盘适配](../../src/polymaker/m21_live.py) · [M21 策略配置](../../config/m4-live/m21.toml)

| 比较对象 | 边界与动作 | 核对证据 |
| --- | --- | --- |
| 源时间、收包时间、帧序 | 源龄闭区间 `[-2 000, 500 000] μs`，本地盘口收包年龄闭区间 `[0, 200 000] μs`。按整数微秒比较。源时间倒序使该 token 证据失效，包括回退 20 ms 以内的更新。完整快照重建；同一原始帧按帧内顺序处理，原始 BUY 存在证据先于正式发布。 | 源序策略标识 `M21_STRICT_SOURCE_ORDER_RAW_BUY_PRESENCE_V1`、帧与连接代、原始 BUY 守卫和重建事件 |
| 队列、信号时钟、市场时钟 | 复用共享队列和 64／32 背压。新下单须在确认后 3 秒内，证据先失效则立即截止。原生发送再次核对原截止及市场 T15、T240。 | 单调时钟、持久计划、原生发送或 `UNSENT` 证据 |
| 拟签名价格、数量、成本 | 同 token 新鲜卖一，签名价 `0.50 ≤ 价格 < 0.95`。按官方已核验 tick，0.1 份步长，整分本金，至少 1 USDC 本金，同时满足共用最小量和含费预算。价带外或当前无合法数量时，在原信号有效期内等待。合法价格改善按真实份数、本金和费入账。 | 独立价带来源、冻结报价、无合法数量原因、实际成交数据 |
| 余款、未确认金额、恢复 | 单信号 5 USDC，单场 10 USDC，每方向一个名额。明确零成交才继续尝试，正匹配待确认时保留占用，正成交确认后停止追加。重启按原任务和订单身份核对，新连接的行情不能恢复终止信号。 | 资金池决定、原订单 ID、`ACK`／`UNKNOWN`／`SETTLING`／`CONFIRMED`、原时限 |
