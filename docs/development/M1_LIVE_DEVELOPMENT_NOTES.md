# M1 当前执行规则

更新时间：2026 年 11 月 3 日，北京时间。

当前新增规则：同一场、同一方向默认最多一个独立买入机会（`max_opportunities_per_direction=1`），由虚实共用的 M1Market 在本地账本中原子准入。YES 和 NO 分别计数；一旦某机会发出 POST，即占用该方向，包含明确拒单、UNKNOWN 和 ACK，重启仍保留。该机会已有的异常重试和明确下跌 Post-only 拒单重挂继续允许，不新增方向名额；从未 POST 的跳过或中止不占用。所有候选及跳过原因照常记录，不追溯改写历史。默认因此每场最多两个方向机会，异常重试可对应最多四笔可能接受的指令；外层 5 个独立机会、20 USDC 总占款上限继续保留。

本规则自北京时间 2026-11-03 15:15 场次生效。194 项相关测试及静态检查通过；实盘与虚拟服务在该边界更新，共用源码指纹和设置指纹已核对，155 条历史虚拟指令保留。证据与改动前备份位于 `research_outputs/analysis/m1_one_per_direction_20261103/`。未制造真实试单，未查询成交或仓位。

只优化 M1，其他策略不再执行。策略根据 RF_BID 与 AP→EX 授权 Buy-only、Post-only Maker 买入，成交部分持有至平台结算。用户已明确授权开始实盘。当前实盘与公共行情虚拟服务并行运行，二者共用提交前逻辑。实盘通过独立的 `m1-live-run --live` 入口显式启用，普通 `m1-run` 仍只运行虚拟交易。

## 账户互斥和成交核对已移除

按用户要求，M1 不取得 `AccountLease`，不创建或检查通用账户/市场 fence，不检查其他策略的未完成状态。旧锁和历史标记原样保留，不再作为 M1 启动、准入或换场条件。虚拟观察服务自身的单进程锁只用于防止同一服务重复启动，不是账户互斥。

M1 执行器不再继承通用 `SMWindowExecutor` 生命周期，不创建成交处理器，不读取挂单、订单详情、成交列表或仓位，不核对部分成交、终态、库存或历史 Merge 收据。历史数据保留，不触发补单、Merge 或链上重试。

账户刷新仅并行读取余额和适用授权额度，校验单位、有限非负数值、授权身份与快照时效。不会为了成交确认而阻止新信号。资金计算仍保守扣留本地全部提交占款，不根据成交、撤单回执或未查询到订单推断退款；余额若已扣除实际成交，可能造成重复保守扣减。每场最多 5 个独立机会、20 USDC 总占款上限继续保留。每个机会的异常返回／超时共用一次额外重试，可能产生两笔实际买入；两笔均按实际合法目标金额占款，不增加信号数。公共时间 GET 用于网络健康恢复，不参与订单或成交核对。

发送结果用于记录 ACK／明确拒绝／UNKNOWN。ACK 不是成交确认。异常返回或超时允许同一机会额外签名、原信号价再 POST 一次；第一次不确定请求单独保留原 ID、报价和全部占款。再次异常不再追加未知重试；重启不会重置次数。不轮询订单、成交或仓位，也没有 T300 撤单。

## 虚拟与实盘共用 POST 前代码

两条路径均直接使用 `m1_live.M1Market`：`advance` 调度、信号选择、去重、时间/价格/积压检查、余额时效、名额与金额预留、报价、失败重试、SDK 签名和最终 guard。

`ExecutionGateway.prepare/send_prepared`、SDK `create_order/post_orders` 和 `ExecutionClobClient._post` 同样共用。签名经济值、Maker/GTC、请求体和最终 guard 完成后，才在 `_native_order_post` 分流。

- 实盘适配器负责向官方发送；只有显式 `--live` 才允许真实传输。
- 虚拟适配器在该边界写入本地模拟执行事实，不发送真实 POST/DELETE；使用临时无资金签名身份，不加载用户钱包或 `.env`。
- 实盘资金来源是余额/授权接口；虚拟资金来源是每场 20 USDC 的模型账户。两者经过相同的共享准入代码，模型账户不冒充真实账户。

虚拟 SDK 只替换原生执行结果。无需再制造订单详情、成交终态和仓位来通过通用核对。虚拟收益继续按指令价足额成交、持有至官方胜负计算，明确属于假设收益，不能作为实盘成交证据。

## 交易与场次切换

| 项目 | 当前规则 |
| --- | --- |
| 信号 | 冻结 cal-16 的 RF/AP/EX；YES、NO 分别识别，完整可见盘口包含自有挂单 |
| 新单窗口 | `[T15,T240)`；官方时间与本地单调时钟换算 |
| 价格 | RF 买档 `[0.01,0.19]`，包含两端 |
| 下单 | Buy-only、Post-only、GTC；首次使用原 RF 价格，不转 Taker |
| 金额与数量 | 每笔目标至少 1 USDC，股数向上取整到一位小数，同时满足至少 5 股和市场最小数量；0.19 × 5.3 = 1.007 USDC |
| 额度 | 每场最多 5 个独立机会；每个机会最多一笔额外的异常重试，最多 10 笔可能接受的指令；总占款不超过 20 USDC |
| 方向限制 | 默认 YES、NO 每场各一个独立机会；首次 POST 后持久占用，同一机会的既定重试不新增名额；未 POST 的跳过或中止不占用 |
| 重试 | 异常返回／超时共用一次额外原价 POST；可重试的明确拒单仍按原信号价重试至 T240。只有下跌导致的 Post-only 拒单允许改成更低的当前 best bid |
| 订单存续 | 不因原信号失效撤单，不按成交回报改价、补单、止盈、止损或配平 |
| T300 | 只结束本地观察、保存记录并切换场次；不撤单、不查询或处理订单，交给平台 |
| 持仓结算 | Hold 至用户指定的平台自动结算；不执行 Merge，不新增主动 Redeem，也不预记回款 |
| 手动停止 | 停新单，等待发送返回，保存原 ID 并保留挂单；同场重启按本地提交记录去重 |
| 本地恢复 | 仅恢复本场机会、签名 ID、发送状态和已证实失败的任务；已结束的本场不重开，不检查跨策略 fence |

`complete_window` 是虚拟和实盘共用的本地场次完成记录函数，没有网络或交易动作。T300 的 `complete=true` 只表示本场观察窗口已经结束，不表示订单终态、持仓或到账已经核实。ACK 与 UNKNOWN 均不触发撤单，原签名 ID、状态和占款原样保留。

结束记录使用 `market_end_actions=PLATFORM_MANAGED`、`execution_status=SUBMISSION_WINDOW_COMPLETE`、`settlement_policy=PLATFORM_AUTO_SETTLEMENT`、`settlement_status=AWAITING_PLATFORM_SETTLEMENT_UNVERIFIED`。真实剩余持仓不推算，`remaining_positions=null`。

## 记录与收益口径

共享账本继续记录全部有效机会、跳过原因、实际报价、预留金额、签名 ID 和发送次数。同一 RF／AP→EX 任务重试仍计一个信号。

当前执行模式记录 `fill_tracking=NOT_TRACKED`。真实成交金额、份数、成交达成率均为未知（`null`），不能把未跟踪误记为零成交，也不再用成交比例作新单或收尾条件。账本中旧成交字段与核对工具仅保留给历史数据，不被当前执行器调用。

虚拟事实与官方最终胜负仍独立保存于 `research_outputs/m1_virtual/state.sqlite3`；共享提交记录保存于 `prepost/<slug>.sqlite3`。历史记录不重算，不将旧验收时段重标为本次代码版本。

## 本次重试规则调整

- 正常接受：记 ACK，结束任务；明确拒绝按拒绝原因决定是否可重试。
- 异常返回（空响应、格式错误、缺少 ID、ID 不一致、无法判断的服务器错误等）或超时：每个独立机会合计允许一次额外 POST，异常与超时共用次数。余额、20 USDC 总占款、网络健康及 T240 截止条件仍适用。
- 普通重试总是回到原始信号价。best bid 下跌本身不构成改价授权；余额、授权、429、异常或超时也不授权改价。
- 已有明确的 Post-only 穿价拒单，且当前 best bid 低于原信号价与刚被拒绝的报价时，允许用当前 best bid 重挂。首次请求和额外原价重试都适用；每次重算合法份数及实际占款。
- 若改价请求又发生异常／超时，尚未用过的额外重试仍使用原始信号价。重试又因下跌被明确拒绝，仍可按上述例外重挂。明确拒绝没有产生第二份可能成交风险，不重复消耗异常重试次数。
- 超时导致资金快照过期时，保留待重试任务，等新鲜余额与公共时间探测确认网络恢复后再准入。不会为了尽快重试而跳过原有提交前检查。
- 原未知请求独立存于 `uncertain_posts`，追加请求保留独立签名 ID。原请求和追加请求都可能成交，不抵扣彼此的占款；重试不新增 RF／EX 机会或信号分母。
- 虚拟适配器若模拟两笔执行，就记录两份实际模拟指令和收益，不把第二笔丢掉；报告区分一个信号与两笔指令，旧记录不重算。

## 每五分钟巡检与本聊天唤醒

用户授权每五分钟检查上一场运行、及时修复明确 BUG 并持续报告。`polymaker-m1-watch.timer` 在 Asia/Shanghai 每个五分钟边界后的第 20 秒运行只读巡检器 `ops/m1_live_watch.py`，结果写入 `research_outputs/m1_live_watch/latest.json` 和逐场 reports。

当前会话没有原生 automation_update 工具，故使用服务器用户定时器及已验证的 `codex queue --thread ... --resume` 唤醒原聊天，不创建新聊天或子代理。实际诊断和修复由本聊天继续执行；巡检脚本自身不加载账户凭据、不下单、不修改策略或账本。尚在处理的审查会合并等待，避免重叠修复；唤醒失败或长时间未复核有重试状态。

每轮报告前一场的 RF/EX、有效机会、POST/ACK、拒单/未知与重试、占款、跳过原因和换场。ACK 不当作成交。网络保护与正常拒单不是自动改规则的授权；只修复有证据且可复现的实现错误，修复后先离线验证再按需更新服务。

停止巡检而不停止交易：`systemctl --user disable --now polymaker-m1-watch.timer`。停止实盘则使用前节独立命令。
