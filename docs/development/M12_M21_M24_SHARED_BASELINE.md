# M12、M21、M24 同场基准

`ops/m1223_shared72.py` 是独立模拟入口。一次固定 864 个连续五分钟市场。
三个策略共用原始行情、事件序号、可得时间、公共 tick 核对与官方结算。
每个策略使用独立 SQLite 账本、信号状态、方向名额和资金预算。
只评估原锚价立即全额假设成交，信号和锚价通过准入时即按原锚价记账。
每笔 5 USDC、每场 10 USDC、0.1 份步长、每个市场每方向一次准入。
不模拟挂单延迟、穿价、ACK 或撤单。公开成交仍用于检测信号。
M24 使用 500ms 原版。缺少可证中间路径时立即暂停新准入，先前已记的假设成交继续等待官方结算。

下一场提前 25 秒查询公开元数据和初始 tick，目标在开场前 5 秒订阅。
相邻两场可以短时重叠，旧场结算和压缩封存独立进行。
封口按三策略共用序号，主汇总仅使用三者均完整且已有官方结果的市场。
公共输入路径不会读取本地账户账本，样本资格明确标记为账户活动未复核。
断流、超时、资金占用和待结算记录保留在逐场报告与账本。

## 存储

每场只录一次 Zstandard 压缩原始事件，包含接收与可得时钟、tick 和结算。
各策略的闭合 SQLite 经过无损压缩、解压哈希核验后保存，旁证和逐场报告一并保留。
活跃账本与已封存账本都计入 **20 GiB** 输出预算。
距输出上限或磁盘保留线 256 MiB 时开始受控收尾，容量停机记为部分完成。
项目盘保留 **5 GiB**。同盘输出的预检要求 **25 GiB** 可用，独立输出盘需要
20 GiB 可用，同时要求项目盘至少留出 5 GiB。已有归档的长期压缩率取决于行情和信号密度。

只读检查使用下列入口，挂载点下应预先存在专用数据目录。

```bash
PYTHONPATH=ops:research:src .venv/bin/python ops/m1223_shared72.py check \
  --storage-root /mnt/research/m122124_baseline
```

`replay` 使用已封存的单场 `input.jsonl.zst` 和相同源码配置，在新目录生成三套账本。
回放逐条验证输入序号和策略版本。已封存账本可以用 zstd 解压并和
`market-report.json` 内的原 SQLite SHA-256 核对。
