# M1234 交易模拟升级工作项清单

日期：2026-11-05。执行交接：Sol 实施，完成后交回独立验证。

## 目标与完成范围

把当前 M234 信号测试扩展为包含 M1 的统一公共行情研究系统。M1、M2、M3、M4 在同源有序行情上分别识别信号、生成模拟订单，模拟延迟、排队、部分成交、撤单与未知状态，维护资金和持仓，并按官方结果结算。系统同时支持实时前向模拟和确定性回放。

本轮交付是可运行、可回放、可核账的交易模拟系统。固定策略作为首版决策规则；完成不以盈利、信号次数或真实成交预测准确率达到某个值为条件。不得用“收益不错”替代工程验收，也不得用模拟运行通过宣称模型已经实盘校准。

设计背景：[M1234 交易模拟升级方案](M1234_TRADING_SIMULATION_DESIGN_20261105.md)。本工作清单明确首版范围与验收，实施中以最新用户指令为先；源码和运行设置的现状由 W00 重新冻结。

## W04 提取通用订单生命周期与延迟模拟

依赖：W01、W03。

- [ ] 从历史 PaperBroker 提取与策略无关的状态迁移，去掉对 M1 claim/RF/EX、单活动订单和固定预算的依赖。

## W05 实现可审计的排队与部分成交

依赖：W01、W04。

- [ ] 以模型到达时的可用盘口初始化队列，显式处理接收延迟造成的盘口时点不确定性。
- [ ] 实现 trades-only：合格直接成交先消耗前方队列，再填充剩余挂单；未知深度下降不直接创造成交。
- [ ] 实现撤单分配敏感性情景，参数冻结。聚合深度无法唯一分解新增/撤单时，将所用分解记为假设而非市场事实。
- [ ] 校验公开成交消息身份，区分真实重复与同一交易哈希下多个匹配；无法区分时保留歧义，不机械按 `(tx, token, price)` 丢弃。
- [ ] 防止成交与对应深度更新重复扣量；互补派生流不能再消耗一份成交量。首版直接成交覆盖缺口明确记录。
- [ ] 同一 profile/情景中的多个订单共享一条模拟队列和成交量，处理它们之间的先后位置。不同反事实账户独立运行，报告不得相加。
- [ ] 部分成交以 Decimal 等精确金额/份数计算，成交量不超过可用量和自身剩余量。

交付：队列模型、事件去重/归因模块、可逐笔解释的成交轨迹。

验收：至少包含手工可核对案例“前方 80 份，后续 85 份合格卖出，自身成交 5 份”；另覆盖多订单、重复消息、多匹配、深度下降、互补流和价格穿越。不得声称 trades-only 是真实收益下界。

## 独立验证时的阻断项

下列任一情况存在，不能验收为“已把交易纳入模型”：

1. 提交成功、ACK、价格触及或不明深度下降仍会直接制造满额成交。
2. M1 接入改变 M2/M3/M4 的信号语义，或策略之间互相清除状态/消费机会。
3. T240 停止处理已有订单，或 T300 直接伪造订单已取消。
4. 同一成交量在一个模拟账户中被多次使用，成交与深度重复扣量，互补视图重复制造成交。
5. 成交、现金、预留、库存和结算不能逐事件核对，未知状态被记为零成交或零损失。
6. 模拟入口可落到真实交易传输，或为完成本任务启动真实试单。
7. 无法用记录重现核心结果，或混用不同模型/参数版本的收益。
8. 把假设成交、模型成交、真实成交混成一项；将有限公共试运行或未校准模型称为已证明盈利。
