## 研究定义

先采集 `AP_BUY 确认 → 此后新形成 RF_BID` 的候选过程。BUY 减弱程度不作为采集门槛，
候选不等同于已经确认有效的 M2。以既有 M1 的 AP 成交流算法、RF 固定队列算法为只读依赖，
不复制、不修改其实现。AP 表示成交流进攻证据，不额外宣称逐笔成交与 Ask 深度消耗已一一归因。

- AP_BUY 使用冻结的 M1 cal-16 参数：750ms 窗口，最小 1 股和深度比例条件，BUY 占比至少
  65%，至少 2 笔、覆盖规定子窗口，单笔集中度不超过 95%。
- 每次 AP_BUY 确认后清除此前 RF 轮次；同方向新的 AP_BUY 确认替换旧参照并重新开始承接。
- RF 沿用 2 轮、每轮 500ms、同档位恢复和 100ms 维持检查；具体恢复迟滞规则完全由原实现负责。
- 买入速率参照是 AP_BUY 确认窗口的 BUY 量。候选存续期间每 250ms 记录最近同长度窗口的
  BUY/参照量，以及 SELL 量、排除的 BUY 量和覆盖情况。比较窗口必须完整位于 AP 确认之后。
- BUY 比例上界将被容差排除的 BUY 量加入分子，避免遗漏成交制造虚假衰减。
- AP 参照最多 20 秒；RF 最多 8 秒，两者取较早截止。锚档位消失、RF 失败/替换、数据缺口、
  tick 变化或过期都结束相应候选，不能跨重连拼接证据。
- 进攻锚记录 AP 开始时的 Ask/Bid 及第一笔价格，承接锚记录 RF 的固定 Bid。
  完整保存两者位置关系，不据此过滤。价格只定位盘口及解释有事件依据的锚关系。
- 所有时间使用实时可获得的单调时钟；输入乱序、源时效、队列水位沿用 M1。
  对照窗口缺覆盖、待处理数据超过 20ms 或公共时钟过期时保留特征，但不模拟开仓。

## 探索组与模拟口径

每套规则独立计算：`all_candidates` 是没有 BUY 减弱门槛的候选参照；另列 BUY 比例上界
不超过 0.25、0.50、0.75、1.00 的探索组。这些是固定的研究网格，不是已选择的生产阈值；
`1.00` 也不保证严格减弱。不会自动优化、自动上线或将观察后的结果回填到更早时刻。
每个规则在本次 AP_BUY 的首次合格观察上计一次；后续 RF 或持续观察不会重复买入。
更低比例可以稍后首次成立，其模拟价格和时间采用届时真实可见的信息。

- 全部合法价格 `0 < p < 1`，满足 tick、可见 Bid 和 Maker 报价条件，不设置低价范围门槛。
- `[T15,T240)`；T240 结束输入，T300 仅完成本地观察和换场。
- 单笔目标最大亏损（买入成本）5 USDC；`floor(5/p, 0.01股)`，不超过预算，并满足至少 5 股
  和市场最小数量。无法满足时保留跳过原因。
- 每组每场 20 USDC，YES/NO 共享该组额度。2026-11-04 起按用户要求，每组每场每方向最多
  1 笔假设成交（`max_entries_per_direction=1`），YES/NO 各一个名额，单组单场最多两笔。
  名额只由成功记为 `ASSUMED_FILL` 的记录消耗，不满足最小数量或额度不足不会消耗名额；
  由 SQLite 已有成交判断，重开账本仍有效。阈值组独立，第一笔可成交的合格观察占用该组名额。
- 所有候选和有效观察落账。每个规则首次符合条件时，即使方向名额或额度耗尽也保留独立研究样本和
  假设收益，模拟账本仅计额度内的假设成交。不同规则不得相加为一个组合。
  后续同方向样本标记 `SKIPPED/DIRECTION_ENTRY_LIMIT_REACHED`；原始 `sample_pnl` 仅供研究，
  `trade_pnl` 为空。策略 PnL、交易市场数、时间稳定性及聚类区间只用假设成交。
  新规则进入参数和源码版本指纹，历史不限笔记录原样保留，不与新策略直接合并。
- 全部收益假设按观察时锚定价足额买到并持有至结算；没有 Maker 排队成交证明。
  不包含手续费、返佣或网络成本。只按官方最终胜方结算，未知结果保持空值。
- 该模式不模拟网络拒单/重试，不制造重复风险。真实执行可达性属于后续阶段。
- 每次运行保存源码和参数指纹；报告按版本分开。重启保留原记录，将中断场次标为不完整，
  不在同一市场重新建一个模拟场次。零候选市场也保留并查询结算。
- 数据异常按原因完整计数，诊断事件限频；完整窗口与输入质量是不同维度，异常不能隐去。

先用探索样本研究衰减比例，选定阈值后冻结规则，在后续市场做独立验证。M1 对照应使用旧的
全价格、单笔 5 USDC 测试数据，不能将当前低价/1 USDC 实盘与其直接等同。
按价格、剩余时间、方向和锚关系分组；`结算指示量 - 买入价格` 用来描述价格校准假设下的
增量，不能代替同价无信号对照。统计按五分钟市场聚类，不能将同场重复信号视为独立试验。

## 运行与资源隔离

```bash
.venv/bin/python -B -m polymaker.m2_study --once
.venv/bin/python -B -m polymaker.m2_study --max-seconds 30 --output-dir research_outputs/m2_virtual/smoke
.venv/bin/python -B -m polymaker.m2_report
```

可选 `--settings` 只接受独立 M2 TOML，不读 `config/config.toml`。独立服务模板为
`ops/polymaker-m2-study.service`。2026-11-04 用户明确要求取消 M2 的所有 CPU 限制：
服务使用 `--disable-cpu-guards`，将 `host_cpu_guard_enabled` 和 `m1_cpu_guard_enabled`
都设为 `false`；整机占用率和 M1 专属等待压力均只记录，不再阻止准入或提前结束本场。
M2 的 CPU 配额及专用调度周期已经移除，恢复默认 Nice 0、默认 CPU 权重 100，
不再以降低 CPU 优先级运行。部署时同时清除旧的运行时 CPU 配额覆盖，核对 cgroup
`cpu.max` 为 `max`；不能只修改服务模板而留下旧的 `CPUQuota=40%`。
I/O idle、内存上限 256MiB、禁止使用 swap 保留。不要修改 M1 服务或为此重启 M1。

默认输出上限 512MiB、可用磁盘下限 2GiB，达到限制时只停止 M2，不删除历史文件。
不保存全量 WS 帧，特征和组件批量写入自己的 SQLite，最多每分钟更新轻量报告。
没有新增签名流程或报告子进程。CPU 门槛关闭后仍必须如实报告积压，
不能放宽信号的数据完整性检查。

本机受限短测确实出现过持续积压和队列溢出，不能算成有效的信号验证。
2026-11-04 排查确认：全局 PSI 是等待指标，不等于 CPU 使用率，不能单凭 PSI 高于 20%
就认定没有 CPU 余量。原全局 PSI 门槛会使采集长时间等待，原调度权重也容易让 M2 自身积压。

早期保护方案改为读取 `/proc/stat` 的最近约 10 秒实际忙碌比例（user/nice/system/irq/softirq/steal；
idle/iowait 不计 CPU 占用），超过 85% 时等待；另读取 M1 实盘独立 cgroup 的 CPU full PSI，
超过 20% 时让 M2 退让。首次读取先等待一个真实测量区间。全局 PSI 保留在报告作诊断，
不再作为单独准入门槛。未知 CPU 状态仍等待。订阅期间每秒检查，等待时每 10 秒检查，
最多每 30 秒更新等待报告。资源不足只结束 M2 本场并标记不完整，不停止其他服务。

早期 M2 后台权重为 25、Nice 10，低于实盘。原单核 25% 配额在实测中频繁限流，
曾改为 M2 最多单核 40% 的处理余量，内存上限保持不变。
全机忙碌比例超过门槛持续 5 秒才退出本场，避免短暂尖峰结束整个市场；
M1 实盘自身 CPU 等待超过门槛仍立即退让，不使用这段宽限。
这些是运行设置，不是信号参数；同机运行无法承诺绝对零性能影响，必须对照实盘心跳、
输入积压及 cgroup 等待情况。信号时效和数据完整性规则不因此放宽。

2026-11-04 首次只关闭 M2 整机 CPU 负载门槛，服务曾通过
`--disable-host-cpu-guard` 将 `host_cpu_guard_enabled` 设为 `false`：仍测量、记录整机 CPU，
但整机负载超过 85% 不再阻止启动或结束本场。M1 专属 full PSI 超过 20% 的退让仍保留，
M2 的 CPU 配额、调度优先级、内存/磁盘限制也保持不变；不修改或重启 M1。
该开关进入参数及源码版本指纹，切换前后按不同版本分析，不自动混合旧样本。
首次切换若在市场中途，新版本首场仍会标记为非完整窗口；保留有效观察及官方结算，
不能为了连续结果放宽输入时效检查。

当前取消所有 CPU 限制后，两个开关仍进入参数及源码版本指纹，新旧版本分别分析。
只重启 M2；旧市场不会再次打开，中途切换造成的旧场中断保留，新版从下一场开始采集。
BUY 减弱研究组、锚点关系、输入覆盖/时效校验、全价格、单笔 5 USDC、每组单场 20 USDC
及官方结算规则均不改变。每场第 240 秒结束输入、第 300 秒结束窗口仍是采集规则。
关闭 CPU 门槛不等于保证没有网络、时间源或输入质量缺口。需要恢复保护时去掉
`--disable-cpu-guards`，默认两个保护均开启；旧的 `--disable-host-cpu-guard` 只关闭整机门槛。

M2 自身还省略了逐档诊断对象的重复构造、复用已有队列状态；完整计数和信号证据仍保留。
这些优化只在独立适配器内，不改共享 M1 类或其信号接纳规则。

## 当前对话的十五分钟巡检

用户已授权在现有对话 `01a1a0dc-5e73-72e1-886e-bd9856858b4b` 每 15 分钟巡检。
当前没有可用的原生 automation_update 工具，复用本机已验证的 systemd + `codex queue --resume`
方式，只向这一个现有 session 送入审查任务，不创建新对话。

`polymaker-m2-watch.timer` 按北京时间每小时 00、15、30、45 分的第 30 秒执行
`ops/m2_study_watch.py`。脚本只读 M2 SQLite、报告和服务状态，不读取账户，也不改交易进程。
独立报告保存在 `research_outputs/m2_watch/latest.json` 和 `reports/<15分钟桶>.json`。
待处理审查合并，失败入队不会冒充已交付；代理实际复核后更新独立的 `agent-state.json`。

审查按当前源码/设置版本区分完整观察、有效观察、独立 AP 事件及独立已结算信号市场；
核对官方结算、重复/孤立记录、报价风险与收益一致性。数据有缺口时注明推论范围。
30 个独立信号市场仅是现有聚类区间的最低探索门槛，不是数据已经足够的证明；
零损失等退化样本不能凭零方差区间宣称确定优势。前后时段、区间精度、多阈值与反复查看偏差
都需要人工复核。候选阈值须冻结后再用后续新市场验证，不自动变更阈值或进入真实交易。

状态不变或仅样本不足时保持安静；故障、数据质量显著变化、新的阶段性证据或用户需要决策时，
才在当前对话通知。停止巡检只需停止本定时器，不影响 M1/M2 的运行。

```bash
systemctl --user list-timers polymaker-m2-watch.timer
systemctl --user disable --now polymaker-m2-watch.timer
```
