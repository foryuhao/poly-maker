# 共享读取与核验接入周期缓存

2026-10-17，北京时间。第二阶段实现，覆盖 `rdp-sm-run` 的 NORMAL、REBALANCE 共同读取层。

## 运行方式

仓库 `config/config.toml` 与 `livecfg/config.toml` 已开启：

```toml
[rdp_sm.sync_observe]
enabled = true
use_for_execution = true
order_interval_s = 1.0
account_interval_s = 2.0
```

用户仍执行原命令，每次只运行一个当前市场、一个 Session：

```bash
uv run polymaker rdp-sm-run
```

或由用户在外层 shell 连续调用 12 次。代码修改不会热加载进已经启动的 Python 进程；下次调用加载新逻辑。开发与验证没有启动实盘交易。

模型默认 `use_for_execution=false`，保留未配置环境和独立观察模式。设为 false 可回到旧读取、旧网络保温路径并保留旁路观察；完全关闭模块需同时设 `use_for_execution=false`、`enabled=false`。配置禁止缓存执行开启而服务关闭。执行模式下，服务不可用会阻断执行，不偷偷回退到旧 GET。

## 缓存与执行器职责

snapshot 是当前市场与账户的服务器观测缓存，不承担订单生命周期审计。短命订单可以从未出现在任何一拍的 `open_orders` 中；不会为此补造历史挂单。POST、DELETE、merge 的动作、回执、在途和未知结果仍归执行器及原操作日志管理。

新增 `CachedExecutionReads` 统一接入 `_snapshot()`、关单、FillTruth、严格拒单证明、确认等待、最终关闭及 merge 前后核验。每次账户读取或关闭核验固定一份不可变快照，原 gateway 读取接口只返回其中的数据；同一轮各处读取不会发 HTTP，也不会每次单独等待一个心跳。原签名身份、成交数量、确认状态、资金及库存校验继续执行。

- 订单、成交、资金、持仓及运行期校时采用服务缓存；主循环不再逐轮查询 Gamma 市场，沿用启动时已验证并固定的市场元数据。
- 同一份完整成交采集结果由共享接入层应用到所有已登记的自有订单；已有 FillTruth/关闭验证仍可在内存中按订单检查。
- 普通全量关闭路径里的“每订单 3 次详情＋1 次成交”成为同一快照上的内存读取，不再对应 4N 次 HTTP。
- 相关订单终态详情在没有新事实时复用；新成交、异常状态、操作边界或矛盾会要求重新核验。观察到终态订单重新出现在当前挂单中仍会阻断。
- 盘口、OBI、报价、数量、最小金额、时间窗口及 2 秒/3 秒期限保持现状。tick/version 的原初始化与约束核验保留；启动预检、结算 SDK 的独立元数据与链上核对仍有各自 I/O。

## 如何等待操作后的状态

POST、DELETE、merge 的在途操作和完成时刻保存在执行器内存中。消费前要求相关集合的实际请求开始时间晚于已完成写操作；在途写操作不能被空列表覆盖。资金与持仓使用各自来源时间，账户读取等待它们跨过写操作边界。

如果关闭证明需要一个尚未由服务器列表发现的签名订单详情，执行器仅提供待核验 ID 和时间要求，由下一次普通周期处理。不唤醒定时器，不调用 refresh，不因多几个消费者增加集合 GET。ID 只授予读取权限，不代表订单已被接受或拥有。

采集器每轮对待核验详情最多并发 4 个，按既有轮转顺序处理。首次 404 保留未解决状态，不把列表缺席或 not-found 当作关闭证明，也不因一个尚未可见 ID 的 404 对全部集合刷新做指数退避。其他真实读取故障仍按原有退避处理。

订单详情与成交集合暂时数量不一致时，接入层等待下一拍，不先用冲突数据进入 FillTruth 造成隔离状态。部分分页中已观察到的订单、成交仍被保留为风险，失败来源不会冒充新鲜成功结果。MATCHED/MINED 不当作 CONFIRMED。

准备后至 POST 最终检查之间，如果最新缓存显示账户事实已变化、来源失败或过期，当前准备槽不提交，由下一轮重新评估。

## 撤单与网络探测

信号反转和期限触发撤单仍立即执行，不等待下个心跳。POST 已返回且缓存观察到身份匹配的可信终态、当前挂单列表也不含该 ID 后，可以停止重复 DELETE；原最终关闭和资金预留规则仍须通过核验。已有在途 DELETE 会排空后才推进操作边界，避免取消 await 后真实 HTTP 仍在运行。

启用缓存执行时移除旧的独立 `warm_network` 循环，由服务的原始 CLOB HTTP 结果供给同一个 NetworkHealth；POST/DELETE 的原始测量继续保留。正常订单通道 1 秒，PAUSED/PROBE 时服务内部采用原有恢复探测间隔，默认最多 500ms 一轮；慢请求与故障退避仍可能延长实际间隔。资金通道维持 2 秒。

## 记录与验收

原交易 journal 格式、已有事件和人工输出保持；新增 `sm_sync_cache_read` 记录实际使用的版本、用途、操作边界与来源请求时间。它的引用同时记录实际消费版本，不能用诊断记录时刻碰巧发布的后续版本冒充消费版本。

原 `research_outputs/periodic_sync/<session_id>/` 五类文件继续保存。manifest/summary 新增 `execution_reads_from_cache`，源码哈希纳入共享接入层；接入后的快照 mode 为 `READ_ONLY_EXECUTION_CACHE`，仍为 `trading_authorized=false`，因为缓存本身不授予交易权限。`RECORDED` 仍只代表记录过程完整。
