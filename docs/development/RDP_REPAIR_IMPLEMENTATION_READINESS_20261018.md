执行契约第8节最后两项业务决定已收到明确答复：第一版整个session固定Delta_max=5 share；真实超限优先恢复硬限额，允许必要负增量EV修复。已确认业务决定不存在待答复项，后续工作为账本/状态机实现、模型版本与性能验证、实证校准及回放验收。

## 已经明确，不再重新征求决定

- 固定NORMAL信号和开仓策略，优化REPAIR；Buy Only、Maker Only、无费用。
- p是真实条件YES胜率；实际新单价格来自对侧真实best bid。
- 在整个session资金15USDC、固定abs(Delta)<=5 share及执行可行性内最大化期望完整PnL；真实超限优先恢复，允许必要负增量EV修复。原始量按实际成交记录，不以episode局部量替代session风险。
- 不再使用浮盈/浮亏符号、0.30/share、B_wait或B_loss作为强制交易门槛。
- KEEP评价旧报价；复核不自动改价。Maker成交概率、逆向选择、部分成交和撤单延迟进入模型。
- 最低金额导致的超量需要单独评价，不能以配平为由无限翻向补仓。
- T240停止新REPAIR并请求撤余单，持续核对迟到成交和确认；T240后的Merge不参与前面的决策变量。

## 一、已由用户确认接受的五项策略语义

确认依据：用户明确回复“对以上5点，我确认接受你的建议”。本节建议均升级为确认范围，不重新征求选择；措辞中的工程数值与估计方法保留版本管理。

### 1. 基准EV和参数情景冲突时，谁决定真实动作

同一T100场景，基准模型BUY，较低流动性情景HOLD。它们是不同参数下的价值，不是两条可同时执行的指令。

已确认：主策略按指定的基准模型选最大EV；情景检查作为解释和研究诊断，不自行改成最坏情景策略。参数版本必须显式指定。不能未经新增决策就引入情景否决。

主比较是可执行基线：无单用HOLD，有单用含迟到成交的CANCEL_NOW；不能与假设瞬间消失的旧单比较。零增量及数值并列优先不新增提交；不擅自加0.01USDC等交易利润门槛。研究脚本的1e-10只为数值并列处理，不是经济优势的可信度。

### 2. REPAIR选择HOLD、部分成交或反向残仓时，NORMAL能否新开

当前状态分流按净仓量四舍五入后是否达到5股判断。原YES5、NO已成交1时净仓4股，会落回NORMAL；最低金额超量后的少量反向残仓也会落回NORMAL。这不代表原修复episode已经完成。

已确认一个市场同时只拥有一个原开仓episode：从原开仓事实建立持续身份，记录实际原始数量、净仓、所有提交/成交/预留；HOLD仍保留该身份。原单余量未解决、持有未达配平容差的残仓时，不启动新NORMAL。按旧0.1股忽略口径视为配平且执行事实已解决、仍处原NORMAL时间窗时，恢复既有NORMAL准入；忽略尾差仍留在经济账本。

这保持NORMAL信号和报价算法不变，但会改变部分残仓状态下的新开仓准入及开仓次数；该协调器变化已随本项建议获得确认。用户已排除其他交易机会的机会成本，因此不为了争取新增NORMAL机会惩罚HOLD。

### 3. 第一版允许多少次干预，求值向前看多少步

研究脚本只计算一张旧单加一次撤后替换，EpisodeContext.max_submissions=2是研究限制。每两秒再调用它、重置计数，会把多个有限策略拼成尚未求过值的另一套策略。

已确认：实际控制器支持持续复核、多次合法撤换；资金、原始量、方向、订单和提交次数均持续记账。求值可以先采用有限深度rollout，但必须固定段末的继续策略，并对完整连续复核控制器进行闭环回放，不能把每个局部Q相加当作整体EV。

不引入“最多两次提交”的业务上限；研究求值深度与实际累计次数分别记录。资金、数量、时限及已确认的执行约束继续限制每一次动作。

### 4. 股数是否参与EV优化

单单研究脚本支持数量候选；后续两单Planner主要按覆盖缺口、受资金约束时取可买部分、最低金额迫使超量的规则生成股数，并未穷举所有合法部分修复量。5股算例不显露这个差别。

已确认第一版至少比较HOLD、合法部分量、可精确覆盖量、资金允许的覆盖量，以及仅由最低数量/金额迫使的超量。执行精度与搜索网格分开；候选离散化、向内取整及数量上限要写清楚，不因模型少搜了一个量就宣称全局最优。

每个候选同时检查现有活动单与未决成交可能产生的最坏数量，不只检查最终计划净仓。不主动为了价差跨过配平点；最低金额反向残仓不自动买回原侧。

### 5. p、sigma和数据不足时的规则

已确认p先用有效YES best bid/ask的中价，NO中价只作互补一致性检查；新NO报价独立读取NO best bid。YES/NO时点、spread、tick、深度是否可用均显式传入，不使用1-p合成可执行盘口。

已确认复用已有波动估计方法作为首版：本市场过去30秒、每秒真实行情样本，至少10个有效间隔、20秒有效时长，不能跨断线generation拼接；sigma为价格变化的USDC/share/√秒，不是收益率波动率。每次价值计算暂冻结当前sigma，并保留期限及参数敏感性，不能把短期估计当作已证实的140秒预测。

数据不足不赋值sigma=0。无活动单时不新增模型单；事实或行情不可用时按明确规则处理旧单并核对。开场NORMAL可以早于波动估计预热完成，因此原开仓后可能出现“有仓但暂不发REPAIR”的时段，不擅自增加跨市场预热或零波动替代模型。

## 二、工程上应直接写明的执行规则

|事项|建议契约|现有基础或缺口|
|---|---|---|
|复核与挂单期限|建议每2秒常规复核，成交/订单状态变化及时触发，异常与T240独立及时处理；KEEP维持订单身份及队列，不从复核时刻重置TTL|当前REBALANCE用固定3秒deadline，需要改为模型计划撤单时点|
|成交状态|以可靠对账的实际仓位形成经济账，允许POSITION_RECONCILED容错路径；未解决的MATCHED/MINED及未知提交保留潜在敞口/预留，后续CONFIRMED不重复入账|现有CONFIRMED硬依赖需同步改造，去重及commitment机制继续保留|
|撤后重挂|先请求撤旧，继续接收迟到事实，可靠解决旧单余量及相关成交后，再按实际缺口与新盘口求值；不复用撤单请求时的旧数量|已有verify_close及终态/分页/成交集合证明，不以ACK替代|

“数据不可用”“订单事实未解决”“模型算不出”应给不同原因码。它们不自动表示仓位无风险，也不授予卖出、taker或越过资金限制的权限。

## 三、可复用的代码与必须改的接口

- `src/polymaker/rdp_sm_rebalance.py`：目前单一REPAIR候选、select固定返回、cutoff300；要接入HOLD/BUY/KEEP/CANCEL/撤后重评及候选价值。
- `src/polymaker/rdp_sm.py`与`rdp_sm_loop.py`：目前按约5股阈值分流；要接入episode归属和HOLD等待，保留原NORMAL信号规则。
- `src/polymaker/rdp_sm_lifecycle.py`：已有post-only提交与撤单/对账原语；需要可持续的活动订单复核，不能每次决策都先强制关闭窗口。
- `src/polymaker/rdp_sm_execution.py`：保留唯一写入、commitment、成交去重与verify_close；状态适配须说明确定仓位及可能仓位。
- `src/polymaker/risk_shadow_model.py`：已有p和30秒sigma计算，但属于观察/研究模块；建议提取纯计算接口，不让交易逻辑依赖Shadow文件写入。

决策输入至少包括：episode身份/原开仓量、经济库存与成本、未决成交/活动单、原报价与队列年龄信息、实际双侧盘口/有效性、sigma及有效性、官方时间锚、现金与预留、策略/模型参数版本。

决策输出至少包括：动作、价格、量、针对的订单、计划撤单时点、下次复核、可执行基线、期望完整PnL及增量、联合终端风险、候选排序、数据支持/模型状态、原因及输入revision。实际POST前对订单、库存、盘口和期限重新检查；已失效的计算结果不得越过执行层。

## 四、开发与验收顺序

1. 按已确认业务语义及第二轮实现契约，写纯决策接口和episode账本；在相同模型与参数版本下复现T100/T102算例。扩展候选或后续策略后重新求值，不把旧算例的动作硬编码为新版本验收答案。
2. 补数量候选和连续复核回放，记录每次可见信息及实际继续策略，核对完整经济PnL，禁止逐路径事后选模型/最优动作。
3. 接入现有执行原语，测试部分成交、最低金额反向残仓、撤单迟到成交、UNKNOWN/FAILED、状态revision变化、资金预留及重启；T240临界与Merge交接分别验收。
4. 测实际tick/行情频率下的计算耗时和超时行为；保留原NORMAL回归检查，明确协调器准入变化。
5. 订单逻辑验收与收益实证验收分开。可配置未校准参数用于开发及离线验证；整体正EV仍需终局标签、成交模型检验与样本外闭环结果，不能用单个场景正增量代替。
