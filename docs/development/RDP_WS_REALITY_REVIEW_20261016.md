# 2026-10-16 行情处理与 dust 复查

针对 23:15–23:20 场的频繁行情失效，按用户要求调整。此文覆盖旧基线中将交叉、
顶档不一致、毫秒时间回退一律视为连接损坏的规定。

## 已修改的判定

| 原条件 | 新行为 |
|---|---|
| 源时间回退 1ms 就重连 | 源时间差按整秒比较；不足 1 秒的回退接受，更旧的更新忽略；未来时间检查也按秒 |
| 重连后沿用旧 source_time | 新连接清空时钟和盘口，等待新快照 |
| 新连接先收到增量就再次重连 | 忽略完整快照之前的增量，在同一连接等待快照建立基准 |
| 一条消息逐笔校验交叉/顶档 | 先完整应用一帧，再统一对齐该帧明确的最新 BBO |
| 本地仍有优于官方顶档的旧档位 | 按官方 BBO 删除矛盾缓存档位，使用已收到的真实数量 |
| 官方顶档缺少对应数量 | 暂停该盘口报价，等待后续数据，不造量、不断连 |
| 真实交叉/锁定盘口 | 保留盘口事实，快照暂不可报价；后续更新可在同一连接恢复 |
| 重复完整快照被视为陈旧 | 更新盘口接收时效；不刷新真实信号事件，不借此重复消费同方向信号 |
| 重复 Tick 通知触发冲突 | 相同新 Tick 幂等；REST/WS Tick 暂不一致先暂停准备并重试 |
| 微小仓位影响后续数量、账户差异、Merge | 严格小于 0.1 股忽略；0.1 股为有效边界 |
| 原因相同的等待日志掩盖新故障 | 按原因、代次、失败计数去重；保存最终 WS 诊断与修复计数 |
| 候选失效只有计数 | 记录具体失效原因 |
| 终端将结构化撤单成功和成交方向显示错误 | 解析真实回执，并从提交订单匹配成交 token |

Dust 仅影响决策与小额差异准入，不删除成交、成本或物理余额。每腿小额持仓和小额净差
不再改变 Skew；Data API 与 Session 库存差绝对值小于 0.1 股不再暂停。忽略按当前总量
判断，累积达到 0.1 股后正常参与。Merge 不处理小于 0.1 对；正常 Merge 只消耗最多已确认
Session 配对数量，外部 dust 留在物理余额。链上实际前后 token/collateral 变化保持精确证明。
新记录标记 dust 策略，历史无标记记录继续沿用原严格校验。

## 复查后保留的敏感条件

- 盘口接收年龄、信号年龄各 100ms，双腿接收时间差 100ms。源时间秒级处理没有放宽这些时效。
- RTT P95 ≤500ms，NORMAL 信号年龄＋P95 ≤500ms。网络按 GET/POST/DELETE 分组，
  单次失败样本仍可能阻止开仓直到离开 30 秒窗口；连续 3 个健康样本不能覆盖窗口内失败。
- 预签候选后报价或方向改变，提交前仍失效并重新准备；这会减少订单，但可防止使用过时报价。
- 同方向区间一次 POST，INVALID 不重新武装；T+120 后 NORMAL 不开仓。
- 交易所最低 5 股/最低 1 USDC、价格 Tick、Post-only、资金 15 USDC 上限继续检查。
- 身份错误、非法/非有限数量、日志写入失败、未知订单暴露仍需阻止新单；dust 不覆盖订单终态证明。

上述是仍会减少成交机会的明确限制，未在本次顺带放宽。
