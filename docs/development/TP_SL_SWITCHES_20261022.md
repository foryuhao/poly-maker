# TP / SL 独立配置开关

## 配置

在实际运行所使用的配置文件中设置：

```toml
[rdp_sm.repair.path]
tp_enabled = true
sl_enabled = true
```

`config/config.toml` 与 `livecfg/config.toml` 均显式写入 `true`。字段省略时也默认 `true`；只接受 TOML 布尔值，不接受字符串或数字。当前没有关闭任何开关，没有启动任何交易。

| TP | SL | 行为 |
|---|---|---|
| 开 | 开 | 保留原 TP、SL、T180 强制 SL 逻辑 |
| 关 | 开 | 无 TP；保留价格冲击、回撤、Delta 超限及 T180 的 SL |
| 开 | 关 | T180 前允许 TP；T180 关闭 TP 余单，剩余 Delta 持有 |
| 关 | 关 | 不发 TP / SL 修复单，剩余 Delta 持有到市场结束 |

SL 关闭意味着上述所有 SL 发单入口都关闭，不会从定时器或执行交接重新打开。NORMAL 的准入与资金 / Delta 限制仍保留；两边已配对的合并、撤单、成交核对及订单所有权证明继续执行。

## 实现范围

- 配置模型：严格布尔、默认开启；只支持 `hd_tp_sl_v1`。若在 `ev_legacy` 下关闭任意开关，直接报配置错误，避免静默忽略。
- 策略：TP / SL 信号按开关进入；SL 关闭后 T180 不再强制 SL。恢复的禁用模式转回 HD 并清掉旧 TP 固定报价。
- 控制器：计划生成、候选、最终匹配及执行入口均检查开关；关闭的模式不能继续提交订单。
- 执行：TP、SL actor 的目标与提交前准入均检查开关；TP 到 SL 的交接也检查 SL 开关。
- T180：仅 TP 开启时，TP 停止并关闭余单，不生成 SL；T240 仍保持原修复发单截止。
- 日志：原 session 的 repair 配置自动包含两个开关，decision / policy snapshot / time boundary 也记录开关。

配置用于新会话，不提供活动会话的热切换。旧订单仍必须按现有撤单和终态证明处理，已成交份额不会被忽略。开关不豁免既有参数和回放准入要求。

## 对比实验边界

当前50场目标及Maker rebate计量见[基线返佣与目标](BASELINE_REBATE_TARGET_20261022.md)：返佣前交易PnL ≥ −1.00 USDC/50场，交易PnL、同批实收返佣和合计PnL分别记录。

关闭修复后，已有未配对 episode 会按现有协调器阻止继续进入 NORMAL；不为复现离线 148 笔入场而放开头寸限制或更改开仓策略。因此未来实际对比的成交集合会随开关变化，不能与固定历史入场的反事实当成同一实验。
