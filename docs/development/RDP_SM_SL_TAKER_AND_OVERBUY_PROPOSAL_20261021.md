# SL 执行切换与最低金额多买：讨论方案

日期：2026-10-21。状态：历史讨论稿 V1，已由 [V2 讨论方案](RDP_SM_SL_TAKER_AND_OVERBUY_PROPOSAL_V2_20261021.md)取代，尚未实施。以下保留前轮讨论记录，当前设计、数量语义和待确认选项以 V2 为准。已确认：整条同方向 SL 腿固定首次有效卖一 +1 跳上限；只允许补对侧 BUY；最低金额优化首版仅覆盖 SL，TP 保持现状。未修改交易代码、运行配置、恢复状态或活动订单；未读取或改动 47 个市场的 Shadow 数据。

**后续只读核查修正（同日）**：[最低金额与数量语义核查](reviews/20261021_minimum_buy_rule_check/README.md)未能从现行官方资料和保留日志完成两类订单的服务器边界验证。尤其，BUY 的签名目标份额不是实收份额硬上限；价格改善时 FAK 可能多收份额。下文所称目标份额只代表本地修复目标，实施前必须核实实际执行数量上界和风险准入，不能仅凭 `size` 保证不多买。

## 1. 建议与范围

两个改进分开配置、分开验证：

1. **SL 执行模式**：`maker` 保留当前行为；`taker` 从进入 SL 的首次提交起，按净缺口设定目标份额、预算和价格边界使用 FAK。目标份额不代表实收硬上限，数量语义仍是实施前置核查。默认 `maker`，旧配置不填也走原逻辑。
2. **最低金额多买策略**：默认 `legacy` 保留当前数量规则；另设 `prefer_exact_buy` 候选，在实际订单约束允许时精确补对侧净缺口。用户已选择只允许 BUY，SELL 分支不纳入本方案。

这里的 SL 包括直接进入 SL、TP 转 SL，以及修复链中后续真正进入 SL 的方向腿。TP 本身继续按现有规则执行。净敞口条件仍决定 NORMAL→REPAIR，不作为新增 SL 触发器；累计回撤、短时不利冲击、进入 TP/SL 的判断不在本次调整范围内。

第一项可独立实施。第二项需要先澄清订单约束；不能把“将最低金额直接删掉”当成已验证的修复。也不通过扩大首腿突破现有 5 份风险上限解决问题。

## 3. 配置如何设计

建议在 RDP repair 下设独立配置，避免改变其他下单路径使用的全局 `execution.post_only`。以下仅为拟议格式，**当前程序尚不支持，不能直接放入运行配置**：

```toml
[rdp_sm.repair.sl_execution]
mode = "maker"                         # maker | taker；默认 maker

[rdp_sm.repair.sl_execution.taker]
slippage_ticks = 1
price_limit_policy = "fixed_initial"    # 已确认；首版不跟随最新卖一重置上限

[rdp_sm.repair.overbuy]
policy = "legacy"                      # legacy | prefer_exact_buy
scope = "sl"                           # 已确认；首版仅覆盖 SL
```

- `maker + legacy` 的报价、买量、撤改单和触发逻辑保持当前行为。
- `taker + legacy` 只切换 SL 执行方式，最低数量仍按核实后的交易所约束及现有策略处理；不把它描述为精确买量方案。
- `taker + prefer_exact_buy` 再验证实际约束允许的精确买量及其收益。`maker + prefer_exact_buy` 同样只能使用符合 Maker 订单约束的精确 BUY；两种模式都不引入 SELL。
- 模式在新交易会话启动时固定，不热切换；日志记录完整有效配置及版本。恢复中的旧订单按其持久化模式处理，不能因配置改变而重新解释为另一种订单，或重复提交。
- 配置错误应在启动时失败；不能把拼错的 `taker` 静默退回 Maker。

## 4. Taker SL 的提交与重试

### 4.1 用有修复目标、预算和价格边界的 FAK

Taker 模式使用 `post_only=false`、限价 FAK：限价内能成交多少就成交多少，其余终止。选择 FAK 的原因是部分降低敞口也有价值；FOK 要求全部成交，在深度不足时会整单失败。[官方订单生命周期](https://docs.polymarket.com/concepts/order-lifecycle)

下单单位是**份额**，不是“买 1 美元”。先根据本策略净仓、已匹配成交和所有旧在途订单计算本次可修复数量，再检查订单最小数量、金额、精度、资金和最坏敞口。`legacy` 可以按其规则增加买量，`prefer_exact_buy` 优先精确补对侧 BUY，但精确买量不合法时仍需遵守原修复准入；都不能绕过现有风险规则。

现有通用 `market_order` 的 BUY 参数是金额，且当前封装没有显式价格上限，不能直接复用来保证固定修复份额。**以限价单的 `size` 编码后再用 FAK 提交，也不能据此保证实收份额不超过目标。**应将目标缺口、支出预算、最差价格及可验证的实际数量上界分别定义；当前 SDK 和市场版本的执行语义未核实前，不采用“固定 size 即固定敞口变化”的准入证明。[官方下单接口](https://docs.polymarket.com/trading/place-orders)

### 4.2 已确认：整条同方向腿固定首次卖一 +1 跳

设进入 SL 后，第一次取得有效、可用于提交的对侧卖一为 `A0`，最小价格变动为 `tick`，买价上限固定为 `A0 + tick`。这个时间点必须在日志里记录，不能事后选取更有利快照。

| 价格策略 | 行为 | 取舍 |
|---|---|---|
| `fixed_initial`（已选） | 整个同方向 SL 腿均不超过首次上限；部分成交、重试和重启不重置 | 限制追价成本；卖一持续高于上限时可能一直无法退出 |
| `follow_market`（不纳入首版） | 每次根据最新有效卖一重新给出“卖一 + 1 跳”限价 | 优先及时退出；总成本可能远超首次卖一 + 1 跳 |

用户已选择 `fixed_initial`、1 跳，先做受限验证。该选择与已有价格压力分析更接近，但不是已经证明最优的实盘止损参数；零成交和持续未修复的损益仍必须计入验证。不得在失败重试中切换成跟随最新卖一，或默默放宽上限。

价格边界只限制最差成交价，不意味着主动按上限全部成交；实际可以在更优价格成交。价格必须落在有效区间和 tick 网格内，取整不得扩大已约定的边界。首次边界、方向腿身份和 tick 变化处理应持久化，防止重试或恢复意外放宽。

### 4.3 失败、部分成交及旧 TP

1. 进入 SL 后发起旧 TP 撤单；旧单在拿到终态和成交证据前，继续占用资金与最坏敞口。
2. 只有在“旧单仍可能成交”的假设下也通过风险准入，才允许新 Taker 与撤单并行；否则先等旧单证据。
3. 同一方向腿最多一个尚未确定结果的 Taker FAK；不能复制当前 Maker 的并行替换机制，无证明地叠加吃单。
4. FAK 完全成交后进入成交/经济证据核对；部分成交则先核实剩余量已终止，再根据剩余净缺口决定下一步。HTTP 成功、取消 ACK 都不能单独证明已退出。
5. 零成交或限价外无量：记录原因，等新盘口和终态后再评估；初始候选为重试间隔至少 500ms，且必须先满足证据条件，不按固定频率盲发。这个间隔尚未经过优化。
6. 请求超时/结果未知：保留原订单风险，按订单 ID 恢复核对，禁止当作零成交重发。旧单晚到成交必须反映到剩余目标，避免反向补仓。
7. 剩余仓位达到当前小仓条件，也必须完成旧单与经济证据核对，才能按现有规则回到 NORMAL。保留当前 T240 提交截止及之后的收尾、迟到成交处理。

本批市场元数据 `itode=true`；官方说明相关可成交订单有 250ms 撮合等待。限价内显示有量不代表到达时仍有量，Taker 也不会自动缩短链上确认和整个轮次安全关闭时间。[官方撮合流程](https://docs.polymarket.com/concepts/order-lifecycle)

## 5. 最低金额多买怎样处理

### 5.1 先区分本地限制与交易所限制

当前 `maker_buy_size` 会按价格将买量抬到至少 1 美元：净缺口 5、对侧价格 0.15 时，向上取整得到 6.67 份，产生反向 1.67 份。这里确认的是代码行为，**尚未证明所有被动 GTC 都必须满足同一个最低金额规则**。

实施前应按本项目使用的市场/SDK 版本、BUY 的 GTC/FAK、被动/可成交订单分别确认：最小份额、最小金额、取整、检查所用价格及手续费结算方式。公共文档/元数据不足以确认的部分，应作为待验证约束保留，不能先删规则再依赖拒单试错。实际交易验证属于后续实施范围，本次不发单。

- 如果 Maker GTC 合法允许 5 份、金额小于 1 美元，可对该明确适用的路径移除本地不必要放大；这是更小的改动，不需要引入 SELL。
- 如果 Taker BUY 确实至少 1 美元，仅把数量强制封顶为 5 会导致无法提交，而不是成功消除 5 份风险。
- 限制真正取决于当时净缺口和对侧价格，不应硬编码成“首腿大于 0.80 就禁止”。

### 5.2 已确认：只补对侧 BUY，不引入 SELL

`prefer_exact_buy` 拟按以下顺序决策：

1. **精确补对侧 BUY 合法可行**：按真实待修复净缺口提交，不为凑名义金额主动多买。
2. **精确 BUY 不合法**：沿用原 BUY 修复数量规则，继续检查最坏敞口、资金及所选执行模式的价格边界。这个分支可能仍产生反向残仓，必须单独记录数量及后续损益。
3. **原 BUY 修复也不通过准入**：保留未修复风险并明确记录原因，依现有规则继续评估和收尾；不能把“拒单/无单可发”计为修复成功。

“精确 BUY”是约束允许时的优先级，不是无条件保证。用户只允许 BUY 后，若真实最低金额限制使 5 份 @0.15 不合法，就无法同时保证“满足最低金额、立即修复、完全不多买”。因此，第二项能否改善及改善多少，取决于实际订单约束核实结果，不能承诺消除全部 −0.6178 的历史残仓损耗。

不得通过抬高限价凑金额、突破首次卖一 +1 跳边界、改用 SELL 或扩大首腿风险上限来规避该约束；Taker 不因最低金额或限价失败自动改用 Maker。后续部分成交留下的残量也必须重新检查最小订单约束，不能强制当作可精确补足。

### 5.3 已确认：最低金额优化首版仅覆盖 SL

只覆盖 SL（含 TP→SL 后的执行），TP 仍按当前规则运行。发生在 TP 的最低金额多买暂时仍存在；验证报告应区分 SL 内可改善的部分与未调整的 TP 部分，不能将所有高价首腿样本都算作本次收益空间。

## 6. 工程上必须一起补齐的能力

只改 `post_only` 不足以安全支持 Taker；以下属于同一个功能的必要配套：

| 当前位置 | 需要支持的行为 |
|---|---|
| `config.py` | RDP 专属模式配置、默认兼容、严格校验和配置快照 |
| `rdp_sm_sl.py` | Maker/Taker 执行分支、方向腿价格边界、FAK 串行结果核对、剩余 BUY 数量及最低订单约束 |
| `execution/gateway.py` | 准备与提交显式携带 order type / post-only；签名、请求体哈希、提交保护和 WAL 保持一致 |
| `userstream/parse.py`、`rdp_sm_sync_reads.py`、`rdp_sm_cached_reads.py` | 当前主要消费 maker legs；需要保留并识别本方 taker order ID、真实成交量/价、费用和多档成交 |
| `execution/filltruth.py`、`rdp_sm_execution.py`、SL 核对链 | WS/REST 对同一成交去重；不能把对手方 maker legs 算成本方成交，也不能要求 Taker 实际成交价等于提交限价 |
| 风险、资金、SL ledger 与 recovery | 手续费预留和扣账、部分成交终态、模式/边界恢复；只处理补对侧 BUY，不扩展 SELL |

订单身份核对仍应匹配原提交限价等签名字段；Taker BUY 成交核对验证实际价格不高于上限，按各笔实际成交价记账。不能简单把所有价格相等检查全局删除。

费用使用具体市场实际参数。上述样本的费率为 0.07、指数为 1，参考公式为 `q × 0.07 × p × (1−p)`；不是成交额统一收取 7%。资金预留要覆盖合法成交价格区间内的费用上界，不能只拿上限价格计算费用，尤其价格跨过 0.5 时。[官方费用说明](https://docs.polymarket.com/trading/fees)

当前项目使用的版本还需核实费用最终扣现金还是影响实收份额，并用权威成交/结算证据核对净到账库存与现金。不能用预估手续费替代实际账本。Maker/Taker 返佣独立记录应计与到账；不将最高 50% 自动视为已获得，也不以未到账返佣降低下单资金预留。

## 7. 如何验收两个改进

分阶段比较，避免同时改变后无法归因：

1. **兼容基线**：旧配置及 `maker + legacy` 行为一致，SL 触发、TP→SL、小仓和 T240 规则不变。
2. **Taker 独立验证**：比较 `maker + legacy` 与 `taker + legacy`；覆盖零成交、部分成交、多档成交、限价外、旧 TP 晚成交、未知提交、重启恢复、费用及余额不足。
3. **精确 BUY 独立验证**：先验证最小订单规则，再比较 `legacy` 与 `prefer_exact_buy`，仅覆盖 SL。包括精确 BUY、精确量不可提交、原数量规则回退、完全不可提交、跨轮 FIFO、反向修复及最终结算；不加入 SELL。

每个 SL 腿至少记录：信号时间、首个有效执行盘口、价格策略及边界、准备/POST/回执、首次及足额 MATCHED、经济确认、旧单终态、风险下降和安全关闭时间。不能把 POST ACK 当成成交。

结果同时报告：

- SL 全体尝试数、限价内足额/部分/零成交率、未修复风险量与持续时间；不只挑成功 Taker。
- 信号→首次 MATCHED、信号→达到当前小仓条件、信号→经济确认、信号→安全关闭的中位及 P90/P95。
- 每条完整修复链及全策略最终 PnL、实际费用、应计/到账返佣、资本占用和最大回撤。
- 精确配对部分、多买残仓、后续跨轮配对、反向修复及终局未配对仓位的 FIFO 损益。

已有快照适合做费用/价格压力参照，不足以给出 250ms 后真实成交反事实；正式执行优劣还需要包含失败路径的到达盘口数据或后续受控对照。不能同时把同一笔 SL 计入 Maker 与 Taker 返佣，也不能把两项历史参考改善直接叠加。
