# PolyMaker CLI Dashboard v1

看板读取独立观察器生成的快照。观察器只以只读方式增量打开已有的交易 journal 和
session 头记录的 CA 文件；不初始化 `Config`、交易客户端、交易 SQLite 或账户锁，
不发送订单、不启动或重启交易。终端展示不读取密钥。持续运行的观察器以无鉴权 GET 查询官方 Gamma
公开市场最终结果，以及 PM Data API v2 的公开账户持仓与成交。新文件放在
`research_outputs/dashboard/`，不读取私有交易状态数据库。M1 基线模式额外
只读 `research_outputs/m1_virtual/state.sqlite3` 和 `latest.json`，不修改生产账本。

## 启动

在项目根目录执行：

```bash
bash ops/install_dashboard.sh
.venv/bin/polymaker dashboard
```

已有观察器服务时，直接使用 `uv run polymaker dashboard`。M1 场次优先显示，
SIGNALS 按时间逐条列出本场全部 M1 信号（含被跳过的信号及原因），不按方向分组。
信号类型为 M1，原 POST 区域改为 RF／EX 信号窗口，显示本场确认次数、最近一次确认
时间和方向；次数是本场累计，换场归零，缺失中间快照字段时以已落库确认事件保底，
不因信号过期或证据重置而归零。确认记录不代表信号当前仍有效。开仓指令区和交易记录页继续标记
“基线／真实”。开仓指令显示方向、
价格、股数与状态；被跳过的信号不列入开仓指令。基线 PnL 按指令价足额成交、持有至官方结算的假设计算；真实
PnL 仅使用确认成交，两者分别累计。未结算的基线场次保持待定，不填零。
看板已移除 PnL 归因分布区；历史 CA 的账务和归档兼容保留。
总览并列显示真实、基线累计 PnL 两张图。共同起点取当前历史范围内两侧首场开始时间
的较晚者，起点之前的收益不计入对照区间；横轴使用相同实际时间范围，金额刻度也一致。
累计收益只在图内按对照区间显示，顶部保留待结算／待核实场次数。没有真实确认收益时明确显示未核实，
不画零收益线；另一侧没有场次时标记起点待对齐。
累计收益旁显示该对照区间累计 PnL 曲线的区间最高、区间最低，包含起点零值，
仅累计已确认收益；尚无确认收益时两个极值均显示待定。真实、基线分别计算。
当前基线每笔目标支出 1 USDC，股数按 `1 / 信号价格` 向上取到一位小数，
每场最多 5 笔成功指令。PnL 使用实际取整后的支出；历史场次保留原始数量和支出。
两张收益图的“对照区间累计”行下显示 `0.01–0.09：盈利场次/有交易场次 ·
0.10–0.19：盈利场次/有交易场次`，沿用共同起点和当前历史范围，真实与基线分别统计。
价格段边界分别为 `[0.01, 0.10)`、`[0.10, 0.20)`。同一场在同段的多笔 BUY
合计净 PnL 大于零才计盈利，该段任一笔待定时不计盈利，但已成交场次仍计分母。
同一场可同时计入两个段。真实优先使用 PM 实际成交及其成交价，不重复计订单回执；
只有 ACK、拒单或未成交的挂单不计交易场次。基线只统计成功指令的假定成交。
总览 SESSION 右侧单独显示“账户 / USDC”框，列出账户现金余额、持仓估值和浮动 PnL。
估值与浮动收益使用所选场次已有的 PM 账户快照并明确标记“本场”；缺失字段不补零，
现金余额未提供时直接标注，快照年龄与过期状态在账户框中展示。窄于 80 列时上下排列。
看板目录的 `view-settings.json` 可用 Unix 秒数 `display_since` 设置展示下限。
当前按用户要求设为北京时间 2026-11-03 13:00；总览、图表、场次与交易记录均不展示
该时刻之前的场次。`h` 的滚动历史范围仍适用，实际起点取两者较晚值。
这是前端筛选，不删除源日志、账本、归档或观察器快照，也不重启交易或采集服务。

安装器按脚本所在项目的实际绝对路径生成用户级 `polymaker-dashboard-archive.service`，
不要求固定目录名；需先创建项目的 `.venv`。移动项目后重新运行安装器即可更新路径并
重启观察器。`ops/polymaker-dashboard-archive.service` 是安装模板，不要直接复制安装。
观察器独立于终端，按秒采集、
按北京时间整五分钟生成运行快照。`q` 或 Ctrl+C 只关闭看板，`a` 切换归档索引。
M1 看板按 `t` 切换交易记录页，再按 `t` 返回总览；`a` 在场次记录页与总览间切换，
两种记录页可直接互相切换。M1 场次记录默认显示真实，按左箭头选择真实、右箭头选择
基线；两类不混表，均按场次从新到旧排列。切换类型返回第一页，页数只统计当前类型。
交易记录页同样按左箭头选择真实、右箭头选择基线，表内记录、PnL 汇总和分页只统计
所选类型；在交易记录和场次记录之间切换时保留类型选择。真实页继续区分订单回执与
PM 实际成交，基线页只显示基线指令。
交易记录按时间从新到旧展示当前历史范围内的基线成功
指令和真实订单，显示场次、指令时间、方向、价格、目标／完成股数、支出、状态和
逐笔 PnL，跳过的信号仍在总览 SIGNALS 中查看。基线成本和盈亏来自原始账本；
真实完成股数与支出只计已确认成交，逐单结算证据不足时 PnL 保持待定。
M1 实盘直接读取 `m1_live_*` 会话的风险日志，包含 RF／EX、候选跳过原因、信号原价、
首次识别时间、每次真实 POST 与接单／拒单／未知回执。同一订单的重复回执去重，
重试次数继续单独计入实际提交数。看板升级会只重放自己的派生采集游标，不改源日志，
也不读取账户或交易状态数据库，不重启基线或实盘策略。
若实盘声明 `fill_tracking=NOT_TRACKED`，SESSION 持仓和 PnL 显示“未核实”，交易页
完成股数和实际支出显示“—／未核实”，不会把 ACK 当作成交，也不绘制零收益曲线。
现按用户授权由看板独立只读查询账户数据：从实盘 journal 文件名核对 funder 地址，
只发官方 Data API v2 `/positions` 和 `/activity` 的 GET，OPEN／CLOSED 均读取，
读取所有游标页及小于默认 dust 阈值的仓位。按账户、condition、slug 与 token 核对，
只统计展示起点之后的 M1 市场，不加载密钥，不创建交易客户端或获取交易账户锁。
活跃／待结算场次约 15 秒更新一次；已结算且结束超过 15 分钟的场次约每小时复查。
账户快照写在独立观察器的 `pm_account` 表，市场归档也保存相同证据。网络异常保留
上次可信数据并显示读取错误；空索引、分页失败、缺失金额不自动补为零或伪造满额成交。
真实累计图按市场的 PM 账户持仓经济数据核算：已关闭仓位采用官方已实现 PnL；
尚未关闭但官方结果已确定的仓位，将 PM 账面估值替换为最终二元赔付。使用的公式为
`PM total_pnl - PM current_value + current_size × 最终赔付`，不再重复加赎回金额或扣费。
结果待定时只展示浮动收益，不加入已结算累计。账户持仓数据可补充 SESSION，即使
策略自身继续声明不跟踪成交，也不修改策略的账本或运行方式。
交易页将“真实订单”与“真实成交”分别列示；Data API 没有订单 ID，不按相近价格
强行归单，真实收益按账户场次汇总。成交金额与逐笔费用不能替代场次官方 PnL。
实际成交的逐笔 PnL 可以从已有快照补算：先按 token 核对完整 BUY 成交股数与 PM
仓位累计股数，再使用官方最终赔付减去该笔实际成交金额。单笔成交可计入其明确费用；
多笔成交只有费用明确为零时才直接分解。已关闭仓位若仅有一笔完整 BUY，可直接归入
该仓位官方净收益。包含 SELL、成交历史不全、费用无法分摊或经济数据不一致时不补。
核对允许 PM 汇总与逐笔明细的精度尾差，每组上限 0.001 USDC；不修改逐笔结果强行
凑齐官方汇总。合计仍使用 PM 场次值，避免订单回执与成交记录重复计算。
没有成交身份关联的订单回执行显示“未归单”，未结算成交显示“待结算”。
账户现金余额由独立的 `BalanceObserver` 在首次发现一个正在运行的真实 M1 session 时
读取一次；不对历史场次补填当前余额。它只读现有 `.env`／环境变量中的签名身份及
`config/config.toml` 中的钱包签名类型，先 GET `/auth/derive-api-key` 获取已有认证凭据，
再 GET `/balance-allowance?asset_type=COLLATERAL&signature_type=...`。仅复用 SDK 的
认证签名函数，不构建交易客户端；传输层只允许这两个官方 HTTPS GET，禁止创建 API key、
更新 allowance、订单、重定向及其他主机。核对日志中的 funder 与本地配置一致。
余额采用响应 `balance` 的六位小数单位，不使用 allowance、持仓估值或策略预算替代。
查询前即在看板独立 SQLite 的 `pm_session_balance` 表记录本场已尝试，完成后仅存
金额、地址、时间、状态和固定错误类型，不存密钥／认证凭据／HTTP 正文；网络失败
标记不可用，本场不重复读取，下一场重新读取。观察器重启也不会重读已尝试的场次。
账户框标记“本场一次快照”与实际读取时间，不当作实时可用余额，也不回写为策略启动资金。
已有 LIVE 日志中的官方余额仍作为未接入独立快照场次的展示来源；缺失项不补零。
平台自动结算的声明不等于成交或结算收益证据。
交易记录的 `↓`／`↑` 分页按交易笔数计算，`h` 切换历史范围并返回第一页。
M1 场次记录首次进入展示当前类型最新的场次；旧 CA 归档索引保留从早到晚的兼容顺序。`↓` 下一页、
`↑` 上一页。页面显示页数和场次范围，终端高度只影响每页行数，不再隐藏较早场次。
`h` 按 **4h → 8h → 12h → 24h → 4h** 循环切换历史周期，默认显示 4h；曲线和归档索引
一起按所选周期更新，当前 session 保持独立展示。周期仅影响本次看板显示，不改变采集或归档。
完整总览建议终端至少 120 列、40 行；小终端使用紧凑总览。
窄终端自动纵向排列，`--once` 可以输出完整文本供滚动查看。不会修改已有交易服务。

```bash
.venv/bin/polymaker dashboard --once
.venv/bin/polymaker dashboard --json
.venv/bin/polymaker dashboard --session-id SESSION_ID --history-hours 48
systemctl --user status polymaker-dashboard-archive.service
journalctl --user -u polymaker-dashboard-archive.service -n 20 --no-pager
systemctl --user disable --now polymaker-dashboard-archive.service
```

不使用服务时，在独立终端运行：

```bash
.venv/bin/python -m polymaker.dashboard archive --project-dir .
```

另一个终端使用 `.venv/bin/python -m polymaker.dashboard view` 打开看板。
独立模块入口不导入主交易 CLI。`dashboard-archive --once` 仅进行一轮有上限的增量采集，
不会为补齐全部历史无限运行。输出目录有独立进程锁，重复启动会明确退出。
可以用重复的 `--journal-dir` 指定多个日志根目录；默认跟踪 `journal` 和 `livecfg/journal`。
初次发现范围默认为最近 24 小时，可在观察器启动时用 `--history-hours` 扩大。
看板的同名参数仅过滤已采集的数据，不会主动读取更早的日志。

## 历史 CA 展示与统计

- 当前市场、session、策略阶段、等待/退出原因、日志时间、观察器快照年龄。
  当前市场没有新 session 时展示最近一次并明确标记历史，不把旧日志当成正在运行。
- CA / BA 分方向展示最近 episode、状态、anchor、剩余有效期。
  CA 使用头信息记录的实际路径，其独立 session_id 可以不同。确认计数不是可交易机会数。
- SESSION 显示启动预检的 `Available Capital`（USDC，6 位小数），固定为会话启动快照。
  历史日志仅在可核实时恢复该值；缺失时显示“未记录”。
- 订单、确认份数、YES / NO、Delta、未配残仓、已配未合并份数。
  撤单 ACK 不等于成交核对完成；不会据此提前清空风险。
- SIGNALS 右侧的 POST 面板按 CA / TP / BA、YES / NO 展示本场实际发单笔数。
  仅统计 `post_started=true` 的订单尝试，同一尝试重复日志去重；已发送后拒单或 UNKNOWN
  仍计入，发送前 ABORTED 与预签名不计入。此处按订单尝试计数，EXECUTION 的 POST
  按 HTTP 请求计数，批量发单时两者可能不同。窄终端将 POST 排列在 SIGNALS 下方。
- 已确认 PnL 的累计 Total / TP / SL / OTHER 曲线。Total 为三类已确认收益之和。
  FIFO 归因数据继续保留在账务与归档中，不再展示归因分布。
- 交易日志没有提供完整行情估值，所以 v1 不展示未实现 PnL、实时 WS 延迟或账户净值估计。
  日志年龄只代表日志新鲜度。超过 10 秒的采集快照或当前日志明确标为过期。

成交按 `(trade_id, maker_order_id)` 去重，仅 CONFIRMED 入账。
使用 Decimal，FIFO 采用首次观察成交的日志顺序，迟到的 CONFIRMED 不改变该顺序。
Taker 必须同时具备精确 `principal_usdc` 和 `fee_usdc`，不能拿报价或 POST 中的 nominal
份数代替真实成本。费用按匹配份数分摊，已计入收益，不二次扣除。
按完成配对的退出腿归因：首次 CA TP 和恢复 TP 归 TP；带 `:ca-expiry-exit` 标识的
TP 到期 Taker 退出归 SL。反向 BA（含普通 REPAIR、TP 接管及历史 BA Taker）、
CA 再开仓吸收旧残仓、系统退出及其余配对收益归 OTHER。
所有已核实残仓结算归 OTHER，不按该残仓的开仓来源分到 TP 或 SL。
归因版本为 3；观察器重启时用已有成交证据重算历史缓存，归档生成新版本，原版本保留。
合并确认只改变库存和合并量，不再次增加配对收益。

未配残仓在结果未知时保留 PENDING。最终 run result 提供可核对的胜方和结算分项时直接
核算；否则持续运行的观察器通过官方 Gamma `/markets/slug/{slug}` 补查。每次最多一个
后台请求，超时 3 秒，未决或失败每场间隔至少 30 秒重试，不阻塞每秒日志采集。
仅接受 `closed=true`、最终状态 `resolved`、二元终值 `0/1`，并逐项核对 slug、condition ID
和两个 token ID；按 token ID 映射本地 YES/NO，不假定 Up/Down 或数组顺序。日志库存核对
或成交确认未完成时不据此计算结算值。`--once` 仅使用已有本地结算证据，不发起补查。
结算值按实际残仓份数乘最终赔付减去其 FIFO 成本，计入 OTHER、Total 和曲线，
与残仓大小无关。原始结果证据保存在独立观察器 SQLite 和市场归档，更新生成新版本。
未结算残仓显示待定场数，未确认部分不计入已确认合计，不以零收益代替。
这是结果确定后的结算盈亏，不代表已执行赎回；赎回现金不重复计为新收益。
返佣与 gas 单列，未知项不填零。缺失日志、解析错误、CA 丢弃、成交成本缺失或最终
库存不一致会保留质量提示；已确认配对部分仍可查看，完整交易 PnL 保持 PENDING。
风险 writer 的 `flush()` 本身会占用无输出的序号，所以前向序号空洞记录在 manifest，
不直接声称丢失了交易；CA 序号缺口及风险序号倒退明确报错。

## 归档

```text
research_outputs/dashboard/
  observer.sqlite3              # 独立采集游标和派生证据，不是交易 state.db
  observer.lock
  latest.json                   # 原子替换的实时快照
  intervals/YYYYMMDD/HHMM/       # 每整 5 分钟一次，即使当前没有交易
    snapshot.json
    summary.md
    manifest.json
  archives/YYYYMMDD/HHMM_SESSION_ID/
    latest.json                 # 最近版本指针
    v0001/
      summary.md
      snapshot.json
      signals.jsonl
      orders-fills.jsonl
      manifest.json
    v0002/                      # 迟到确认、收尾或结算证据追加修订
```

市场归档在五分钟市场结束、完整记录读取后产生；未完成交易或待结算市场为 PROVISIONAL。
最终结果、核对和结算均完整才可成为 FINAL。旧版本不覆盖，每个文件有 SHA256 和大小，
manifest 同时记录源路径、inode、读取偏移、序号、解析/缺口状态、源码哈希与策略参数。
归档先在临时目录写完再原子发布，磁盘错误会在看板和服务日志显示并重试。

interval 名称是调度区间 `[start,end)`，内容是 `observed_at` 实际已观察的快照，
不是严格重建的截止时刻账本。初次启动补档明确记录观察延迟；停机漏掉的窗口仅记录数量，
不伪造当时状态。市场归档保存该 session 截至观察时间的完整生命周期，两个时间都保留。
每秒快照只精简历史配置；详细来源和配置在市场归档保留，避免重复写入全部历史大对象。

读取每轮预算 8 MiB，每个源预算 1 MiB，允许为读完一行额外读取至多 4 MiB，
并设置 150ms 的读取时间预算；历史与最新源轮转，
未追平时显示 CATCHING_UP。JSONL 半行等待补全，重启使用已提交游标；源替换/截断明确提示。
大体量的 cache/prepared 诊断只提取时间、序号和丢弃计数，不解码其内部 payload；跳过数量
写入来源记录。订单、成交、信号和收尾证据仍完整解析与校验。
服务 CPUQuota=15%、Nice=10、MemoryMax=256M、IOWeight=10；资源限制只作用于观察器。
初次历史补齐需要时间；清理器已删除的原始日志无法恢复。归档目录不属于现有交易日志清理范围，
会持续保留，需要按自己的磁盘保留策略另行管理。
