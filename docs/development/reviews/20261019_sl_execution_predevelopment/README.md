## 1. 开发范围

本次入口只覆盖HD→SL首次发单、TP→SL交接、SL内追价、相关回执/异常处理，以及SL并行撤挂带来的反向仓位交回普通REPAIR。

允许的必要配套：session总预算20、全部在途资金/Delta登记、逐请求身份隔离、逐订单查询及额度释放、SL订单范围内撤单、T240并发收尾、日志及回归验收。

保留现有行为：

- NORMAL开仓信号、价格、数量、周期和T120截止；已确认session总预算从15改20带来的可用资金边界变化除外。不增加SL专用资金池、NORMAL子限额或新的分配策略。
- HD/TP/SL判定公式及参数、TP定价与已接受TP单的队列维持；TP→SL只增加执行交接，不提前预挂SL、不长期保留旧TP。
- 已有普通REPAIR规则、≤2.5不新修复、<0.1配平、Data API 0.01核对容差与尘量处理。反向新仓仅补齐普通REPAIR所需输入，不借此重写全部仓位会计。
- T180强制SL、T240撤单及Merge规则；最终NORMAL/Merge交接仍需完整事实核对。
- 其他策略/旧命令、旧EV模型和冻结研究代码；不升级SDK、不迁移结算资产、不清理既有未提交修改。

SL执行需要修改共享文件中的少量接口，但新准入只作用于当前策略的SL及其交接；不得全局删除`safe_to_continue`、把所有策略变成并发或让旧TP关闭任务撤掉新SL单。

## 3. 已确认的四项，继续有效

1. session总资金20 USDC，所有本session交易累计共享。
2. 全在途Delta完整区间处于[-5,+5]；空间不足立即撤旧单，保留最新目标，按释放事件重新计算。
3. 仅撤换时短暂双挂，新SL优先提交并立即并行撤旧TP/SL。
4. 反向REPAIR默认HD、复用普通TP/SL规则。原方向SL不可回退；新方向不继承原方向SL锁定。T180/T240仍按session计时。

## 4. 本轮确认结果及唯一剩余项

### 确认1：有MATCHED但经济证明未到时，SL如何计算剩余修复量？

当前代码只要出现pending成交就暂不追价。新的事件驱动执行如果只看已证明实际Delta，可能在一笔已撮合但未确认时重复补足整个原缺口。

建议把可信、身份明确且去重的MATCHED数量计入“已承诺的修复量”，只对剩余缺口生成SL目标；这只是执行数量，不改写已证明实际库存。全部MATCHED仍计入资金/Delta未决上界，不凭此释放风险，也不凭此创建反向普通REPAIR。

例如YES实际5股，NO旧单已MATCHED3股但还没经济证明：执行剩余缺口为2股，不再新发5股，立即撤不需要的旧余量；≤2.5规则对这次执行剩余量也生效。MATCHED仅1股时，可对剩余4股继续SL追价，按既有最小5股/$1约束生成候选，再检查全在途Delta和20预算；若不满足就只撤单等待。

若MATCHED失败，撤销其“已承诺修复量”并立即重算同方向SL意图，不重启HD。这里“重算”不代表绕过现有FAILED隔离：`tracker.py:345`及`filltruth.py:145`仍会把FAILED视为未解决，新BUY必须在已有异常核对解除隔离后才可提交。本次不扩展FAILED自动恢复能力。成交身份冲突/方向尚不确定的情形也隔离处理，不能拿来计算确定的新方向。

**已确认：采用“可信MATCHED抵扣执行剩余量、经济库存及风险预占仍按原事实口径”。** 替代当前“有pending一律不追价”，并明确≤2.5在未证明成交期间的执行含义。

### 确认2：旧单什么证据齐备后可以释放未成交余量？

建议允许后台定向证据释放：POST已经结束，撤销之后的身份匹配订单终态、完整相关订单/成交页相互一致，即可释放已证明不再可能成交的余量；已MATCHED未证明部分继续预占。无需再等capital/positions刷新，也不用重新验证整session所有旧单。

取消ACK本身、普通not found、空交易页本身、POST仍在途时的早到取消，都不满足释放条件。迟到成交与本地观察冲突时保留或收紧预占，并定向核对。可靠取消ACK可以先停止无意义重复DELETE，不必等到额度释放。

**已确认：采用上述逐订单证据释放，完整账户核对保留在后台和最终交接。** 只有本地额度被占满时，新SL才会依赖这份证据；额度本来就足够时仍先发新单。

### 确认3：反向残仓的成本与TP用什么PnL？

**已确认的处理分支：反向实际残仓≤2.5 share不再修复；>2.5 share走普通REPAIR，从HD开始。** 不另设反向策略，不因T180强制SL绕过≤2.5停止规则。小残仓仍保留真实数量、成本及未决订单处理，不能当作已配平或据此重开NORMAL；后续迟到成交使其>2.5时重新按普通流程判断。

用户随后明确确认下述FIFO成本方案。该规则只补齐>2.5反向残仓的普通TP输入，不改原有非反向episode公式。

当前代码累计原episode全部成交，尚不存在新反向仓位的普通输入。建议只在本次SL并发产生的新方向交接处：按可靠成交时间FIFO配对已买YES/NO，把剩余成交批次的真实成本归给新方向；该新普通REPAIR的TP看残仓自己的浮动PnL，已配对锁定PnL留在session/修复链累计报表，不掺入新方向TP判断。原有非反向episode的算法不在本次重写。

例：YES5@0.30，先成交NO5@0.65，再成交NO5@0.71。FIFO下剩余是NO5@0.71；已有5对锁定+0.25。若当前NO为0.70，新方向浮动PnL是−0.05，session总浮动/锁定合计+0.20。若用NO10股均价0.68给残仓分摊，反向浮盈会变为+0.10、配对锁定变为+0.10；总PnL仍+0.20，但TP触发不同，不能把两种会计随意混用。

**已确认：>2.5股的反向残仓，采用“按成交时间FIFO划分残仓，TP仅看该残仓浮盈亏，session总PnL连续累计”。** 这是新反向上下文输入归集，不修改TP公式、阈值或价格。另一可选方法是同侧成交均价分摊；两者都不影响session总PnL，但会影响普通TP触发；本版已明确选择FIFO。

### 确认4：反向HOLD的持有时间和路径从哪里开始？

建议新方向使用上述剩余成交批次的最早可靠实际成交时间作为取得时间，不能等经济证明到达才重新计时。复用已有可信交易所时间/首次本地成交观察的来源规则；没有可靠历史就记录路径缺口，不编造。

新方向的路径从该残仓取得后的可靠历史建立，波动率仍用同一市场估计；不继承旧方向的回撤峰值，也不另加固定HOLD时长。相同方向随后部分成交按普通增量更新，不反复重启HD或把时间归零。

例如残仓成交T150、证明T156，进入新普通REPAIR时持有时间已是6秒，可回看可靠的T150–156新方向路径；不是从T156重新等待。已满足通用TP/SL条件可立即转换，T180及T240继续优先适用。

**已确认：采用“实际剩余成交时间起算、可靠历史连续接入、无额外HOLD等待”。** 残仓批次由已确认的FIFO规则确定，再按对应真实批次确定时间，不新增反向计时参数。

### 确认5：SL是否继续遵守现有网络熔断/冷却？

当前网络控制不只有“批次在途”：连续慢请求、超时、服务错误或限流可触发PAUSED，恢复需要冷却及探测；这可能继续推迟新SL。把旧单active_batch当成新单禁止条件必须去掉，但是否也取消真正的冷却是另一项执行取舍。

建议本次保持现有网络熔断触发及恢复规则，SL一组内允许多请求并行；已进入网络PAUSED/恢复等待时仍不新POST，必要DELETE持续按现有异常规则执行。当前配置初始冷却2秒、失败恢复退避上限8秒，并要求后台探测通过；反复异常还会延后恢复，不能把8秒称为总等待上限。探测在后台进行，不为每个SL动作新加探测。NORMAL和TP的网络准入不改。

网络状态的活动请求归属及安全关闭接口需适配SL并发，避免仅因组内还有旧请求就永远无法进入恢复探测；逐单收尾不能调用全session取消把新单一起撤掉。此处是适配旧熔断规则，不新增阈值或探测政策。

**已确认：保留原网络熔断/冷却，只解除SL链内“已有批次在途”的程序互斥。** 本次不新增SL绕过PAUSED或专用网络重试政策。

## 7. 本轮复核后的执行定义与开发任务

### 7.1 执行量、实际量与风险量分开

```text
D_actual = 已证明YES数量 - 已证明NO数量
M_Y/M_N = 可信且去重、尚未成为已证明库存的相应MATCHED数量
D_exec = D_actual + M_Y - M_N

Delta_possible = [D_actual-U_N, D_actual+U_Y]
```

其中LIVE/POSTING/CANCEL_PENDING/UNKNOWN的未撮合余量不抵扣`D_exec`，只计入`U_Y/U_N`及资金预占。否则旧挂单已覆盖缺口就会错误地阻止接替，违背这次并行撤挂目标。MATCHED本身仍计入`U`，直到经济证明接续；转为实际时原子转移，两个账本不能重复计数。

当前方向SL按以下顺序生成操作：

1. 已到T240、已知无效行情、FAILED/身份冲突或现有网络准入不允许时，走原有截止/异常分支；必要撤单立即执行。
2. 实际|Delta|≤2.5，不发新的修复BUY，撤不需要的余单。0.1–2.5仍是残仓，不算配平。
3. MATCHED抵扣后已覆盖当前方向缺口、估计翻转或执行剩余≤2.5时，撤冗余余单，不再按旧实际缺口重复补仓；估计翻转不创建反向HD，等待实际方向证明。
4. 同方向执行缺口>2.5时，按其数量结合现有最小5股/$1、最大单量生成候选；候选须减少该执行缺口的绝对值，并满足全在途Delta5及session20，不能仅因为实际旧Delta看起来大就凑一个不减少执行缺口的最小单。
5. 本地可行则优先发新POST、同轮DELETE旧单；不可行则立即DELETE、保留最新目标，逐单事件释放后重算。任何重试都重新校验当前方向、状态和T240，不能盲发旧候选。

真实方向已经翻转时先撤旧方向余单，然后按用户确定的实际≤2.5/>2.5分支交接普通REPAIR；原方向遗留未决量始终计入session风险。新普通HD没有发BUY的义务，已到T180则沿用原有时间强制SL。
