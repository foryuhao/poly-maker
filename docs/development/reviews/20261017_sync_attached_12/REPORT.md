# 同步旁路一小时运行复核

日期：2026-10-17，所有时间为北京时间。审查范围为 20:20–21:20 的 12 个连续五分钟市场，首场 epoch 1792239600，末场 epoch 1792242900。每次 shell 调用独立进程、Session 和快照目录；不包含程序内部跨市场循环。本次只读取日志、源码和持久化快照，没有调用交易 API、启动交易、改动策略或配置。

**更新后的结论（按用户确认的缓存定位）：第一步的独立采集与内存快照运行稳定，具备进入 NORMAL、REBALANCE 整合开发的条件。snapshot 表示当前市场与账户的服务器观测状态，不承担每笔订单生命周期审计；已在两拍之间撤销的短命订单无需曾经出现在快照中。写操作、回执、在途和未知状态继续由执行器管理并写入操作日志。第二步需要完成消费适配、操作之后的来源有效性判断及成交/库存/资金协调，不能直接以“有新版本”替换关闭证明。

## 提前取得成交证据的效果

按 `(trade_id, maker_order_id)` 识别成交，状态流转不重复算新的成交。原策略最终记录了 **20 条确认成交，涉及 15 个订单**；旁路全部观察到。

**以 `snapshots.jsonl` 第一次真正发布、且包含该笔 CONFIRMED maker leg 的快照为准**，与原策略记录该笔 `sm_trade CONFIRMED` 的单调时钟相比：

- 18/20 条在旁路快照中更早可见；2 条晚约 115ms 和 37ms。
- 全部 20 条的“原策略记录时刻 − 快照可见时刻”：中位数 **1,998ms**，p95 **7,898ms**，最大 **9,111ms**。
- HTTP 读完 CONFIRMED 到快照发布：中位数 **184ms**，最大 **216ms**。只看内部 `sync_trade_observed` 事件会高估可供执行方消费的提前量，所以主要结论使用快照发布时间。

例如 **20:40 场的最后一笔配对成交**，旁路快照已经包含 CONFIRMED，原策略仍过了约 9.1 秒才在自身成交账本中记录。本次不能据此保证接入后能节省同样的时间：安全关闭还要求相关订单终态、数量、关联成交、在途 POST 和资金预留一起满足规则。

这说明“周期同步＋本地证据复用”的方向有实测价值；本阶段并没有改变原策略补仓速度。

## 第二步接入需要明确的缓存语义与一致性规则

### 1. 短命订单未出现在当前挂单快照属于正常采样现象

105 次提交中，104 次 ACK，1 次拒单。104 个成功挂单中有 **14 个（13.5%）**，旁路整个 Session 都没有采到其订单详情；它们也从未出现在旁路记录的全量挂单或对应成交中。13 个属于 NORMAL，1 个属于 REBALANCE。它们从 POST 开始到首次撤单 ACK 的时间在 **283–1,333ms** 之间。

这符合当前状态缓存的定位，不作为第一阶段缺陷或接入阻塞项。第一阶段从服务器返回的挂单和成交发现待查 ID；一笔单在两次查询之间已经撤掉，后续当前挂单列表不再包含它是正确的。交易动作及其结果由执行器本地状态和操作日志保存，不要求 snapshot 证明每笔订单曾经存在，也不以提高采样频率追求生命周期覆盖。

**具体时间线：20:30 场 w1。**

| 时间 | 原策略/旁路事件 |
| --- | --- |
| 20:30:22.636 | 旁路上一轮全量挂单查询完成，当时尚未 POST |
| 20:30:22.794 | 原策略开始 POST |
| 20:30:22.849 | 原策略出现有效方向反转，开始撤单 |
| 20:30:23.077 | 撤单 ACK；POST 也在此时返回成功 |
| 20:30:23.451 | 旁路下一轮开始查询全量挂单，该单已经不在列表 |

主策略仍在原 journal 中保存此单的签名预期 ID、提交结果及后续关闭证明。证据：[原策略 journal，第 28–35、59 行](../../../../../poly-maker-data/journal/rdp_sm_0x2d73e1f6c90662d30e13fed534bf10bc5bd99d5d_dac6d84080274b02a15316a6c4a26cc7.jsonl)，[旁路 HTTP 事件，第 96、101 行](../../../../../poly-maker-data/research_outputs/periodic_sync/dac6d84080274b02a15316a6c4a26cc7/events.jsonl)。

**第二步的处理：**执行器保留签名 ID、POST/DELETE 回执、在途/未知状态和资金预留；缓存保持服务器当前状态的职责，不为审计而把每笔已撤短命单补进快照。消费适配层结合本地操作结果与操作完成之后的服务器观测，核对当前挂单、成交、库存和资金。列表缺席不能覆盖尚在途或未知的操作，404 也不自动解除未知风险；确需进一步核验的异常由服务在固定心跳内处理，调用方不主动触发网络刷新。

### 2. 同一快照中的不同来源会暂时不一致

732 次订单详情与成交列表核对，731 次一致，**1 次短暂不一致**：20:40 场的订单详情显示已成交 5 股，但稍早完成的本场成交列表没有这笔成交，关联成交 ID 也不一致。下一轮约 1 秒后成交列表补齐，核对恢复一致。

证据：[20:40 场旁路事件，第 649、656、658 行](../../../../../poly-maker-data/research_outputs/periodic_sync/534f6433923f4335956983d8f2e0e661/events.jsonl)。这与各个 API 的非原子读取、读期间发生的新成交或服务器可见性差异相符；仅凭现有日志不能区分这几种成因。

**第二步的处理：**执行方按相关订单检查详情数量、关联成交和确认状态，检查各来源请求与相应操作的先后关系；不一致就等待下一次心跳，不立即补仓，不把全局版本递增当作关闭证明。不需要调用方主动刷新。

持仓 API 也不能代替成交账本：本场 13 个曾成交 token 的首次非零持仓，在首次 MATCHED 观察后约 3.0–10.0 秒才被读取到；这个间隔混合了成交确认、服务端可见性与 2 秒轮询等待，不能全算成模块延迟，也没有验证每个后续部分成交的数量已经对齐。库存与预留仍应根据经确认的订单/成交事实及 merge 更新，持仓用于账户复核。

## 对原策略和资源的影响

旁路实际新增 **15,078 次 GET**，全是 HTTP 200，没有 POST/DELETE，没有 429；累计模块存活约 3,586 秒，约 **4.2 次 GET/秒**。原策略自身仍有 **13,593 次被 journal 计时的 GET**，未移除重复查询；主策略持仓接口不在这套网络计时覆盖内，不能将这两个数字之和称为账户全部网络请求。

与部署前最近一批 **15:40–16:40 的 12 场**对比：

| 原策略 HTTP 指标 | 上一批 p50/p95 ms | 本批 p50/p95 ms |
| --- | ---: | ---: |
| POST 下单 | 226 / 442 | 220 / 494 |
| DELETE 撤单 | 220 / 388 | 216 / 390 |
| GET 订单详情 | 228 / 324 | 223 / 320 |
| GET 全量挂单 | 199 / 332 | 196 / 345 |
| GET 成交 | 200 / 306 | 198 / 308 |
| GET 资金 | 196 / 364 | 193 / 368 |

请求中位数没有普遍恶化，但 POST 尾部变慢：最大值由上批 862ms 变成本批 **2,173ms**，发生于 **20:47:07.301–20:47:09.474**。主策略进入 PAUSED 次数为上一批 13、本批 14；本批原策略有 2 次 DELETE 传输错误，均在 20:35:29.71 附近并很快重试成功；旁路同期没有读取故障。不能把“旁路没有报错”解释成“原策略所有网络操作都成功”。

两批不是同一时间的 A/B，对信号、成交密度、交易服务器与网络变化没有控制。因此只能说未见普遍的中位延迟退化，不能排除新增流量对长尾的影响，更不能把尾部变化直接归因于旁路。当前 REBALANCE 收尾仍走旧路径，本批 22 次有提交的 REBALANCE 从请求关闭到窗口关闭的中位数约 **8.38 秒**，不应宣称新模块已改善策略效率。

旁路五类文件合计 **206.1MB**，其中全量快照约 152.4MB。记录的 CPU 时间合计 255.9 秒，峰值 RSS 各进程约 101.7–127.5MiB；这些资源指标覆盖整个主进程，包含交易策略，不能说是同步线程独占的开销。

## 建议与限制

第一步观察验证的主要目标已经达到，建议开始第二步 NORMAL、REBALANCE 整合开发，无需为了让短命订单出现在快照中再修改采集器或另跑一轮测试。共同的数据消费适配层负责来源有效性、本地写操作与服务器观测协调、订单/成交/库存/资金的一致性判断；固定心跳继续作为唯一 HTTP 刷新驱动。实现和验证可先覆盖 REBALANCE 的读取与等待，再复用到 NORMAL，迁移对应读取后移除重复查询。保留现有终态、资金预留及未知订单保护；本报告不声称这些接入功能已实现或已通过实盘验证。

本次没有更改生产代码或配置，没有调整心跳，也没有运行新的市场。分析证据包括来源文件哈希、实际行号、每笔挂单覆盖、每条确认成交提前量和引用年龄，可复算；基线索引扫描排除了一个历史 JSON 损坏文件，该文件不属于本批 12 场，也未入选对照 12 场。当前报告没有计算净盈亏、返佣或策略预期收益，不能把快照提前量等同于实盘收益。
