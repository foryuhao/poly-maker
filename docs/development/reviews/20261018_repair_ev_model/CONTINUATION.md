## 1. 本轮补上的逻辑

从只比较HOLD/新单、KEEP/CANCEL，扩展到比较一次撤单后的自适应重挂：

`请求撤销旧单 → 旧单继续承受成交风险 → 可靠撤销生效 → 读取当时价格及已成交量 → 计算新方向、价格、合法数量 → 新单提交延迟及post-only检查 → 成交/撤单 → 残仓结算`。

新单的价格和数量取决于撤单完成时真实可知的状态；不能在T102直接按T102盘口和原5股数量假装已经换单。旧单全部成交时不再发新单；旧单部分成交后，剩余不足最低数量时重新检查最小股数、金额、反向敞口和资金。

这里的“撤销生效”是模型中剩余可成交量已消除的时刻，不等于现实里的任何单次撤单ACK。实际数据缺少该事实时不允许重挂。

## 2. 两张订单的价值如何计算

设撤销生效后的价格/旧单成交量联合状态为s，概率为w_s。替换策略价值为：

`Q_replace = 已提前完成路径的PnL贡献 + sum_s w_s * (M_s + G_new(s))`。

G_new包含新单排队重置、post-only拒绝、部分成交、不利成交及撤单延迟。替换后暂按新单计划及结算持有继续，不使用事后最优价。代码逐情景验证：

`Q_replace - Q_cancel = sum_s w_s * G_new(s)`。

这保证旧单的迟到成交成本没有漏计，新旧订单没有重叠预留或被当成瞬时撤换。

为了复用计算，同时缓存新单收益g的三个矩：E[g]、E[g平方]、E[Z*g]。Z为YES最终结果。令A=N-C、Delta=Y-N，则：

`E[Pi] = M + E[g]`

`E[Pi平方] = A平方 + 2*A*Delta*p + Delta平方*p + 2*A*E[g] + 2*Delta*E[Z*g] + E[g平方]`。

其中E[Z*g]保留成交与结算的关联，没有把波动、结算风险和PnL简单相加。缓存只复用成交分布；实际库存、现金和可行性逐分支检查。

|T220，p=0.31，旧NO5@0.40，排队年龄20秒|REPLACE_AFTER_CANCEL|先撤旧；生效后按剩余仓位与当时best bid重挂，T240撤新单|0.0611|

最后一行的KEEP价值约0.0509，立即撤单后持有约0.0500。若T220.2旧单已可靠撤销、期间没有成交且p仍为0.31，则新单为NO5@0.68，计划T240请求撤销；若期间价格/成交量不同，新单按该分支重新计算。JSON保存各分支概率、价格、量与最早可提交时点。

## 4. 部分成交与连续复核

增加EpisodeContext，记录原修复方向、已使用的REPAIR提交次数和事实完整性。更新上下文依靠实际POST/成交/终态事件，不因模型作出建议或价格复核就重置。

当前研究子策略最多两次REPAIR提交，用于验证一张旧单加一次替换的完整时序；这不是用户新增的生产交易次数限制，也不是任意次数重挂的全局最优解。重新复核不会自动获得又一次免费替换机会。

一个输入真实成交事实的连续例子：

|观察时点|累计NO成交|原单余量|基准模型动作|
|---|---:|---:|---|
|T102，p=0.25|1|4|KEEP NO4@0.68|
|T104，p=0.30|3|2|KEEP NO2@0.68|
|T106，p=0.35|5|0|HOLD已配对仓位，不再下修复单|

这是连续观测后的计划演示，不是以三条假定观察计算出的完整策略事前EV。

还增加三项处理：

- 原始缺口已经覆盖或最低金额超量产生反向残仓时，请求撤销原余单，接受残仓；不继续为了赚模型价差扩大反向仓，也不自动买回原侧。
- 原单不足5股的余量可以保留；撤后重发的新单仍受最小数量约束，二者分别评价。
- 订单/成交事实不完整时输出CANCEL_AND_RECONCILE，不把未知当作无订单，也不给出虚构的确定EV。T240仍停止新单、请求撤余单、继续核对迟到成交。

## 5. 参数情景不能变成事后挑模型

当前共同评价四组未校准情景：基准、较低流动性、较高流动性，以及穿价时每步最多1股且成交概率0.5的有限深度情景。当前盘口、资金/数量约束、数值格点和提交/撤单延迟保持一致。

每个候选都是同一套可执行规则，例如“立即撤单，可靠生效后按实际剩余仓位及best bid重挂，统一在T240撤单”。允许根据未来已经观察到的事实调整；不允许按事先未知的真实参数挑选不同规则，再把各自最优值拼起来。

输出同时提供：

- nominal_decision：基准参数下期望PnL最高的候选。
- common_policy_stress_decision：同一候选在这组模型中的最小增量值最高的候选，作为模型风险检查。
- 每个候选在各情景下的EV、相对立即撤单/无单HOLD的优势及终端风险。

第二项不是概率意义的EV预测，也不是统计置信下界；不默认把用户目标从最大化EV改为最坏情景优化。没有拟合参数概率时不把四个模型简单平均，不宣称真实参数一定处于这四种情景。

结果示例：

|场景|基准模型|共同情景检查|
|---|---|---|
|T100、p=0.31，无单|BUY|低流动性下买单负增量，检查结果HOLD|
|T102、p=0.25，旧0.68未成交|KEEP|该候选在四个情景中均改善，相对立即撤单的最小优势约0.0267|
|T102、p=0.30，旧0.68未成交|KEEP|存在不支持续挂的情景，检查结果CANCEL|
|T220、旧0.40离盘口很远|REPLACE|低流动性下替换不划算，检查结果KEEP；优势很小，不能视作实盘有效边际|

这些分歧直接指出哪些参数需要实证识别，不让模型通过选择有利参数制造正EV。

## 6. 挂单时间可以选内部解

单独增加结构敏感性：某旧报价年龄达到20秒后，有利流动性成交强度变成原来的3%，公平价格仍按输入波动率变化。这个假设没有从数据拟合，不属于基准参数。

在这一情景下，T100的NO5@0.68选出的计划撤单时间为T120，即挂20秒，EV约0.06113。继续挂到T240的EV约0.06012。求值器可以根据流动性/逆向选择的时间变化选择较短期限；20秒不是新固定TTL，也不是已测出的市场半衰期。

下一步应从数据估计条件成交强度随报价距离、队列及年龄的变化，而非人工选择能够得到理想订单的衰减形状。

## 7. 盘口输入与计算范围

增加Book输入适配：当前报价使用输入的真实bid/ask，不再必须由1-p加减0.01合成。未来盘口暂按当前偏移移动并按tick向外取整，是待验证的简化。

支持半tick中价，例如YES公平价0.305、NO盘口0.69/0.70；公平价格格点和订单tick分开。矛盾/越界/off-tick输入明确报错，不静默凑价格。这只是接口及合成例验证，还未接真实行情/订单流。

当前数值模型主要在0.01订单tick演示，较小tick需要数值方法和性能验证，不承诺可用于实时下单。

## 8. 验证与剩余工作

已验证：

- 概率质量、单单与两单PnL增量恒等式；缓存收益矩与直接求值一致。
- YES/NO互补对称；保持实际可用资金不变时，历史成本只平移PnL、不改变增量排序或风险方差。
- 撤单期间全部成交不发替换单；替换最早在撤销生效后提交；每分支检查资金、方向、最小量及T240。
- 部分成交余单可保留；覆盖/反转后撤余单、不机械翻回；未知事实不放新单。
- 复核不重置研究次数预算；有限深度下穿价不再必然全量成交；真实盘口样例与半tick格点。

仍待完成：真实事件时间对齐、参数及其范围的拟合、随机延迟/FAILED事实、实际队列/深度与波动状态预测、更多次干预和完整连续复核策略的闭环EV检验、固定NORMAL全部episode的样本外整体正EV验证。

当前Q是指定有限候选后续策略的精确离散模型值；反复重规划会改变后续策略，其完整事前EV不能直接等同于某一次局部Q。单个场景收益为正或四情景一致都不证明真实交易策略整体正EV。

后续[真实数据审计](../20261018_repair_ev_calibration/README.md)已完成：固定NORMAL的12场与现有47场Shadow没有重合；19场旧日志可对齐但政策/规模不同。所有31场均缺有效撮合时间和最终赢家，实际修复单首撤请求基本不超过3秒。当前不足以把lambda0、queue_scale或长挂单衰减拟合成真实参数。审计补充了终端订单收益标签这条路线，精确撮合时间缺失不妨碍补齐结算后研究实际收益；未执行的长挂单反事实仍待识别。
