## 修正的缺口

旧模型以 `C-min(Y,N)` 的累计最坏亏损直接决定HOLD与否，导致高价买入后大跌的仓位，即使剩余市值已很小，仍被强制寻找低于原成本预算的配对。这既可能无法实现，也把历史亏损当成追加资金的理由。

v3保留会计 `PnL_Y=Y-C`、`PnL_N=N-C`，但当前持有下行改为 `V-min(Y,N)`，其中 `V=pY+(1-p)N`。相同持仓和当前价格，前瞻风险与成本C无关；历史盈亏和新增风险限制仍与C有关。

## 用户案例

YES5股@0.75，当前参考价0.15：C=3.75，V=0.75，参考PnL=-3.00，累计最坏亏损3.75，但当前剩余下行为0.75。

若设计候选前瞻预算为每股0.30，则5股预算1.50，前瞻下行单项通过。其他有效性、波动、结算及联合预算通过时选择HOLD_ACCEPTED。累计损失若另已超限，可以同时NEW_RISK_BLOCKED，停止新增NORMAL。

等待检查必须显式参与：在有依据的反应窗口h_required上计算 `D*sqrt(V_hat*h_required)` 并比较B_wait_sd=0.15。若假设h_required=1秒、sigma_hat分别为0.02/0.04每√秒，5股的等待标准差为0.10/0.20，前者通过，后者不通过；后者若系统无法支持0.5625秒以内的真实风险反应窗口，则需评估减险动作。该例没有提供实测V_hat或反应窗口，不能据此无条件断言HOLD，也不能随意缩短h绕过检查。

若假设可以Maker买NO5股@0.85，将追加4.25并锁定整轮亏损3.00；相对当前参考点不再有结算波动。这个动作只消除了剩余0.75下行，原风险已接受时无需为了归零自动执行；如果其他风险门禁不通过，也不因历史亏损3.00而一律禁止该减险动作。

实际NO报价须来自真实盘口并满足post-only。这里的对侧价格只用于算术说明，未获取当前交易行情。

## 算术检查

- 相同Y/N/p、不同开仓成本，HOLD前瞻风险和同一修复动作的边际结果一致。
- 已配对Y=N=5、累计成本8，历史亏损3，但方向风险为0，不再通过买入尝试消除亏损。
- 低价买入0.15后涨到0.70，剩余下行为3.50，而非开仓成本0.75；配对可保护当前价值。
- 高价买入0.85且当前仍为0.85，NO6.67股@0.15的前瞻下行和反向残仓价值为0.2505。
- 低价Maker候选的条件参考收益不等于小残仓风险：NO7.15股@0.14例中，参考收益0.0715、残仓风险0.3225、相对原参考点下行0.2510，分别记录。
- 0/1/2.5/5股部分成交分别计算，以固定决策参考点为基准，未成交不提前算完成修复。

## 参数边界

`b_forward_loss_per_share=0.30`是新口径的设计候选，不是原开仓成本统计已验证出的前瞻风险最优值。旧b_loss_per_share和v2门槛不得静默改义；累计浮亏/已锁定亏损/回撤限制独立配置。B_wait_sd仍为短期等待标准差代理，并按真实敞口与波动率算复核间隔。
