# 合并限流与订单状态回退的会话恢复

2026-10-26。对应 288 次运行核查：31 个市场因合并调用限流提前退出，2 个市场因订单状态短暂回退提前退出；外层循环立即重启同市场，额外消耗 76 次启动。

## 修复后的行为

- 合并准备读取、或提交调用在返回交易句柄前明确抛出 SDK `RateLimitError`：记为拒绝/未提交，不设 `MERGE_UNKNOWN`，不释放仓位成本。按照服务端 `retry_after` 退避，最少 5 秒，再经过原有的持仓、身份与关闭证明检查后尝试合并。同一会话继续运行。
- 句柄已经返回后，轮询、回执或账本验证失败，包括此时发生的限流：继续保留 `MERGE_UNKNOWN` 和 `merge_pending`，不重复提交合并，不虚记回款；协调器暂停新单并保留会话到原市场截止时间。
- 已结束订单又被订单事件、订单详情或挂单列表报告为未结束：撤销该订单的关闭证明、恢复风险占用，记录 `sm_terminal_recheck`，暂停新单并执行原有撤单与核对。
- 缓存恢复要求完整集合读取与涉事订单详情都晚于矛盾证据，旧缓存不能解除保护。完整订单、成交、分页与全部已知订单的关闭证明通过，且核对期间没有新的矛盾或事件变化，才清除该矛盾，记录 `sm_terminal_recovered`，在原会话内恢复。
- 矛盾持续存在、成交证据缺失或读取失败：继续暂停到原市场截止，最后仍可返回 `INCOMPLETE`。账户身份、订单经济参数、日志持久化等独立故障不因此被清除。

## 代码位置

- `src/polymaker/rdp_sm_merge.py`：区分明确拒绝与提交后未知；兼容未提交的合并流水校验。
- `src/polymaker/rdp_sm_loop.py`：合并退避；NORMAL/BA/OBI 协调器对可等待的执行状态保留会话。
- `src/polymaker/rdp_sm_execution.py`：矛盾发生时撤销证明；完整关闭核对后恢复。
- `src/polymaker/rdp_sm_cached_reads.py`：缓存矛盾标记与新的证明时间边界。
- `src/polymaker/rdp_sm_recovery.py`：将订单状态矛盾纳入会话等待分类。

## 验证范围

两条旧测试原本要求短暂矛盾永久锁死，现改为要求：发生矛盾后阻止当前候选；只有后续新完整证明可以恢复，不能直接发送已被拒绝的旧候选。
