# 共享缓存执行接入实盘复核

范围沿用已冻结的 2026-10-17 22:45–23:45 北京时间 12 场。依据原 journal、同步 events/snapshots、manifest/summary；只读分析，无交易 API 请求和生产代码改动。

结论：采集、共享消费、减少重复 GET 已有运行证据；存在短暂等待、无效详情响应和成交时间字段缺失，尚不能称为完全无异常。缓存负责订单、成交、资金、持仓与校时；盘口/OBI 仍依赖 WS，市场元数据固定为启动时已验证的数据。

- 12 场 execution_reads_from_cache=true，8046 次策略缓存读取。5437 个持久化快照，事件/引用丢失为 0，无所检查的 Session/市场错配。运行时 5 个同步/缓存模块源码哈希相同且匹配复核时源码。
- 订单通道 3620 轮，实际开始间隔 p50/p95 为 1001/1002 ms；账户通道 1789 轮为 2001/2002 ms。整轮耗时 p50/p95：订单 212/429 ms，账户 237/381 ms。订单有 7 轮超过周期，最长 2853 ms；账户没有超周期轮次。
- 按 100ms 网格抽样，从来源请求开始计算数据年龄：订单/成交 p95 约 1.203 秒，资金 2.144 秒、持仓 2.154 秒。实际账户消费时，订单/成交年龄 p95 约 1.166 秒，资金/持仓约 2.079/2.115 秒。该缓存是秒级观测。
- 将主日志 operation_id 与采集事件 read_id 对齐，主日志 14177 次 GET 中有 12628 次是同一采集请求的重复记录；采集器 15246 加主策略独立 GET 1549，覆盖范围内实际去重为 16795。接入前 20:20–21:20 一小时，独立主策略 13593 加旁路采集 15078，共 28671；新批减少 41.4%。两批策略活动不同，不是 A/B。主日志未覆盖的部分启动、持仓、结算等调用未纳入，不能称为全进程全部 HTTP。仍保留 tick-size/version 及部分预检读取。
- 每次消费依用途检查所需来源跨过最近写操作时间，8046 次未发现该项时间边界违规；33 条确认成交与持久化缓存逐腿数量、价格一致，库存和现金流最终对平。此检查不等于认证全部安全逻辑。
- 774 次订单详情/成交一致性检查中有 7 次暂时不一致。8 个窗口以 SYNC_CACHE_NOT_READY 结束，随后约 2.01–3.28 秒首次恢复 SAFE。4 个发生在 post-only 穿价拒单后，4 个发生在 Already canceled/UNKNOWN 后。该原因只表示就绪条件未满足，现有诊断不能把全部等待精确归到单一来源。
- 2 轮详情返回 HTTP 200 但触发 SYNC_ORDER_INVALID / ValueError，均未作为成功证据发布；约 2.42/2.39 秒后读到合法详情并恢复。原响应正文没有持久化，具体哪个字段无效未知。HTTP 全为 200 不等于数据全有效，轮次 error_type=null 也不能代替单项证据检查。
- 33 条确认成交的缓存 timestamp 均为 0，官方 match_time 未被保留，影响撮合时间重建与延迟归因。应优先补齐该证据字段及缓存等待原因的细分诊断。

上一轮发现的 55/80 次补仓因 WS_BOOK_STALE 关闭属于盘口策略路径，现有证据不能将其归因于这个账户/订单缓存。23:25 场主要等待有 14.70/15 USDC 资金约束的直接证据；缓存接入本身也不能证明提高了交易收益。
