## 主要运行发现

1. **运行能正常收尾，但完成不等于配平。** 12 场都是 COMPLETED / SAFE_TO_CONTINUE / MARKET_CUTOFF，blocked_windows=0，缓存丢事件=0，无 observer fatal。111 个 NORMAL 与 31 个 REPAIR 窗口共 142 次尝试，140 次进入 POST；139 初始 ACK、1 初始 UNKNOWN 最终 REJECTED，2 次在 POST 前因信号过期中止。不是每个窗口都成交，也不能将窗口数当轮数。
2. **最大结构问题是最小订单产生反向残仓。** 12:20 原始只成交 NO 0.676664 股，但最小补仓 YES 5 股，剩 YES 4.323336。12:30 补 NO 0.10 时 $1 最小金额要求 10 股，留下 NO 5。12:40 NO 0.18 要至少 5.56 股，留下 NO 0.565714。三场重复命中 MINIMUM_FORCED_REVERSE_RESIDUAL，分别记录 130/55/114 次。该防反复翻仓规则阻止继续扩大交易链；不能据此声称规则失效，但这些仓位确实留到了结算。这与 12:50 的 NO 0.01 dust 不同。
3. **SL 成交占比高且亏损大。** TP 配对收益 +1.2990 抵不过 SL −7.5729。最差 13:05 场 SL 首次触发 T72.5，到本地观察补仓成交 T87.0，约 14.5 秒；YES 报价从 0.59 追到 0.79。12:25 第一轮约 16.3 秒，13:10 第二轮约 16.1 秒。它们包含撤单、重新报价、Maker 等待和成交观察延迟，不能全部归为 CPU 或网络耗时；需要按订单事件拆解才能优化。
4. **已有容差调整确已运行。** 12 场库存核对日志均使用 0.01 股容差，未因尾差阻塞到市场截止。但 `blocked_windows=0` 不能证明盘中没有库存等待：后续细查发现 13:05 场 CONFIRMED 到来后，Data API 仍迟迟没有展示 5 股 NO，约 T67.5–72.5 因账户核对等待而没有进入 REPAIR；这是实质仓位的副本延迟，与 dust 容差不同。12:50 的已知 0.01 股 dust 保留为账面仓位，未再次开单追补。
5. **数据与连接有短暂波动，未导致本批中止。** 12:40、12:45 各一次 time/ReadTimeout；12:55 一次 open_orders/ReadTimeout；13:10 一次 trades/ValueError。12:25 一张 TP 单因 WS_DISCONNECTED 收单，之后重挂；13:00 一张 NORMAL 单因 WS_EMPTY_BOOK 收单。所有场最终均跨过安全屏障。
6. **旧 TP 波动率 warmup 问题仍存在。** TP_VOLATILITY_UNKNOWN 在四场记录共 31 次（7+1+7+16）；此项属于先前暂缓的 RP-001，本次仅记录，不修改。
