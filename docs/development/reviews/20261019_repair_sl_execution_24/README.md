# 24场数据：SL识别与执行脱节研究

固定样本：2026-10-19 上海时间12:20–13:20、14:35–15:35，共24场，沿用上一轮审计的session及文件哈希。
固定HD/TP/SL规则和参数；本次只读分析，没有修改生产策略、配置、实时订单或进程。
主要分析：其中16场内的22轮实际SL补仓，47次SL POST，25次撤换；另检查TP成交后的尾仓SL。

## 结论

执行层存在显著脱节，主要在订单生命周期及证据等待，而非签名/计划计算慢。
系统识别SL至首次本地观察MATCHED，平均8.071秒，中位数6.079秒，最长19.021秒。
若从历史价格路径首次满足SL算起，平均9.047秒；其中历史触发到实际识别的均值0.976秒、中位数约5ms，呈长尾，而非每次固定慢1秒。
识别后首单延迟集中在模式切换：7轮需要撤销现有TP单，识别SL至首个SL POST平均2.974秒；其余15轮平均31.3ms。应优先检查模式切换/关闭核对路径，而不是优化毫秒级计划计算。
47次发单前的最终SDK证据均满足quote=当时对侧ask−tick；计划到POST中位约15ms，所有47次原始路径as-of中点均与最终盘口一致。不能把问题概括成系统直接提交数秒前的旧报价。较老的book接收时间也不等于报价内容已经落后，REPAIR允许安静盘口继续有效。
但下单后的价格风险仍然存在：44个ACK订单中，12个在POST到ACK期间出现至少1tick不利中点移动，5个至少2tick，最大3.5tick；这是中点变化，不是ACK时完整BBO或交易所接收时刻的直接观测。

## 时间口径与分解

使用原生monotonic时间；历史触发点通过同一次observe的当前点锚定，不能直接把官方策略elapsed与本地wall时间相减。
MATCHED是本地首次收到成交的时刻。交易日志原生venue撮合时间缺失，挂单等待和成交回报延迟无法进一步可靠拆开。
以下均值以22轮为分母，包含零次撤换的轮次；各阶段不重叠，严格加总到触发→首次MATCHED。

最后一笔MATCHED到CONFIRMED平均6.527秒；它不属于该轮已经成交之前的风险延迟，不能再加进本轮成交损失。

## 执行脱节对应的收益差额

固定每轮最终实际配对的数量Q=min(原始成交量,补仓成交量)，原始均价保持实际值。第一点是SL触发时同一篮子原始持仓的中点浮盈；首单点是实际Maker报价对应的配对收益目标；终点是实际补仓VWAP对应的已配对PnL。原始数量较小或补仓不足时，统一使用相同Q，避免把数量变化混成滑点。
该比较不含最小订单带来的额外方向尾仓结算；也不代表在信号价、首单价必然能成交。

| 路径触发时的中点浮盈 | -7.278712 |
| 系统识别时的中点浮盈 | -8.778712 |

## 撤换过程的证据

- 25次实际撤换，平均2.679秒，中位2.843秒。
- 22次具有明确canceled回执的零成交旧单，回执至下一POST仍平均2.564秒。3次POST被拒绝后也经历关闭核对。
- 25次采用的最终关闭帧中，positions最后完成19次，capital最后完成4次，time和trades各1次。这指可见公共页面中的最后完成者，不把未展示的订单详情或本地验证时间强行归入该页面。
- 明确撤销ACK之后，仍有40次针对同一旧单的重复DELETE。源代码会在每次写后推进证据水位，而close scope要求time/open_orders/trades/capital/positions从该水位之后重新读取。重复写与整账户刷新共同延长撤换通路；不能把全部时间解释成DELETE网络慢。
- 22次撤换均在历史快照中找到更早的窄范围证据：明确撤销ACK之后发起的订单详情=已撤销且size_matched=0、关联交易为空，同时完整订单页不再有该订单、完整交易页无该订单的maker leg。
  这些证据实际发布时刻，比下一POST平均早1.794秒，中位1.865秒，范围1.047–2.522秒。
- 上述22段剩余等待内，同一配对篮子的中点估值净恶化1.350000 USDC：11段恶化2.257273，6段改善0.907273，5段相同。这将可观测的等待与价格变化连接起来，但没有假设提前挂Maker就能成交。
- 重要反例：15:05第二轮SL，T108.326请求追价撤单，T108.575才首次观察到5股成交。不能把撤单请求、not found或空交易页单独当作无成交证明。该轮必须走完整成交核对。

## 关键案例

### 13:05：首单之前和首单之后都发生恶化

NO5@0.60；路径T64.536触发，系统T72.515识别。开仓订单T67.441才完成关闭，随后库存核对又等待约5.074秒；positions快照显示NO仓位到T71.532才可见，下一次循环T72.515进入REPAIR（此前审计已留存对应快照明细）。
T72.534首挂YES5@0.59，之后0.63→0.76→0.79，T87.016首次观察成交。从路径触发到成交22.480秒；触发浮盈基准−0.20、首单配对目标−0.95、实际配对−1.95。

### 15:10：识别及时，但TP撤换和SL追价迟迟未成交

YES5@0.30；路径T72.357触发，T72.362识别。撤销TP并完成关闭后，T75.439首挂NO5@0.71。SL随后0.77→0.85→0.85，T91.383成交。首单目标−0.05，实际−0.75；仅首单到成交就有0.70 USDC价差。并非重新计算SL信号本身耗时数秒。

### 15:30：很短的延迟也可能对应很大的价格变化

第一轮NO5@0.43，路径T100.628触发，T100.790识别，只有约162ms；同一篮子浮盈基准已从−0.10变成−0.725。T100.815首挂YES@0.73，再挂0.81，T106.478成交，实际−1.20。因此仅按秒数排优化优先级不够，必须同时衡量信号后价格移动与剩余敞口。

### 反例：等待并非总是恶化

12:35第一轮识别迟3.442秒，但中点基准由−0.575改善为−0.275，最终配对−0.20。15:15第二轮首挂NO@0.35，实际以0.13成交，配对收益从首单目标−0.70改善为+0.40；由于额外NO尾仓结算输掉，该轮完整PnL为+0.049。不能将所有等待都算作可避免亏损。

## 覆盖与边界

- 22轮覆盖本样本全部实际SL补仓，不按亏损与否筛选。7轮实际TP成交未混入SL执行延迟。
- 另有两轮是TP成交之后，反向尾仓再进入SL却未挂出SL单：12:30（NO5）、12:40（NO0.565714）。它们受尾仓/最小订单规则约束，已单列tail_only_sl_cases，不当成正常首轮SL成交样本，也没有隐去无单情形。
- 原始撮合时刻缺失；MATCHED→CONFIRMED不能当作尚未成交。
- 信号路径可能从历史补处理，部分点当时库存经济证明尚未就绪；不能假设触发时刻已有合法可执行数量。
- 已确认的是时间、证据和价格差；提前挂单的排队、成交量、后续NORMAL轮次和最终收益尚无可识别反事实。

## 在保持状态机规则不变下的执行改进方向

1. 优先研究零成交撤换的证据通路。对已明确撤销、详情匹配且size_matched=0、完整交易页一致的旧单，让下一笔REPAIR不必串行等待全账户positions/capital重新发布；仍保留session预算、官方资金依据、Delta预占、所有迟到成交及未知状态隔离。其他情况继续原有完整关闭流程。当前22次更早窄证据证明此方向可研究，尚不是生产准入验证。
2. 同时减少明确cancel ACK后的重复DELETE，避免无必要地移动最新写水位；不把ACK单独当完整无成交证明。
3. 另一个需要验证的执行候选：当前SL价格追价检查排在reconcile_owned_order之后。可研究先用本地盘口发起追价撤单，随后继续完整核对，重挂仍由经济数量与关闭证明约束；与已经提前执行的TP→SL模式撤单检查区分。本次缺少该检查全过程的BBO记录，尚未量化提前撤单能节约多少时间或收益。
4. 将开仓后SL路径跟踪与开仓关闭/库存核对解耦。先持续记录并准备SL意图，待经济数量得到证明即用最新盘口执行；不通过超时把MATCHED提升为CONFIRMED，不提前对未经证明的数量下单。
5. 用最新ask−tick持续跟踪仍是Maker约束下的执行选择，无法保证立刻成交。新增监控应分开记录路径触发、状态识别、取消请求、首次明确撤销、窄证据齐备、全证据齐备、实际POST、MATCHED、CONFIRMED，并记录这些时点的BBO和剩余敞口。
不改TP/SL门槛、不改状态转换，不把4.879675或1.35 USDC差额当作上线后的收益承诺。
