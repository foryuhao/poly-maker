# M1 独立开发测试

CA 长期实盘测试优先。M1 当前只用公开行情观察入口，不启动完整交易引擎：

```bash
.venv/bin/python -m polymaker.rdp_sm_m1_observe --config-dir config-m1
```

单次最多运行 360 秒，在 T240 前结束行情观察；若当前已过 T240，则等待下一场。
短时连通检查可加 `--max-seconds 20`。每 5 秒输出心跳，Ctrl-C 只关闭 M1。
只有显式启动连续运行器时才跨场继续；已完成的短测不会留下后台任务。

需要连续观察时，使用已改为独立入口的运行器：

```bash
.venv/bin/python ops/m1_observe_until_marker.py --config-dir config-m1
```

运行器在正常完成且存在通过独立原始深度复核的公开行情 `WOULD_POST` 后停止，
连续三次失败或达到日志额度也停止。检测器标记但复核失败时保留拒绝证据并继续下一场。
不要使用旧的 `polymaker rdp-sm-run --config-dir config-m1` 做并行观察：它会启动账户交易引擎。

## 隔离边界

- 复用 `SessionFeed`、`M1Signals`、`CAWriter` 的有界队列/线程生命周期和 5 美金报价数量计算。
  没有复制 RF／EX 检测实现，也不启动无关 BA 检测器。
- M1 写盘批量处理并保存 `events.jsonl.gz`，保留全部原始帧、拒绝记录和信号事实；
  省略与原始帧重复的成功逐档处理日志，省略数量单独记录。提交候选按 25ms 检查，避免每个行情消息重复计算。
- 直接读取 M1 TOML 的信号配置，不调用 `Config.load`，不读 `.env`，不创建私钥、账户、SDK 或执行客户端。
- 网络只有公共 market WebSocket、Gamma 市场查询及 CLOB `/time`、`/tick-size` GET；无账户轮询、POST、DELETE、签名、撤单或 Merge。
- 全部观察结果在 `research_outputs/m1_isolated/`：逐场配置、元数据、公共帧、信号和结果。不会打开 CA 的 DB、交易日志或账户锁。
- M1 自己的 `.public_observer.lock` 限制同时运行一个公开观察进程；原账户交易引擎的公共账户锁保留，不通过另设交易锁绕过保护。
- CLI 将进程 nice 降到至少 15，支持 ionice 的主机使用 idle I/O 类。行情队列沿用 2048 上限，观察写盘队列缩为 2048。
- 每秒检查文件与磁盘预算：单场事件文件达到 32 MiB、总观察目录达到 256 MiB、磁盘可用空间不足 256 MiB 时结束。检查间隔和有界队列排空可带来少量超出；不删除旧证据。

## 标记含义

公开观察使用当前 `cal-16` 配置、20ms 时序容差和 T15–T240 观察窗口；没有修改 CA 参数。
相对 cal-15，仅回补轮次由 750ms 调为 500ms，RF 仍要求两次独立稳定回补；其余门槛不变。
实盘入口仍是 T100–T240。RF／EX 需有效重叠，剩余时间至少覆盖 400ms 提交预算加 50ms 最低有效时间。
同一 RF 或同一 AP→EX 只标记一次；价格只用于队列定位、报价合法性及 5 美金数量换算。

这里的 `WOULD_POST` 明确带有 `scope=PUBLIC_SIGNAL_QUOTE_TIMING_ONLY` 和
`account_admission=NOT_CHECKED`，表示信号、报价和静态时效检查通过。
它不代表账户资金/库存准入、实测 POST 延迟或实盘成交已经验证，也不用于计算收益。
观察器不伪造持仓、成交、活动订单或占款，因此标记数量不受虚构的 20 美金账本限制。
实际交易引擎仍保持单张活动订单、每笔 5 美金及累计支出加占款不超过 20 美金的限制。
