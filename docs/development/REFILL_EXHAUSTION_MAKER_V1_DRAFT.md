# M1：反复承接与卖压衰竭后的双边持续 Maker 买入

日期：2026-11-01，北京时间。

最新阶段：用户要求先观察信号并记录 WOULD_POST，不发送真实 POST，源时间容差参照 CA。
当前 `config-m1` 已切观察模式；变更口径和运行证据见
[M1_SIGNAL_TIMING_AUDIT_20261101.md](M1_SIGNAL_TIMING_AUDIT_20261101.md)。以下原始交易设计保留供对照。

状态：开发规格与实现核对。交易规则已由用户确定，代码及独立 config-m1 配置已实现，已完成报告列明的离线验证；未启动实盘或提交真实订单。实现入口、预算依据及完整验证记录见 M1_REFILL_EXHAUSTION_IMPLEMENTATION.md。

本文 M1 是交易逻辑名称，不是仓库既有的 M1 Safe Session 开发阶段。实现标识建议使用 refill_exhaustion_maker_v1，避免混淆。

## 1. 已经确定的策略约束

- 只实现 M1，不接入 T2 或其他主动买入逻辑。
- 同一二元市场的 YES、NO 分别检测自身 RF_BID + EX_SELL；哪边满足，就产生哪边的买入候选。
- Buy Only、Maker Only。每次原始委托以 5 美金为预算，按挂单价换算 shares，不固定 5 shares。
- 单 session 累计买入支出加未成交/未决委托占款不超过 20 美金。双边库存不抵扣额度，不采用组合最坏结算亏损 20 美金的口径。
- 价格只用于档位身份、成交与队列匹配、合法委托、金额到数量的换算及成本账本；价格水平、涨跌、两边价格排名、持仓盈亏和配对成本不生成方向或买入信号。
- 库存、资金和未决订单只影响准入，不产生另一边的买入理由，不设目标净敞口，不自动补足或配平。
- 每个 session 可以重复交易，但每一笔必须由新的有效机会授权。
- 交易窗口为市场开始后的 [T100,T240)：T100 可以提交，T240 起禁止新提交并关闭未成交委托。预热和行情记录可以更早开始，不回放过期机会。
- T240 起沿用现有 Merge：先撤单、核对所有未决成交，再合并本 session 已确认的双边份数；剩余残仓等待结算。信号失效不授权反向补买。
- 采用新的单引擎状态机，不沿用按库存切换 NORMAL/REPAIR 的架构；此项已经确定，不作为待确认事项。
- 单场完整成本后结算结果记入连续市场批次，观察 50、100 场；这些场数不是盈利有效性的自动证明。

## 2. M1 机会的含义

RF_BID 表示同一 Bid 档位经多轮冲击后稳定回补；EX_SELL 表示已经确认过的主动卖出，其后强度在完整观察中显著减弱。

两者同时有效时，允许挂 Maker 接受后续卖盘。后续主动 SELL 本身是预期成交来源，不能因出现一笔 SELL 就判定机会失效。需要区分卖压余波、卖方持续进攻恢复，以及承接失效。

不要求先出现 CA 或主动 BUY。不把没有成交当作失败，不把没有消息当作卖压衰竭。

## 3. 最小检测范围

沿用 docs/research/ORDERBOOK_SIGNAL_TOOLBOX_V1_20261101.md 与同版本 parameters.json 的研究定义，先实现以下部分：

1. 公共事件顺序、快照/增量、数据有效性 G、连接 generation、定时器和可得时间。
2. AP 方向检测：完整 750ms 窗口、绝对/深度归一化门槛、80% 占比、条目和子窗口持续性限制。AP_SELL 提供 EX_SELL 参照；AP_BUY 仅用于反向进攻形成后的 EX 结束，不授权 Taker 或额外买入。
3. Bid 冲击回补轮次：固定 750ms、成交及损失双门槛、净恢复、100ms 保留、完整封口。
4. RF_BID：三个不重叠的稳定成功轮次，中位封口恢复率至少 70%。
5. EX_SELL：以确认 AP_SELL 为参照，之后三个 250ms 子窗口均有有效盘口更新覆盖，并满足衰竭门槛。

第一版不需要实现全部 AA_ASK、LW、DF。先前讨论中的 LW_BID/DF_BID 属于可扩展的反证，不应在未实现时声称已提供这些撤单保护。

RF 下一轮完整观察后不再稳定成功，以及 EX 观察到卖压恢复，提供首版基础撤单原因。首版不增加尚未定义的轮次中途提前撤单规则。

## 4. 机会与订单的生命周期

### 4.1 生成

- 同 token、同 generation、anchor 可比、G 有效，RF_BID 和 EX_SELL 当前均为有效 CONFIRMED。
- 历史 AP_SELL 是 EX 的参照，不要求参照 AP 此时仍有效。
- 生成唯一 opportunity_id，绑定 rf_id、ex_id、参照 ap_id、anchor、全部可得时间和参数版本。
- 允许 RF 和 EX 的证据共享，但记录共享关系；不能据此增加独立样本数。
- 已确定使用严格信号重叠：机会截止 = min(RF 截止, EX 截止, session 停止开仓时点)。不因轮询、新事件或订单等待延长。

### 4.2 准备与提交

- 每笔目标预算 B=5 美金。Maker 无额外收费时，原始数量 q=floor_to_legal_precision(B/p)，p 为 RF 的挂单档位。按合法精度向下取整，确保 p*q 不超过 5；如有实际适用费用，费用一并计入该笔预算。
- 数量换算在买入方向和档位确定之后进行；不把价格高低作为选边、时机或仓位倾斜依据。
- 检查合法数量/最小金额、每单数量上限、账户可用资金及全部未决委托占款。无法合法表达 5 美金预算时跳过，不静默放大、拆单或缩成剩余额度的小单。
- 新委托前要求 session 剩余额度和账户可用资金足以覆盖完整 5 美金预算。已确认支出与挂单/UNKNOWN 最大可能支出计入 20 美金上限；同一笔成交与剩余委托不重复计入。
- 固定在 RF 所观察的有效 Bid 档位，post-only BUY；不追随新 Bid 自动改价，也不转 Taker。
- 签名和原生 POST 前重新检查机会有效性、原截止时间、账户和网络准入。
- 在原生 POST 开始时消费 opportunity_id，包含结果 UNKNOWN 的情况，避免同一机会重复下单。签名或准入失败且尚未开始原生 POST 不伪造一次提交；再次评估也必须仍满足原始时限。

### 4.3 挂单期间

允许零散 SELL 与当轮暂时深度损失；回补需要时间，不能把每次受击初始的低恢复率直接当作防守失败。

基础撤单条件：

- EX 结束为卖压恢复或反向 AP_BUY 形成；
- RF 因下一轮封口不满足稳定成功而结束；
- 任一所需信号到期；
- anchor、tick、generation 变化或数据有效性丢失；
- session 停止开仓时点到达；
- 账户、未决订单或资金证据不再允许维持订单。

撤单请求不是不可成交证明。迟到/部分成交全部进入真实库存与资金账本，不能事后删除。

### 4.4 关闭与再次交易

- 订单成交完毕或撤销并核对完成，释放未成交金额的预留。
- 部分成交的实际 shares 和金额全部保留；订单关闭后不自动补足该笔未用的 5 美金预算。
- 下一笔等待新的独立 RF 证据组和新的 AP→EX 过程，避免反复交易同一衰竭事件。每次独立机会最多提交一笔 5 美金预算的委托；此规则已由用户确定。
- 已消费、失效或过期的机会不复活；未决订单核对结束后，也不能回放等待期间已经过期的机会。

## 5. 库存与并发

- 单边残仓不会切换成旧 REPAIR，也不会阻止所有后续同侧机会。已经确定的额度是 20 美金累计资金占用，不继承旧 delta_limit=5，也不自动增加额外 shares 上限。
- 已确定整个 session 最多一张活动 Maker。订单关闭并完成核对后，才能处理下一张；YES、NO 始终都可被检测和选择，不因已有残仓切换引擎。
- 两边均有信号不沿用 CA 的双边冲突拒绝规则；调度时按实际机会可得顺序处理，另一个候选随后必须重新检查有效性，不排队保留过期机会。
- 20 美金额度检查必须覆盖所有未决订单可能产生的最大支出。YES、NO 委托分别占款，不能把方向相反当成金额抵消，也不能预支尚未发生的 Merge 回款。
- 结果 UNKNOWN 或账户归因不清时暂停新的提交，先核对既有订单；这不产生反向订单。
- 资金占用按累计实际买入成本、费用与未成交/未决委托最大可能支出计算；不继承旧 NORMAL 为未来修复额外预留每份 1 单位资金的口径。
- 未成交额度只有在订单关闭与成交核对完成后才能释放。双边库存的确定结算价值不释放交易额度，账面配平不当作现金。
- T240 后完成已确认双边库存的 Merge，真实现金回流单独记账，但本 session 不再恢复买入；已实现 Merge 盈亏与残仓最终结算盈亏一并归因。

### 5.1 新单引擎状态机

建议主状态为 PREPARING → TRADING → DRAINING → MERGING → HOLD_SETTLEMENT → DONE。

- PREPARING：身份、账户、盘口快照及检测器准备；T100 前记录和预热，不下单。
- TRADING：仅在 [T100,T240) 接受双边独立 M1 机会；已有任何方向残仓都不切换交易引擎。
- DRAINING：T240 或提前终止时关闭挂单、核对部分/迟到成交及 UNKNOWN；不能直接将撤单 ACK 当成已关闭。
- MERGING：T240 起且关闭证据满足时，调用既有 merge_confirmed_pairs 及确认核对机制。T240 是最早启动边界，不保证链上交易恰好该秒完成。
- HOLD_SETTLEMENT：保留单边残仓及未能合并的库存，等待决议/赎回；缺少 Merge 条件或暂时失败不产生额外 BUY。
- DONE：结算/赎回现金流和账本已核对。交易进程可以先结束，但持久化结算跟踪不能把待结算状态提前记为 DONE。

异常阻塞、恢复与未决写操作是执行状态，不根据 Delta 的正负或大小划分开仓/平仓引擎。Merge 的重试、UNKNOWN 处理及账户核对沿用现有机制。

## 6. 现有代码的两项明确不兼容

### 6.1 旧状态机不支持自由累积残仓

src/polymaker/rdp_sm_lifecycle.py 的 NORMAL 会因 repair_episode 或 repair_required 阻止继续提交。src/polymaker/rdp_sm_quotes.py 也会根据库存转入 REBALANCE，并按净敞口规划另一边数量。

因此新增 M1 单引擎状态机与持续买入控制器，复用身份、签名、订单跟踪、成交真实性、账户核对、Merge 和账本；不通过删除所有旧策略限制来硬塞入 NORMAL/REPAIR。架构选择已由用户确定。

M1 不调用 higher_bid、Favorite、目标配平、价格 TP/SL、基于盈亏的冷却或 CA TP 路径。

### 6.2 旧下单预算会全部拒绝严格 M1

当前 config/config.toml 的 BA/CA 网络预算为 POST floor 750ms + 最少存活 500ms。entry_admission 要求剩余时间至少为两者之和，即至少 1,250ms，实测 POST 更慢时还会增加。

研究定义中 RF 的确认后寿命为 1,000ms，EX 为 750ms；严格重叠的 M1 剩余寿命最多为 750ms，实际通常更短。因此直接沿用旧准入会使所有机会被拒绝。

第一阶段保留已确定的信号定义，复用现有网络计时采集实际处理、准备、POST、确认活动及 DELETE 时延，适配 M1 执行准入。无法覆盖实际延迟的机会跳过，不为了成交而放宽信号寿命或忽略网络条件。具体网络预算应有实测依据，本规格不虚构数值。

若选择独立、更长的交易机会寿命，则属于策略语义变更：RF/EX 只能作为历史触发，必须另定义整个等待期的实时反证，不能仍宣称两信号始终有效。

## 7. 数据采集、日志与自有订单

- 在 SessionFeed 公共流过滤/合并前采集原始帧，以及逐子事件的接收、处理、接受/拒绝原因。
- 保存完整快照、绝对档位更新、方向成交、乱序/重复歧义、GAP、generation 与定时器结果。
- 定时器只能关闭观察窗口，不能代替 EX 所需的市场更新证据。
- 不能照搬 CA/BA 对小乱序消息丢弃后仍保留信号的方式，来证明 AP/EX 的完整成交量。
- 自有挂单、撤单、成交必须保留生命周期，并核对其对公共深度的污染。只有能可靠对齐的自身数量才可剔除；不拿 POST/DELETE 请求时间代替公共盘口已变化的证明。
- 不可消除的自有污染明确标记，不能进入主要证据样本或被用来刷新机会。必须报告由此造成的覆盖率损失。
- 日志包含机会、订单、成交、库存、成本、错过原因及参数/源码版本；保存信号原始截止时间。
- 信号失效后或撤单途中成交仍保留收益归因。成交后回补只能作为事后结果，不能反过来筛除亏损成交。
- 结算跟踪应跨 session 生命周期保留；市场尚未决议时标待结算，不将停止交易时间当作已结算。

### 8.1 复用时不能继承的旧策略假设

- rdp_sm_sizing.py 的 normal_sizes 会按库存差增加数量；make_quotes 会转 REBALANCE。这些不能作为 M1 选边/数量规划器。
- 旧 NORMAL 的 sigma 就绪、Favorite、higher_bid、TP/SL 和盈亏冷却不能作为 M1 的附加交易前提；只保留真正的身份、数据、金额、网络与订单事实约束。
- maker_buy_size 按缺口和最小份数向上取整。M1 应增加一个小的金额换算函数，复用 SDK 网格及合法性检查，向下取整且核对签名后的真实支付金额不超过 5 美金；不重新实现订单构建器。
- RDPSMConfig.max_order_size 默认 15 shares，SMWindowExecutor._validate 会执行它。5 美金在 0.25 档位需要 20 shares，原样继承会被拒绝。M1 使用自身金额上限与真实场所技术限制，不继承旧策略的 15 shares 上限；不把配置遗漏变成隐含价格筛选。
- delta_candidate_allowed 沿用 repair.delta_limit=5，会拒绝独立的同侧新增机会。M1 必须改用已确定的金额准入，不继承这个旧方向约束。
- 模式注册不止修改一个枚举：session_capital_limit、行情初始化、缓存核对、原生提交和配置相容性分支均需覆盖新模式，避免回退到旧模式默认逻辑。
- BatchLifecycle 的 busy、全 session 关闭证明和逐窗口执行可以作为首版复用基础，但 prepare/guard/send 中的 REPAIR、TP、冷却和每份 1 美金资金预留必须通过公共钩子隔离；不能整段照搬，也不复制整套 lifecycle。
- 公共研究记录框架存在，不等于当前 SessionFeed 已经接上全量记录。ResearchEvent schema 也不直接接受任意 raw-frame 类型；需补适配/schema 与缺口记录。不能只复用最多五档的 StateSnapshot 代替原始事件。

## 9. 开发与验证顺序

1. 补齐独立事件记录和回放输入，保证新增研究记录不会阻塞交易；溢出必须明确标 GAP。
2. 实现 AP_SELL、Bid 轮次/RF、EX_SELL 的纯检测器与独立定时器，先验证不下单的观察模式。
3. 采集真实覆盖率、RF/EX 重叠时长与执行时延，检查严格 M1 是否存在可执行窗口。
4. 实现 opportunity_id、消费、每笔 5 美金预算换算、session 20 美金准入和新单引擎状态机；交易窗口固定为 [T100,T240)。
5. 接入现有 post-only、成交与 UNKNOWN 核对原语，保持 M1 默认关闭，明确选择后才启用。
6. 离线集成验证通过后，输出每次机会到成交的证据链与结算账本。启动或替换运行中的实盘进程不属于本草案整理动作。

必要验证场景：

- 单笔大 SELL 不形成 AP；普通安静/断流不形成 EX；闪烁补单不刷出 RF。
- RF 与 EX 没有有效重叠时不交易；过期候选不因稍后处理而补发。
- 后续零散 SELL 不无条件撤单；持续卖压恢复、RF 封口失败和数据失效会结束挂单。
- 部分成交、UNKNOWN、取消途中成交、原截止时间在签名/POST 前耗尽。
- 同一机会不重复开仓，新机会允许在已有同侧残仓下再提交 5 美金预算；不同档位的 shares 正确换算、精度不超支、部分成交不自动补预算。
- 双边信号同时成立时有序选择；整个 session 最多一张活动单，未决订单核对前不提交下一张，过期机会不回放。
- 旧价格选边、TP/SL、REPAIR、盈亏冷却不被误调用，旧策略行为保持兼容。
- T100 前及 T240 起不提交 BUY；准备/签名在窗口内但原生 POST 时已到 T240 也应拒绝。
- 20 美金额度覆盖成交与全部未决委托；双边库存不抵扣额度，同一成交不双计。
- T240 截止后的订单核对、沿用 Merge、真实残仓和最终结算净收益一致；Merge 回款不重新启动买入。

## 10. 已确定规则与工程验证项

用户已确定：

- 新单引擎状态机，取消旧 NORMAL/REPAIR 分工。
- 每笔目标预算 5 美金，非固定 5 shares。
- 单 session 累计实际买入支出与未成交/未决占款合计不超过 20 美金；不允许用双边库存抵扣该额度。
- 交易窗口 [T100,T240)，T240 撤销未成交单并沿用现有 Merge。
- 严格遵守 RF/EX 有效重叠，任一到期即撤单，延迟不足就跳过，不另设更长寿命。
- 同一过程最多一次提交；再买必须是新的独立 RF 与 AP→EX，部分成交不补足。
- 整个 session 最多一张活动挂单，关闭核对完成后再处理新的有效机会。

首版撤单范围沿用 RF/EX 自身生命周期、档位/数据失效与时段边界，不额外增加尚未定义的 LW/DF 或轮次中途规则。

两个方向同时可用时，按本地实际机会可得时间先到先处理；完全同一处理时点使用预先固定、跨 session 轮换的方向优先规则。不按价格、浮盈或配平需要排序；单张订单关闭核对后，下一候选重新判断有效性。

目前没有其他必须由用户补充的首版交易规则。后续待完成的是工程验证：完整输入覆盖、自有订单污染、实际 POST/DELETE 时延、签名金额与精度、全 session 核对和 Merge 兼容性。预算应来自实际写操作证据，不拿公开 GET 探针代替；证据不足或准入不满足时不下单，也不通过延长信号来凑成交。
