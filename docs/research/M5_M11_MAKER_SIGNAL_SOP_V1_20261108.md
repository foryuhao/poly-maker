# M5 到 M11 Maker 盘口信号 SOP

日期：2026-11-08，北京时间。规格版本：`m5-m11-maker-sop-v1.0`。状态：供新框架实现和并行测试的冻结研究规格，尚未实现或验证收益。机器可读参数见 [参数表](M5_M11_MAKER_SIGNAL_SOP_V1_20261108.parameters.json)。参数表不是现有交易程序能够直接加载的配置。

研究目标：信号成立后，在规定的有效等待条件下以 Maker 买入选定结果；这些成交在相同成交价和相同剩余结算时间下，比普通 Maker 成交更常最终胜出，同时保留实际成交率和全部成交损益。

Up 和 Down 分别作为待买入 token 运行同一套规则。`AP_BUY` 指主动买入该 token，`AP_SELL` 指主动卖出该 token。触发只使用公开盘口、成交和因果时序。价格用于识别档位、匹配成交、验证合法报价；执行金额计算和结果分组可以使用价格。BTC 外部价格、价格涨跌幅、tick 推进、未来结算和持仓盈亏不进入信号。

## 1 首版冻结选择

AP 和 RF 的数值参数沿用当前 cal-16 / M2 候选研究：AP 750ms，回补轮次 500ms，RF 两轮、确认后 8 秒。LW 沿用工具箱研究定义；EX_BUY 需要新增对称检测器。M8 使用严格两轮参考加两轮减弱的 DF，轮长改用统一的 500ms；不能直接换成 M4 frequency-v2 的宽松 DF。

以下为本次新冻结的研究选择，不是已经验证的最优参数：M5 的恢复比较，M7 的严格阶段顺序，M8 的修复要求，M9 的新 RF 复验，M10 的三轮递减，M11 的独立留存检查，以及统一执行门槛。任一门槛、寿命、证据顺序或失效条件变化均升级策略版本。

| 策略 | 首版确认表达 | 确认后的原始期限 |
| --- | --- | --- |
| M5 强压稳接 | 当前 AP_SELL 与两轮可比、恢复稳定的 RF_BID 重叠 | `min(AP.deadline, RF.deadline)`，最多 750ms |
| M6 撤供留托 | 当前 LW_ASK 与 RF_BID 重叠 | `min(LW.deadline, RF.deadline)`，最多 750ms |
| M7 歇后再攻 | AP_BUY1 → EX_BUY1 → 新 RF_BID → 新 AP_BUY2 | `min(AP2.deadline, RF.deadline, AP1.confirmed+20s)`，最多 750ms |
| M8 承接修复 | 严格 DF_BID → 可比冲击下的新 RF_BID 修复 | 新 RF 的原始期限，最多 8 秒 |
| M9 余波复验 | M1 成立 → 在其仍有效时启动新检验 → 两轮新 RF 复验成功 | `min(新RF.deadline, 原AP_SELL.confirmed+20s)`，最多 8 秒 |
| M10 回流递减 | AP_BUY → 三轮新卖盘回流递减且承接稳定 | `min(RF_R1_R2.deadline, AP.confirmed+20s)`；第三轮不续期，紧凑形成时约剩 7.5 秒 |
| M11 多档续托 | 母信号成立 → 下方两档净补单留存 500ms 检查通过 | 母信号原始期限；不新增寿命 |

这些期限是配置允许引用证据的上限，不是预测能力的测量结果，也不是固定挂单时长。实际执行还受提前失效、提交预算和 T240 截止约束。

## 2 共同证据和时间规则

### 2.1 因果时间与质量

使用本地接收 monotonic 时间和原始输入顺序；同时保存事件发生时间与策略实际可得时间。`confirmed_available_at` 是最后一份必需证据处理完成的时刻，不能倒填为窗口结束时刻。事件窗口为 `[start,end)`，边界事件归下一窗口。当前事实仅在 `confirmed_available_at <= now < deadline` 有效；阶段标注的截止时刻到达即不再接受新的确认。时间戳相同时按输入序号和处理可得序号排序，新阶段不能复用使前一阶段确认的同一事件。

AP、EX、500ms 轮次和 M11 留存窗口须完整封口；允许封口后最多 50ms 汇总处理，但不能把这 50ms 中的新行情算进已结束窗口。数据水位不足或处理超过预算，记 `UNAVAILABLE`。100ms 保持条件包含在各自形成窗口内，不另加到轮长之后。

质量条件 G 全程成立：同一连接 generation；有完整有效快照；无已知丢帧、队列溢出、解析缺口；盘口非交叉、tick 已验证；本地盘口年龄不超过 200ms；所需事件源年龄不超过 500ms，最多容忍 2ms 的源时间超前。20ms 乱序容差不允许把不可还原的成交丢掉后继续声称流量完整。

每个 250ms 流量区间须有该 token 的有效公开深度或 BBO 更新，且采集链路完整。PONG 和另一 token 的更新不构成该区间的覆盖证明。零成交只有在覆盖已证实时才是零，否则是 `UNKNOWN`。

主输入复用当前互补成交归一化约定，但适配器必须保存原始事件身份、直接/镜像来源和映射版本。同一经济事件映射到同一 token 后只计一次。没有身份依据时，不把互补盘口当成两次独立确认；无法消除的成交歧义隔离为 `UNAVAILABLE`。`price_change.side` 是挂单侧，不能当成主动成交方向。

信号只读公共行情和当时可得反馈，不能读模拟器未来 timer、未来成交或未来撤单结果。模拟自有单不反写公共证据；真实自有挂单无法可靠剥离时标记 `SELF_CONTAMINATED`，该证据不进入主信号样本。

### 2.2 档位与轮次

Bid 锚点 `p0` 在阶段第一次合格触及事件前冻结。沿用当前可见锚点口径：只要该价位仍可见且数量大于零，不因 best bid 改变而追价或重建锚点；该价位消失、清空后重建、tick 改变或 generation 改变，结束旧证据。恢复到原价格也不复活旧队列。

每个 Bid 轮次由主动 SELL 击打冻结档位开始，期限固定为 500ms。成交量只累计能够对应这个档位的 SELL。窗口中的深度变化按原始顺序处理，不能把先到的深度下降用后来成交倒排成成功承接。

```text
Q0 = 轮次开始前该档位的可见数量
Qlow = 轮次内观察到的最低数量
D = Q0 - Qlow
V = 轮次内打向该档位的 SELL 数量
r = min(1, max(0, Qcurrent - Qlow) / D)   # D > 0
u = V / Q0
d = D / Q0
m = max(0.5份, 0.0001 × Q0)
```

Q0 或 AP 的 Dopp 不大于零时不可用。合格冲击须同时有 `V >= m`、`D >= m`。恢复达到 50% 后开启保持计时，连续 100ms 不低于 40% 才取得保持证明；新 trough 重置证明，恢复低于 20% 撤销已有证明。稳定轮次须完整封口、仍有保持证明、`r_end >= 50%`。

RF 由两个连续的合格稳定轮次形成，第一轮起点至第二轮确认可得不超过 15 秒，恢复率中位数至少 50%。两轮不重叠，确认后期限为 `confirmed+8s`。下一合格轮次不稳定、锚点丢失或 G 失效，RF 结束。

完整但不合格的小噪声轮次不充当成功或失败，也不计入规定轮数，但消耗阶段的绝对时间预算。遇到合格但失败、不符合策略要求或不可比的轮次，不得跳过它去拼接后面的有利轮次。轮次不重叠只表示事件分配独立，不表示不同交易者或统计独立。

### 2.3 AP 与 EX

AP 在方向首笔合格成交时冻结方向和对手侧最多三档总深度 `Dopp`。完整 750ms 窗口内，方向量 `Vs >= max(1份,0.0001×Dopp)`，方向成交占比至少 65%，至少两条成交记录，三个 250ms 子窗口至少两个有同向成交且最后一段有成交，最大单条量不超过方向总量的 95%。AP 可以使用当前适配器认可的非最优档成交，不要求价格移动。

AP 确认后固定有效 750ms。每 250ms 检查最近完整 750ms：方向占比低于 60%、方向量低于冻结最低量的一半，或最近 250ms 无同向成交，均结束；反向 AP 确认亦结束旧 AP。新 AP 具有新身份，不延长旧候选。

EX 从对应 AP 实际确认可得时开始再观察 750ms。三个 250ms 子窗口的同方向量各不超过 AP 参照总量的 `1/6`，总量不超过其 25%，G 完整，才确认。EX 有效 750ms；最近完整 750ms 同方向量恢复到参照量的 50% 或以上即结束。反向 AP 确认结束当前 EX 或其形成观察，历史事实仍保留。EX_BUY 镜像 EX_SELL 的方向，数值不变；不能用“买盘刚好没有成交”替代缺失的 AP 参照。

### 2.4 历史阶段与当前条件

历史事实只证明某个阶段曾发生；其当前 TTL 到期不删除历史。是否允许后续引用、可引用多久，由每个 SOP 的阶段截止规定。需要“当前同时成立”的条件则取各自剩余寿命的交集。

策略使用阶段局部观察器，键至少包含 `(strategy_version, market, token, anchor, generation, campaign)`。一个策略清空旧轮次不能清空另一个策略的状态。跨策略允许引用同一证据，但记录共享 ID；同一策略新阶段必须使用阶段门槛之后的新事件，不把旧轮次改名为新复验。

同一策略的 campaign 在存续期间不并行堆叠同锚点的同类根证据。当前必需事实被替代时结束旧候选，不能替换依赖后续期；新根开启新 campaign。历史引用不受这一条当前事实替代规则影响。新候选不能复用该策略已经消耗的阶段轮次。信号层记录全部合法机会，执行层另做次数和预算限制。

## 3 M5 强压稳接

策略版本：`m5-pressure-supported-v1`。

**语意：**方向性卖压仍在发生，同档位经历可比冲击后持续恢复，等待后续 SELL 以 Maker 成交。“强压”首版以 AP_SELL 达标表示，额外强弱保留实际归一化量分层，不暗加另一个阈值。

1. 收集同锚点两轮新的稳定 Bid 轮次 R1、R2，形成 RF。
2. 两轮 `u2/u1`、`d2/d1` 均在 `[0.5,2.0]`，且 `r2 >= 0.8×r1`。两个分母均须有效且大于零。
3. RF 确认时或之后，其有效期内出现当前有效的 AP_SELL；该 AP 的证据区间须与 R2 的证据区间有正长度重叠，避免用很久以前的 RF 配一个完全无关的新卖压。
4. 两者第一次同时满足时确认。价格锚定 RF 的 p0，期限取 `min(RF.deadline,AP_SELL.deadline)`。
5. 任一必需事实到期、AP 减弱或反向、RF 失败/被替代、锚点丢失、G 失效，立即结束并撤未成交余单。

后续成功补单不续期；本候选只引用确认时冻结的 AP 和 RF。成交表示在卖压仍可观测且承接尚未被否定时承接卖单，不预设最终胜出。

## 4 M6 撤供留托

策略版本：`m6-withdrawal-supported-v1`。

**语意：**同 token 的 Ask 出现无法由已知成交解释的可见供给收缩，Bid 仍有反复承接。

1. RF_BID 可以先存在，也可以与 LW 形成过程并行，不要求 LW 后再等两轮 RF。
2. 第一次 Ask 深度下降时冻结最多三个可见 Ask 档位集合 P、原最优 Ask 档和总量 Q0；完整盘口确实不足三档时使用实际 K，截断数据不允许这样降级。
3. 对固定集合计算 `loss=max(Q0-Q(P,t),0)`。将本地接收区间 `[t0-500ms,t]` 内可对齐、击打 P 的 BUY 量记为 `Vexec`，`L=max(loss-Vexec,0)`。前置 500ms 是历史对齐缓冲，不增加未来形成等待。
4. `loss/Q0>=30%`、`L/Q0>=20%`、`L/loss>=50%` 同时保持 100ms，且保持在 t0+750ms 之前完成，确认 LW。零分母不达标；时序不明记不可用。
5. 当前 LW 与 RF 均有效时确认 M6；p0 为 RF 锚点，期限取二者较短值。
6. `L/Q0<10%`、`L/loss<25%`、loss 归零、原 Ask 基准档丢失、RF 结束或 G 失效，立即结束。固定 P 不随 top K 排名变化而换档。

LW 只输出“疑似净撤退”，不输出确定撤单、隐藏订单或交易者意图。只看到挂单减少、缺少可靠成交对齐时不得确认。

## 5 M7 歇后再攻

策略版本：`m7-pause-refill-reattack-v1`。首版严格串行，不把 EX 观察与新 RF 形成重叠。

1. 确认 AP_BUY1，冻结根身份及历史截止 `AP1.confirmed+20s`。
2. 只用 AP1 确认之后的完整 750ms 观察确认 EX_BUY1。
3. 从 EX1 确认之后的新 SELL 开始，两轮新稳定 Bid 轮次形成 RF；旧 RF 和 EX 确认前开始的轮次不能使用。
4. 若新 AP_BUY 在 RF 确认前已经成立，当前 campaign 结束为 `EARLY_REATTACK`，不能把它留到后面冒充第二次进攻。
5. RF 确认后开始新的 AP_BUY2 观察。AP2 的全部证据必须晚于 RF 确认，不能复用 AP1 或暂停期的 BUY。AP2 确认时 RF 仍有效，且未超过根历史截止，确认 M7。
6. p0 为新 RF 的锚点；期限为 `min(AP2.deadline,RF.deadline,AP1.confirmed+20s)`。
7. 当前 AP2 减弱、反向或被替代，RF 结束，锚点丢失或 G 失效，立即结束。AP1、EX1 仅为历史，不要求再次进攻时 EX1 仍然活跃。

阶段之间无空档时形成最快约 3.25 秒，最终候选有效期最多 750ms。记录排不到单与进攻结束后才成交的比例，不能用 AP2 的主动 BUY 当作自己的 Maker BUY 成交。

## 6 M8 承接修复

策略版本：`m8-strict-damage-repair-v1`。

1. 同一 Bid 锚点连续两个合格稳定参考轮次，第一轮起点至第二轮确认不超过 5 秒，`median(r_ref)>=70%`。冻结恢复率、`u_ref`、`d_ref` 的中位数。
2. 参考确认后 5 秒内，接下来的两个合格轮次都须与参考可比：u 和 d 相对参考的比值均在 `[0.5,2.0]`；各轮 `r<=30%` 且 `r<=0.5×r_ref`。第二轮封口后确认严格 DF。任一合格轮次不符合即结束该 DF 候选。
3. DF 当前状态寿命为 1 秒；后续稳定轮恢复至少 70% 时亦结束。M8 保存已确认的 DF 历史，进入独立修复阶段，不要求“衰退”和“修复”同时为当前状态。
4. DF 确认后，接下来的两个合格新轮次构成修复 RF。两个修复轮次分别与两轮弱恢复轮次的 u、d 中位数比较，比例均须在 `[0.5,2.0]`；每轮都稳定，且 `r>=max(50%,0.8×原r_ref)`。
5. 修复 RF 必须在 `DF.confirmed+5s` 之前确认；超时或出现合格但不可比/修复不足轮次，结束该 campaign。不能跳过第一次修复失败等更好样本。
6. 新 RF 确认时确认 M8，p0 为同一修复锚点，原始期限为 `RF.confirmed+8s`。DF 的 5 秒修复截止只限制形成阶段，不在确认后继续当作当前 DF 期限。
7. 等待成交时，新合格冲击若不稳定，或恢复低于冻结修复门槛，结束 M8；锚点丢失、RF 被替代、G 失效亦结束。后续更好恢复不续期。

首版要求经历真实受击后的修复；只有补单、没有新合格 SELL 检验不成立。严格序列最快约 3 秒。

## 7 M9 余波复验

策略版本：`m9-fresh-rf-retest-v1`。这是独立的“新 RF 复验”版本，不是给原 M1 的 EX 续期。

1. M1 的 RF 与 EX_SELL 当前同时有效时，记录 M1 种子、原 AP_SELL、原 RF、原 EX、p0 和确认时间。种子形成沿用当前 M1：RF 与 AP→EX 可以重叠；最早组合证据至组合确认不超过 20 秒。
2. 在该 M1 种子仍有效时，等待确认之后的第一笔新 SELL 击打 p0，启动复验。若种子在第一笔新 SELL 前结束，campaign 直接结束。之前已经开始的轮次不能算复验。
3. 从这笔 SELL 开始，接下来的两个合格轮次须形成全新的 RF；所有轮次证据晚于 M1 确认，且与原 RF 轮次不重叠。新 RF 须在 `M1.confirmed+5s` 之前确认。
4. 复验开始后到候选结束，持续检查最近完整 750ms 的同 token SELL 总量；达到原 AP_SELL 参照量的 50% 或以上，立即结束为 `SELL_PRESSURE_RESUMED`。此检查沿用原 AP 的流量口径，并包含保守处理的未对齐同向量；G 必须覆盖窗口。复验启动时即使用已有的完整历史窗口检查，此后每个成交事件和 timer 都复核，不另等一个新 750ms 才开始检查。
5. 低于原参照一半的弱 SELL 即使触发了低门槛的新 AP_SELL，也不单独作为失败；真正限制的是相对原进攻的压力恢复，避免把所有新检验都误判为新一轮强进攻。
6. 新 RF 成立且余波条件仍成立时确认 M9。期限为 `min(新RF.confirmed+8s,原AP_SELL.confirmed+20s)`，p0 不变。
7. 新 RF 失败/被替代、余波条件失效、锚点丢失或 G 失效，立即结束。旧 EX 在复验启动后因固定 TTL 到期，不单独取消这个新阶段；它因卖压恢复失效时，当前余波检查也必须相应结束。

两个新轮次各须真实受击并稳定恢复；小噪声或没有成交的安静窗口不能替代。连续无空档时，从原 M1 最早证据到 M9 约需至少 2.5 秒；确认后最多 8 秒来自新 RF，而不是旧 EX。

## 8 M10 回流递减

策略版本：`m10-three-return-decay-v1`。

1. AP_BUY 确认时冻结历史参照，截止为 `AP.confirmed+20s`。清空本 campaign 内所有确认前的承接轮次。
2. AP 确认之后，同一 p0 的前三个合格新 SELL 回流轮次依次记为 R1、R2、R3。每轮 500ms；R1 起点至 R3 确认不超过 15 秒，R3 确认还须早于 AP 历史截止。
3. 三轮全部稳定。对 i=2、3，分别要求 `Vi<=0.8×V(i-1)`、`ui<=0.8×u(i-1)`、`ri>=0.8×r(i-1)`，并始终满足单轮 `ri>=50%`。总量和归一化压力必须同时递减，不能仅靠基准深度变化制造递减。
4. R1、R2 正常生成 RF12；R3 只确认递减结构，不把 RF12 改名为新的 RF，也不重置其期限。R3 时 RF12 必须仍有效。
5. R3 确认时确认 M10。p0 为三轮共同锚点，期限为 `min(RF12.deadline,AP.confirmed+20s)`。紧凑连续形成时，RF12 的 8 秒已消耗约 500ms，最多约剩 7.5 秒，不能再给完整 8 秒。
6. 等待期的新轮次，累计 V 或 u 一旦超过 R3 对应值的 1.25 倍，立即结束为 `RETURN_PRESSURE_REBOUNDED`，不用等封口。封口时若不稳定，或恢复率低于 `max(50%,0.8×r3)`，亦结束。
7. 新 AP_BUY 替代原 campaign 时结束旧候选，由新根另开观察，不继承旧候选的订单权限或期限。RF12 到期/被替代、锚点丢失和 G 失效均结束。

若 R2 或 R3 不符合递减，结束该 AP 根的本次尝试，不滑动寻找后面的三轮有利子序列。没有新的独立 AP 根，不能反复重试同一段历史。小噪声轮次不算“更弱的一轮”。

## 9 M11 多档续托

策略版本：`m11-post-parent-depth-retention-v1`。M11 是附加筛选条件，不单独提供方向。主比较组为 `M4+M11`、`M9+M11`、`M10+M11`，母策略自身同时作为独立对照。M4 固定使用 `m4-frequency-v2`。

1. 母候选确认时，冻结其 p0、原始期限，以及 p0 下方最近两个已存在的 Bid 价位 p1、p2 和各自 Q0。不把 p0 的同一份 RF 恢复再当作额外档位证据。缺少任一必要档位或只拿到截断盘口，M11 记不可用。
2. 母确认后完整观察 500ms，不预先使用已经在母信号前形成的补单来提前确认。价格集合固定，不随 best bid 或 top K 排名重排。
3. 对每个额外档位，`delta_i(t)=Q_i(t)-Q_i0`。在 500ms 内，两个档位同时满足 `delta_i>=max(0.5份,10%×Q_i0)` 并连续保持 100ms；封口时条件和保持证明都须有效。新下降使条件不满足则撤销证明、重置保持计时，之后须重新完成 100ms。
4. 500ms 封口且母信号仍有效时确认附加候选，冻结各档 `delta_i_confirm`。继续沿用母候选 p0、根身份和原始期限。M11 的 500ms 消耗母信号的剩余时间，不给母信号增加时间。
5. 等待期任一额外档位的净增加量低于确认量的 50%、档位丢失、母信号失效或 G 失效，结束附加候选。只累计真实净增加，不累计反复撤加产生的正增量之和。

母策略对照可以在母候选确认时提交；M11 组只能在自己的留存检查完成后提交。两组使用独立反事实账户，不能先让母策略成交，再把成交归入尚未确认的 M11。按真实成交价与剩余时间匹配，单独报告这 500ms 延迟带来的成交损失。

不把 M11 默认叠到 M5、M6、M7：它们最多 750ms 的期限经本版 500ms 留存检查后，通常已不足统一的 400ms 提交门槛。

## 10 统一 Maker 执行卡

本节是新框架的主测试执行版本；其信号期限严格生效。当前运行中的 M1 GTC、旧 M234 或其他执行版本保持独立，不能把改变等待方式后的收益混入原策略结果。

1. **信号输出。**所有合格候选都记录。新单仅在 `[T15,T240)` 允许提交，T 为该市场开场后的秒数；窗口外的信号仍可输出研究记录。
2. **提交条件。**候选仍有效，G 有效，p0 可追踪且满足 post-only 买单合法性，当前无该执行 episode 的未知或活动订单；距离 `min(original_deadline,T240)` 至少剩 400ms。这个门槛是首版执行预算，不是信号形成时间，也不是实测网络延迟。
3. **报价和数量。**只在 p0 挂同 token Maker BUY，不追价、不改价、不转 Taker。主测试每单最多 5 USDC；按统一份额步长向下取整，低于交易所最小份额就跳过，不自动抬高预算。首版不添加按价格高低筛选的策略门槛。
4. **执行次数。**每 `(策略版本,市场,token)` 最多一次独立 POST；检查阶段的跳过不消耗名额，实际发出后消耗。明确拒绝也不自动重挂；需要重试的执行版本另立实验。M11 各母策略组分别计数。
5. **有效等待。**每个市场事件及计时器复核必需条件。到期、硬失效或 G 失效即请求撤销未成交余量；T240 对所有未成交余单请求撤销。部分成交后只对余量执行该规则，已有仓位持有至官方结算。
6. **撤单及未知。**撤单请求不代表订单已撤；提交、撤单在途以及回执延迟期间继续接受成交。信号在提交回执前失效时，保存撤单意图，取得可用订单身份后立即请求撤余量；不能假定未收到 ACK 就尚未成交。状态未知时继续核对，禁止补发新单。T300 后仍未知的订单保持未知，不能用时钟自动写成未成交或已撤。
7. **模拟成交。**主情景采用已有 trades-only 排队口径，不能用触价、挂单消失、无归因深度减少或信号确认直接制造成交。取消前量的假设另列情景。若沿用旧模型，100ms POST 生效、200ms ACK、200ms 撤单生效均明确标为模型假设；真实记录使用真实生命周期，二者不混作实盘证据。
8. **账户。**各策略、M11 附加组和队列情景使用独立反事实账户。一个场次共享同一个官方结算结果；不能把这些账户收益相加称为组合实盘收益。

新框架主版统一 T240 撤余单，比旧基线“仅限制新单、旧单可能继续等待”的规则更严格。比较策略时须给对照使用同一执行卡，或把这一差异单独报告。数量和执行预算属于政策层，不反向影响信号确认。

## 11 新框架接口与失效分类

信号状态为 `FORMING → CONFIRMED → ENDED/EXPIRED`，质量不足为 `UNAVAILABLE`；结束后不得复活旧 ID。历史事实、当前必需事实和候选期限分别输出。

```text
SignalCandidate {
  spec_version, strategy_version, parameter_hash,
  market_id, token_id, outcome, generation,
  candidate_id, root_id, parent_candidate_id,
  anchor_price, evidence_refs, historical_refs, current_required_refs,
  evidence_start, evidence_end, confirmed_available_at,
  original_deadline, component_deadlines,
  signal_valid, entry_valid, holding_validity,
  feature_values, quality_status, end_reason, reason_class
}
```

`signal_valid` 由本 SOP 判定；`entry_valid` 还要结合执行卡，不能用“目前不能下单”倒推信号没有成立。`holding_validity` 使用新框架的 `VALID / SOFT_EXPIRED / HARD_INVALID / UNKNOWN` 四值；原因类别另记在 `reason_class`。单纯计时到期输出 `SOFT_EXPIRED`，只是表示没有新的证据否定，不表示仍允许本主版等待。当前事实替代首版保守映射为 `HARD_INVALID`，具体原因保留 `REPLACED`；T240 只关闭执行许可，不伪造盘口失效。

| 原因 | 分类 | 主版执行动作 |
| --- | --- | --- |
| AP/RF/LW/EX TTL 到期或历史参照截止 | SOFT_EXPIRED | 撤未成交余单 |
| 锚点消失、合格回补失败、压力回升、恢复变弱、M11 净补单撤回 | HARD_INVALID | 撤未成交余单 |
| 当前必需事实被新事实替代 | REPLACED | 结束原候选并撤余单，不自动续期 |
| 断流、事件歧义、超时处理、无法判明自有污染 | UNKNOWN | 停止新单，撤余单并核对风险 |
| T240 执行截止 | POLICY_CUTOFF | 撤余单，信号研究记录可继续 |

若新框架使用 CARA，对上述字段进行只读消费。首版严格期限组不允许用效用分数越过到期条件；研究“软到期后继续等待”时另立执行版本，明确标记成交发生在原信号期限之外。信号本身不输出未经校准的结算概率，不能把信号成立或盘口报价直接当作预测胜率。

## 12 记录与评价

参数表列出必需字段。输入、原语、轮次、候选、订单和每笔部分成交都应有可关联身份；保存参数哈希、数据适配版本、队列模型版本及代码身份。原始记录不因最终输赢被删除或改写。

成交归因使用成交实际发生前的最后可知信号状态，不使用之后收到的行情倒判。触发成交的同一输入也造成失效时，保留 `signal_valid_before_fill_event` 和 `same_event_invalidation` 两个字段；后续失败不能把此前已发生的成交从样本中移除。只有回执时间、无法可靠定位成交时间时，归因记 UNKNOWN。

分别记录 `fill_after_deadline`、`fill_during_cancel`、成交时间和反馈可得时间。它们全部计入策略的真实或模拟损益，不能剔除之后宣称策略盈利。“有效成交子集”仅用于解释策略语意，必须同时展示全部成交结果。

主报告至少包括：候选数、允许提交数及跳过原因、提交数、任意成交率、成交数量比例、首次成交等待时间、信号/支撑年龄、到期及失效后成交比例、官方结算胜率、成本与毛损益、确认适用的费用和返佣。待结算、断流和未知订单保持独立状态，不填为失败或零收益。

主要比较是相同实际成交价 p、相同成交时剩余时间 τ 下：

```text
Delta_q(p, tau) =
  P(选定token最终胜出 | 信号策略的Maker成交, p, tau)
  - P(选定token最终胜出 | 普通Maker成交, p, tau)

每份结算毛期望 = q - p
```

普通 Maker 对照须在当时合法的公开状态下预先生成，不根据未来是否成交或胜出挑选；使用相同报价/金额算法、队列情景、预算及等待上限。策略自身的结构失效规则仍属于策略处理，不能声称该匹配差异等于信号的独立因果效果。费用与已实现返佣另核，未确认返佣按零处理，不用返佣替代 Delta_q 的证据。

预先分组：短寿命候选按确认后 `[0,250)、[250,500)、[500,750)` ms；较长候选按 `[0,1)、[1,2)、[2,4)、[4,8)` 秒。组合年龄和 RF 年龄分别记录，M10、M11 两者尤其不能混同。剩余市场时间按实际成交计算，不能用提交时的剩余时间代替。

统计按市场聚类并按日期前后留出；同一市场的 Up/Down、共享证据候选和 M11 对照不当作独立结算样本。没有足够匹配对照或成交数量时报告未能判断，不用全体候选的假设足额成交结果代替实际 Maker 选择后的结果。

## 13 接入验收场景

| 场景 | 预期 |
| --- | --- |
| AP 的 750ms 窗口未闭合，量已达标 | 不提前确认 |
| RF 单轮提前完成 100ms 保持 | 等满该轮 500ms，不能提前开启重叠下一轮 |
| 数据断流期间无成交 | UNAVAILABLE，不确认 EX 或递减回流 |
| 同一事件直接流与互补镜像同时出现 | 同一 token 只计一次，不制造额外轮次 |
| M5 AP 不与第二承接轮重叠 | 不确认 |
| M6 只有深度下降，成交对齐未知 | 不确认 LW |
| M7 RF 成立前再次出现 AP_BUY | EARLY_REATTACK，不事后改成 AP2 |
| M8 弱恢复两轮中夹入合格正常恢复 | 当前 DF 形成失败，不能跳过 |
| M8 DF 当前 TTL 已过，新两轮真实修复仍在 5 秒形成预算内 | 可确认 M8；DF 作为历史，不复活其当前状态 |
| M9 原 EX 在复验第一笔 SELL 之前到期 | 不启动复验 |

| M9 卖压达到原 AP 参照量的一半 | 立即结束，即使新 RF 很强 |
| M10 R1/R2/R3 的 V 为 10/8/6.4，Q0 相同，恢复均为 0.6 | 递减与恢复门槛通过；仍须分别满足真实冲击、保持、覆盖和时间条件 |
| M10 R3 完成 | 期限仍来自 RF12，不能重置为 R3.confirmed+8s |
| M10 R2 失败，R3/R4/R5 很好 | 不能把后三轮改称原 campaign 的成功三轮 |
| M11 反复加单撤单，最终回到 Q0 | 不通过净补单条件 |
