# AP AA RF LW EX DF 盘口信号研究规格 v1

日期：2026-11-01，北京时间。状态：待样本校准的研究定义；未实现六个检测器，未接入交易决策。

六个信号分别表达持续进攻、卖方吸收、反复补给、疑似流动性撤退、进攻衰竭、防守衰退。信号输入限定为公开盘口、逐笔成交及其时间与事件顺序。价格仅用于定位档位、匹配成交和验证同一队列，涨跌幅、收益率、均线、外部标的价格和持仓盈亏均不进入触发条件。

当前实时 SessionFeed 有计算这些信号所需的主要原始字段；当前抽查的落盘文件没有完整盘口事件流，不能直接重放六个检测器。LW 即使补齐采集也只能识别未被可见成交解释的深度损失，不能从 L2 精确还原撤单、订单身份或意图。

## 1. 统一对象、时间和证据口径

### 1.1 标识与方向

最小对象为 `(session_id, market_id, token_id, connection_generation)`。所有计算先在单个 token 内进行：

- `AP_BUY` / `AP_SELL`、`EX_BUY` / `EX_SELL` 的方向指主动成交方向。
- `AA_ASK` 指卖方在 Ask 吸收主动 BUY；Bid 对称吸收保留 BA 名称。
- `RF_BID/ASK`、`LW_BID/ASK`、`DF_BID/ASK` 的方向指被观察的挂单侧。
- `CA(token)` 保留当前 SELL 后 BUY 的反击定义，不把另一 token 的 CA 自动当成同一 token 的镜像成交。

YES/NO 的同向信息可能来自互补报价或同一经济事件。没有共同交易身份时，跨 token 组合只能作为“信息方向一致”的描述，不能当作两份独立确认。NORMAL BA 和 opposite BA 观察器也不能直接合并计数。

### 1.2 时间和信息可得性

计时使用本地接收 monotonic 时间；确认时间使用“确认所需的最后一份证据已处理完成”的本地时间。交易所时间仅用于新鲜度、乱序及对应关系检查。保留原始帧号、帧内事件号和本地全局序号，不根据交易所时间排序重放，也不把晚到成交回填进过去已经生成的特征。

信号记录同时保存 `evidence_end_received_mono` 和 `confirmed_available_mono`。组合及后续标签从后者起算；处理时已经超过候选绝对确认截止时间时，不能补发一个过去的确认。AP/EX需要等待完整窗口闭合，另给50ms处理预算：其证据窗口仍为750ms，确认最晚在窗口结束后50ms可得，期间不纳入窗口结束后的市场事件。AA/LW的形成与保留仍须在t0+750ms内实际完成，RF/DF的轮次截止汇总也适用50ms处理预算。

窗口约定：事件窗口为 `[t0,t0+W)`；边界上的事件属于下一窗口。定时器在窗口闭合后判断，累计量到阈值使用 `>=`。定时器本身不构成新的市场证据。

### 1.3 数据有效条件 G

以下条件必须覆盖所需的整个观察区间，不能只在确认瞬间成立：

1. 同一连接 generation，已取得有效完整快照，没有已知丢帧、采集队列溢出或解析缺口。
2. 必需字段齐全：成交需 token、方向、价格、正数量、源时间；深度需档位和更新后绝对数量。`price_change.side=BUY` 是 Bid 更新，不是主动 BUY 成交。
3. 事件到来前盘口非交叉、tick 合法；成交能够与此前盘口对应。触及价无法解释的成交记 `TRADE_BOOK_UNALIGNED`，不能默认为撤单或直接丢掉后继续计算缺失敏感信号。
4. 本地盘口年龄不超过 200ms，成交源年龄不超过 500ms，处理排队计入年龄。研究初值沿用当前 BA 的预算口径，尚未验证适用于所有信号。
5. 无未解释的重复成交或乱序缺口。已被证明的重复消息可以去重；仅凭相同时间、数量、价格不能证明是同一笔成交。字段不能消除歧义时记 UNKNOWN。

现有 CA/BA 对 20ms 内旧消息采用丢弃并保留信号的策略。新研究需要记录这些原始消息及处理原因：对 AP/EX/LW 等依赖完整量和无成交区间的窗口，丢弃了不可还原的新成交必须标为 UNAVAILABLE，不能把当前策略的容差当成完整性证明。此规则不修改现有 CA/BA。

公开流没有提供可独立验证的全市场逐笔连续编号。因此 G 证明的是本地采集和对齐质量，不是证明交易所从未漏报。特别是 LW 始终保留“疑似”语义。

### 1.4 深度和自有挂单

`Q_s(p,t)` 为挂单侧 s、档位 p 在 t 的可见数量，单位“份”。增量消息里的 size 是更新后数量，不是新增量。数量变化必须按原始逐事件顺序计算：

`add_visible=max(Q_after-Q_before,0)`，`drop_visible=max(Q_before-Q_after,0)`。

AP 的归一化深度和 LW 的档位集合在候选开始前冻结，不能随每次 top K 重排而变化。AA/RF/DF 追踪固定触及档位；该档位不再是原触及档位时结束观察并记 `ANCHOR_CHANGED`。这是同一队列的可比性边界，不以价格突破作为失败标签。

若自身订单生命周期能够在当时精确定位，另报去除自身数量的外部深度版本。无法精确分离时保留公开总深度，并标 `SELF_CONTAMINATED`；该窗口不进入主验证样本，不能用撤单请求时间冒充深度已经移除。自身 maker 成交可能同时影响成交和深度，不能重复扣减。

### 1.5 状态与生命周期

状态统一为 `FORMING → CONFIRMED → ENDED/EXPIRED`；缺失或矛盾证据为 `UNAVAILABLE/INVALID`。形成阶段到期且 G 完整、业务条件未达成，记 `NOT_CONFIRMED`；数据不足、连接切换、观察被截断不属于失败样本。

每个候选冻结 t0 和绝对观察截止时间。确认后也有固定寿命，新成交、补单、轮询不能延长原信号。寿命内发生失效条件立即结束；当下次独立证据重新满足定义时生成新 ID，不复活旧信号。一个历史 CONFIRMED 事实不会被删除，后续状态另记结束原因。

主样本对同一家族、同一方向、同一token/anchor使用不重叠候选；后一个候选不能复用前一个已结算轮次的成交或深度变化。不同方向或不同家族可以引用共同证据，但必须保留共享证据ID，不能因此增加独立样本量。

## 2. 初始研究参数

以下为可执行的起始规格，不是从历史拟合得到的最优值。以同版本 JSON 为机器可读参数来源，变更任意阈值需提升版本。

| 参数 | v1 初值 | 用途 |
| --- | --- | --- |
| 短窗口 W | 750ms | AP、AA/回补轮次、EX、LW 最大形成窗口 |
| 子窗口 δ | 250ms | AP 持续性、EX 衰竭观察；共 3 段 |
| 完整窗口闭合处理预算 | 50ms | AP/EX及轮次截止汇总；不延长证据窗口 |
| 数量下限 q_min | 5 份 | 回补轮次的成交、可见损失下限 |
| 相对冲击下限 | 事前单档深度的 10% | AA/RF/DF 小噪声过滤 |
| 回补确认比例 / 保留比例 | 50% / 40% | 达标后持续 100ms 不低于保留比例 |
| RF/DF 比较区间 | 5s | 同一 anchor 的轮次序列 |
| 组合最大间隔 | 1s | 有序组合的 A 确认至 B 首个候选证据 |
| 组合最大总跨度 | 5s | 最早候选证据至最终组合确认 |
| 固定确认后寿命 | AP/AA/LW/EX 750ms；RF/DF 1s | 最大可作为当前状态引用的时间 |

所有 signal TTL 都从其实际确认可得时间起算；形成截止时间从 t0 起算。与现有 CA/BA 组合时还要尊重其原始 t0+3s 时限，不延长旧信号。

## 3. AP 持续进攻

**定义。** 某方向主动成交在一个完整短窗口内占优，并有跨子窗口的持续性；不要求价格移动，也不要求对方深度消失。

**计算。** t0为s方向无活动AP候选/信号时的首笔合格s成交，其方向冻结为s；BUY/SELL候选分别维护，不在窗口结束时挑选表现更强的方向。冻结事前对手侧前3档总深度`D_opp,0`；BUY使用Ask，SELL使用Bid。完整盘口少于3档时使用实际可见档位并记录K；截断数据不知道剩余档位时不计算该深度版本。两个方向窗口可能重叠，作为相关过程保留，不能当作独立样本。

在 `[t0,t0+750ms)` 累计方向成交量 `V_s`、反向量 `V_other`、方向成交条目数 `N_s`、各子窗口方向量 `v_s,j`：

`share_s=V_s/(V_s+V_other)`；`pressure_s=V_s/D_opp,0`；
`V_min=max(10份,0.10×D_opp,0)`；`concentration=max(单条方向成交量)/V_s`。

条目数不代表独立订单数、独立交易者数或独立进攻次数，交易所拆分成交会影响该量。

**确认。** 窗口完整闭合后50ms内，同时满足 G、`V_s>=V_min`、`share_s>=0.80`、`N_s>=3`、3 段中至少 2 段有同向成交且最后一段有同向成交、`concentration<=0.80`。零分母、零事前深度为不可用。两方向不可能在同一窗口同时达到80%；若实现出现此类双确认，作为数据/实现异常处理。

**结束。** 确认后每 250ms 用最新完整 750ms 窗口检查：`share_s<0.60`、`V_s<0.5×V_min` 或最近 250ms 无同向成交，任一成立即结束为 `PRESSURE_FADED`。反向 AP 确认结束为 `FLOW_REVERSED`。G 失效立即不可用；750ms 固定 TTL 到期结束。原 V_min 不随寿命内盘口变薄而降低。

**输出。** 量、条目数、成交量份额、归一化强度、子窗口覆盖、最大单条占比分别保留，不合成未经校准的“置信分”。该定义刻意不把单笔大单归为持续进攻；可另外留作脉冲标签。

## 4. AA 卖方吸收及统一冲击回补轮次

### 4.1 单轮对象

AA_ASK 与 Bid 研究轮次使用同一计算方式，方向镜像。下述 Bid 轮次是 RF/DF 的研究原语，不替换生产 BA 的判定规则。

1. t0 为合格主动 BUY 打在事前 Ask（Bid 轮次为 SELL 打在事前 Bid）。冻结 anchor p、事前单档数量 Q0、t0+750ms 截止时间。
2. 此后同一 anchor 的同向成交量为 `V_hit(t)`；深度最低值 `Q_low(t)=min(Q0,观察开始后的各次Q)`，只在已经观察到合格打单后才累计深度损失。
3. 可见损失 `D(t)=Q0-Q_low(t)`；净恢复 `R_net(t)=min(D(t),max(0,Q(t)-Q_low(t)))`；回补比例 `r(t)=R_net(t)/D(t)`，D=0 时为未知。
4. 若继续出现新低，更新 trough，重算 D、r，并重置正在进行的保留计时，但不重置轮次截止时间。

此处成交与深度下降是共同观察到的证据，不假定逐笔一一匹配。`D` 可能包含撤单，`V_hit` 可能在回补同时发生。分别保存二者及其比例，不能把 D 直接命名为精确成交消耗。

### 4.2 确认及失败

轮次最低合格冲击为 `V_hit>=max(5份,0.1Q0)`，且 `D>=max(5份,0.1Q0)`。达到合格冲击后，r 首次达到 0.50 时开启保留计时；之后连续 100ms 满足 `r>=0.40`，且不迟于 t0+750ms，才确认一轮成功。低于 40% 则清除保留计时，窗口内可重新达到 50% 后重新计时。确认记录中的 `r_confirm` 是 100ms 保留结束时实际比例，可能在 40% 至 50% 之间；同时保存 `r_cross`。

采用净恢复而非所有正增量相加，避免“减 10、加 10”反复闪烁把累计回补刷大。比如 Q0=100、最低70、最终94，D=30、净恢复24、r=0.80。

AA_ASK 在轮次成功时确认。仅有 BUY 成交、无可见损失，记 `NO_VISIBLE_DEPLETION`；仅有深度增加、无合格打单，记 `NO_QUALIFIED_HIT`。完整观察到期、冲击合格却未成功恢复，才是已观察的回补失败。未达最低冲击的轮次不进入 RF/DF 比较。

AA可以在750ms内提前确认，但底层轮次仍观察到固定t0+750ms才封口，期间所有新成交仍分配给当前轮次，不开启重叠轮次。封口记录固定区间的V_hit、D、r_end；完整统计需在随后50ms内可得。供RF/DF使用的“稳定成功轮次”同时要求曾完成AA式100ms保留，且封口r_end>=0.50。这样成功和失败轮次的成交强度都在相同750ms内比较，不拿早确认的小窗口去对比失败的大窗口。

先收到深度下降、后收到成交，不能倒排补成“先打后补”；该段记 `EVENT_ORDER_UNRESOLVED`，不作为成功或失败。

### 4.3 AA 结束

确认后 anchor 不再是原 Ask、G 失效、或相对冻结 trough 的 r 降至 0.20 以下时立即结束；否则 750ms TTL 到期结束。后续重新打单不延长旧 AA，只有新的独立轮次可以产生新信号。

**含义。** 买方发起主动进攻，但同档位卖方可见供给得到补充。它不证明买方失败，也不证明存在隐藏订单或同一个卖方。

## 5. RF 反复补给

**定义。** 同一挂单侧、同一 anchor 在多次独立冲击后都恢复，表达持续补给能力；强度来自多轮检验，而非累计补单量。

**计算与确认。** 使用上述轮次计算器。最新3个已封口且达到最低冲击的轮次均为稳定成功，从第一轮t0到第三轮封口统计可得不超过5s，且3个`r_end`的中位数不低于0.70，才确认RF。三轮不重叠，所有成交/深度变化只分配给其中一轮。记录每轮固定750ms的`V_hit/Q0`、`D/Q0`、`r_end`，并另报`r_confirm`、首次达50%的延迟和保留时间，不拿历史BA CONFIRMED记录数代替三轮。

**结束。** 确认后下一轮合格冲击封口却不满足稳定成功，结束为`REFILL_FAILED`，但这本身尚不等于DF。anchor改变、G失效立即结束；无新冲击时只到期为EXPIRED，不认定防守失败。固定TTL 1s。后续RF需重新形成不复用旧三轮的新证据组。

**含义。** `RF_BID` 为持续承接，`RF_ASK` 为持续卖方吸收。可以记录其覆盖了多少冲击量，但不推断补给主体。

## 6. LW 疑似流动性撤退

**定义。** 固定近端档位集合的可见深度显著减少，其中相当部分不能被同区间已经观察到的主动成交解释。

**计算。** 候选由一次合格深度下降启动，t0 为该更新接收时间；冻结更新前 top 3 的价格集合 P 及其总深度 Q0。后续即使 top K 排名变化也只追踪 P；若 anchor 触及价改变，则结束为不可比较，不将移出 top K 当作消失。

`Q_P(t)=Σ[p∈P]Q_s(p,t)`；`loss=max(Q0-Q_P(t),0)`；
`V_exec(t)=截至t已可得、本地接收落在[t0-500ms,t]中、方向确实击打s且成交价格属于P的可对齐成交量`；
`L_unexplained=max(loss-V_exec,0)`；`withdrawal_fraction=L_unexplained/Q0`。

500ms前置成交缓冲用于覆盖“先收到成交、后收到对应深度下降”的情况，所需G也覆盖这段缓冲；否则第一笔深度下降可能被错误归为撤退。该版本保守扣除全部缓冲成交，其中一部分可能已反映在Q0里，因此宁可漏掉部分LW，也不把它当精确撤单估计。500ms是初值，若已知成交/深度错位超出该预算则该段不可用。

不能因一个快照没有成交字段就把V_exec设成零。成交时间与深度不对齐时为UNKNOWN，而非“无成交解释”。逐事件L2会把同期间的新增与撤回净额混在一起，因此该公式既不估计撤单总量，也不能发现被同时补单掩盖的全部撤退。

**确认。** G 完整、Q0>0，`loss/Q0>=0.30`、`L_unexplained/Q0>=0.20`、`L_unexplained/loss>=0.50` 三项持续满足 100ms，并在 t0+750ms 前完成保留。每条新成交都重算 L；100ms 只是初始对齐等待，并不能保证交易所没有更晚的消息。

**结束。** `L_unexplained/Q0<0.10`、后续成交使 `L_unexplained/loss<0.25`，或 anchor 改变时立即结束；已知漏成交/迟到歧义为 UNAVAILABLE。750ms TTL 到期结束。保留 `VISIBLE_WITHDRAWAL_SUSPECTED` 标签，不输出“确定撤单”或“诱骗”。

**例子。** 事前集合深度300，当前150，期间可对齐打单20，则 loss=150、L=130；损失50%、无法解释部分43.3%、其占损失86.7%。在持续性与 G 均满足时可确认 LW；这只是计算示例，不是本次历史观测。

## 7. EX 进攻衰竭

**定义。** 已被 AP 确认的主动进攻，其后同方向成交强度显著并持续下降。必须先有进攻参照，不能把普通安静直接命名为衰竭。

**计算。** 冻结 AP 确认窗口的同向量 V_ref 与速率 `λ_ref=V_ref/0.75s`；在 AP 实际确认可得之后连续观察 3 个 250ms 子窗口，不与参照窗口重叠。`λ_j=v_j/0.25s`，`fade=(v1+v2+v3)/V_ref`。

**确认。** G 覆盖参照与后续全区间，三个 `λ_j` 都不超过 `0.50λ_ref`，且 `fade<=0.25`。每个后续子窗口还须有至少 1 个已接受的公开深度或 BBO 事件，证明本地在持续收到该 token 的市场更新；单纯 PONG 或其他 token 更新不算。这是保守的可观察性限制，不证明场内真实无漏报。

例如 V_ref=60份/750ms，后续三段为5、4、3份，fade=0.20，三段速率都低于参照一半。零成交子窗口可以参与计算，但只有在其覆盖条件已验证时才是真实观察到的零；否则为 UNKNOWN。

**结束。** 新完整750ms窗口的同向量恢复至 `0.50V_ref` 及以上，结束为 `ATTACK_RESUMED`。反向 AP 确认可另报 `FLOW_REVERSED`，不能将其作为 EX 确认的必要条件。G 失效立即不可用；固定 TTL 750ms。

**含义。** EX_SELL 只表达主动卖压减弱；是否出现主动反击由 CA/AP_BUY 提供，是否存在承接由 BA/RF_BID 提供。

## 8. DF 防守衰退

**定义。** 已被检验过的防守，在相近相对冲击下连续两次恢复明显变差。它与 LW 的区别在于有明确的受击过程和历史恢复基准。

**参照。** 同一侧同一anchor最近连续两轮稳定成功回补（或一个RF中最后两轮），二者固定750ms封口`r_end`的中位数`r_ref>=0.70`。计算相同长度区间的参照相对冲击中位数`p_ref=median(V_hit/Q0)`、相对可见损失`d_ref=median(D/Q0)`。只有一条BA历史记录可以启动待观察状态，不能直接提供两轮比较基准。若基准防守来自更早轮次，最早参照t0至最后参照封口可得也不得超过5s。

**计算与确认。** 在最后一轮参照成功后5s内，接下来两个合格、不重叠轮次都需要：

1. 同一 anchor，G 全程成立；`(V_hit/Q0)/p_ref` 和 `(D/Q0)/d_ref` 均在 `[0.5,2.0]`，避免用更重冲击伪造能力下降。
2. 已观察到完整750ms截止；最终`r_end<=0.30`，且`r_end<=0.50r_ref`。即使曾短暂满足AA确认，只要封口恢复很差，也可成为防守衰退的一轮证据，必须保留“短暂吸收后衰退”的过程。
3. 两轮均满足后，在第二轮完整封口统计可得时确认DF（最晚为其截止后50ms）；第一轮失败只输出FORMING。下一个合格轮次若不具可比性，结束当前候选为`SHOCK_NOT_COMPARABLE`，不能跳过它寻找后续有利样本。若可比但恢复正常，结束为`DEFENSE_NOT_WEAKENED`，也不跳过该轮。

若冲击后没有继续补单但数据完整，允许得到低 r_end；若因断流、anchor 改变、市场结束而提前中断，则该轮为 CENSORED/UNAVAILABLE，不能计为失败。补单延迟达到750ms仍未过50%时记录“右删失至750ms”，不伪造一个精确延迟或无穷值。

**结束。** 后续独立合格轮次稳定成功且`r_end>=0.70`时结束为`DEFENSE_RECOVERED`；anchor改变、G失效立即结束；固定TTL 1s。没有新的冲击时只到期，不判断防守恢复。

**例子。** 参照两轮恢复率80%、90%；后续两轮相对冲击均在可比范围，完整观察后恢复率20%、10%，则 DF 可确认。若后续成交压力增为参照5倍，按 v1 只能说冲击不同，不能确认防守能力衰退。

## 9. 与 CA BA 的组合语法

### 9.1 组合规则

- `A + B`：同一 token、同一 generation，在最终确认时两者都 CONFIRMED 且未过各自寿命；anchor 型信号的 anchor 需相容。
- `A → B`：A 先实际可得，B 的首个独立候选证据发生在 A 之后，间隔不超过1s；A 在 B 启动时必须仍有效。完整序列跨度不超过5s。B 形成期间 A 因正常 TTL 到期可以保留“历史序列”解释；若 A 因 anchor/数据矛盾失效，组合取消。
- 未来标签、最终盈利、未来是否确认 B 不能回填成 A 确认时已经可用的特征。
- 两个信号同时存在、但 B 的候选在 A 确认前已启动，最多报 `+`，不能强行报 `→`。
- CA/BA 已确认后会冻结自身累计证据；旧信号不能用新研究的轮次去延长。保留原信号 ID、原 deadline 与研究信号 ID。

### 9.2 可表达的信息

| 组合 | 表达的信息 | 必须保留的边界 |
| --- | --- | --- |
| CA + AP_BUY | 反击已具有持续主动买入支持 | AP 必须满足独立持续性条件；共用确认 BUY 不算第二个独立样本 |
| CA + AA_ASK | 主动反击遇到卖方吸收 | 冲突状态，不能合成单向看多分数 |
| BA_BID + AP_SELL | 卖方持续进攻，买方仍在承接 | 表达对抗，不等于承接已经获胜 |
| BA_BID → RF_BID | 一次承接之后出现新的多轮补给 | RF 的三轮必须在 BA 后独立形成；复用 BA 轮次只能报共同证据关系 |
| RF_BID + CA | 持续承接背景中出现主动反击 | 不能据此推断同一方先守后攻 |
| CA + LW_ASK | 反击同时伴随卖方可见供给撤退迹象 | LW 是疑似净撤退，不是精确撤单 |
| CA + LW_BID | 反击时自身买方支撑却在减少 | 表达反击基础脆弱的假设，需验证 |
| AP_BUY + AA_ASK + RF_ASK | 连续买入遇到反复卖方补给 | 不因主动买量大就认定进攻有效 |
| BA_BID + EX_SELL | 已有承接，同时主动卖压衰竭 | 不包含主动买入增强的保证 |
| EX_SELL → CA | 卖压先衰竭，随后出现反击 | 很快的 CA 可能发生在 EX 确认前，此时不能标这个顺序 |
| BA_BID → DF_BID | 已有防守之后观察到恢复能力下降 | 需额外两轮成功建立参照，BA 本身不够 |
| CA + DF_BID | 反击存在，但买方防守已出现衰退 | 保留进攻与支撑不一致的信息 |
| AA_ASK → DF_ASK，再接 AP_BUY | 卖方吸收逐渐衰退，后续买入继续 | 较长过程通常只能是历史序列；不能把已过期 AA 当当前 AA |

上述是信息解释假设，不是已证明的收益排序。1s间隔和5s总跨度可能导致某些长序列没有合格样本；不得为了凑例子静默放宽窗口。

| 信号 | 当前实时字段 | 当前抽查文件能否严格回放 | 缺少的关键证据 |

## 11. 最小补采要求及验证顺序

### 11.1 补采规格

在当前 SessionFeed 的真实公共market WS入口，在过滤和整帧合并之前记录原始公开帧；同时记录逐子事件的解释/应用结果。研究写盘异步有界，出现溢出时明确GAP，不阻塞交易。此为后续实现规格，本轮没有修改或重启实时进程。

必需字段：

- session、market、token、generation、原始帧号、帧内数组/更新索引、单调全局事件号。
- 源时间、本地received wall/monotonic、processed/available时间；源时间缺失不能伪造。
- 初始完整book和每个更新后的绝对档位数量；周期完整快照仅用作核对，不填补缺口。
- 所有公开BUY/SELL成交、quantity、price、可得的transaction hash/交易身份；不能假设hash唯一对应一笔成交。
- 每条事件的accepted/ignored/rejected及原因、stream gap、重连、队列丢弃、writer水位与关闭摘要。
- 盘口BBO一致性、时效、tick变更；只对自身公共订单记录能去污染的最小生命周期，不采集凭据。

公开L2不能精确区分 gross add/cancel，也不能恢复其他人的订单ID、排队优先级、真实冰山量或身份；这些内容不列为补采后可证明的目标。

### 11.2 验证顺序

1. **语义验收。** 用有明确预期的事件序列检验六个检测器：单笔巨量不算AP、反复增减不刷RF、无已知进攻不算EX、断流不算衰竭、缺成交不算LW、极端更重冲击不算DF、anchor离开和观察不足为删失。六个定义不能靠复制实现逻辑的测试自证。
2. **输入覆盖。** 在完整公共流上输出可用窗口占比及不可用原因；分开统计源事件缺字段、成交盘口不对齐、旧消息、重复歧义、GAP、自有挂单污染。先决定数据是否适合，再讨论信号效果。
3. **盘口结果标签。** 从信号实际确认可得之后观察未来0.75/1.5/3s的同向成交量、独立回补轮次成功率、净恢复比例、未解释深度损失和anchor删失率；标签使用与特征不重叠的事件。未来形成AP/AA等可以是行为标签，但不单独作为有效性的证明。
4. **组合增量。** 比较CA与CA+AP、CA+AA、CA+LW；BA与BA+EX、BA+RF、BA后DF。背景匹配仅用当时已知的市场阶段、事前深度、过去活跃度和数据质量。全部同一五分钟市场放在同一训练/验证分组，按时间留出，不能按行随机切分。
5. **样本单位。** 以不重叠episode/市场为单位报告，重叠窗口不能增加独立样本量；条件化RF/DF必须报告其冲击筛选与删失。多阈值、多组合搜索保留未选择结果，避免只报告最好组合。

第一阶段只研究盘口行为表达能力，不用价格结果反向选信号。某个组合更容易随后涨价或盈利，属于另一个需明确约定执行、延迟和费用的验证问题。

## 12. 外部依据与适用边界

- [Polymarket官方实时数据文档](https://docs.polymarket.com/market-data/realtime-data)：核对book、深度更新、成交和时间字段；不提供其他参与者完整逐订单生命周期的证明。
- [Cont、Kukanov、Stoikov，The Price Impact of Order Book Events](https://arxiv.org/abs/1011.6402)：订单簿事件与订单流失衡的研究依据；不支持把可见深度减少全部归因为主动成交。
- [Xu、Gould、Howison，Multi-Level Order-Flow Imbalance in a Limit Order Book](https://arxiv.org/abs/1907.06230)：多档订单流可作为构造维度；其股票样本结果不等于Polymarket上的有效性证明。

本规格中的AP、AA、RF、LW、EX、DF命名、阈值、保留时间和组合语法均为本研究提出的可检验约定，不声称是上述论文定义或已经验证的市场规律。
