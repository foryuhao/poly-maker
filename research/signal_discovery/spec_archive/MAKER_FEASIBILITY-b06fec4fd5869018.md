# Maker成交与支撑底线的可行性

日期：2026-11-11。本文是新候选的逻辑交接说明，不是新信号、模拟适配器或测试结果。以下结论只在写明的队列与数据假设下成立，不自动更改各SOP参数，也不把纸面可行当成真实成交。

## 1. 形成量、排队量与成交量分开

信号形成期间的H回答“此前发生了多少实际受击”。Maker订单只能从它实际进入模型队列以后开始取得排队进度；确认前、提交前或尚未生效时的历史成交不能用于清理它前方的队列。

用c表示候选确认、s表示提交、a表示订单生效，d表示信号首次失效决定时刻，z表示取消真正生效。有效信息下的排队时间至多为 `max(0,d-a)`，不是每个候选都享有完整3秒；取消在途的额外暴露直到z，须单列。ACK晚到不重设a，提交延迟及M17的准入前复核等待也不能重设c或deadline。

例如M18形成两轮的H1+H2即使很大，也不意味着新订单已经排到前面。M1/M6的组件最大寿命750ms同样不是750ms已生效排队时间；其历史执行版本需单独冻结，本文不把新COMMON的floor加到旧策略上。

## 2. 固定底线为何需要后续流动性

先看一个理想化的**物理FIFO队列**：同token、同价P；只有一笔研究订单；入队前所有已在P的外部订单都排在它前方，之后新单排在后方，没有特殊优先级、隐藏队列或无法识别的重排。设入队时外部量A0，研究订单量q，信号底线F>0且只由外部量支持。

若入队后没有新的外部挂量，消耗/撤回前方队列的过程会先让外部量跌破F，然后才可能清完前方队列、轮到本单。在即时、完整可见的假设下，**“全程外部量>=F”与“无后续补单却成交”不能同时成立**。这不表示严格Maker永远不能成交，而是指出它需要什么样的后续路径。

有后续外部量加入时，新单可排在本单后方。记第一次实际成交时仍留在后方的外部量为B；前方已清空，故此时外部量就是B。若底线仍有效，必要条件为 `B>=F`。所以“前方能消耗掉”和“外部需求仍留在原档”可以并存，完整语意依靠队列更替，而非只靠初始厚度。

若公开总量把本单剩余量q_remaining也算进去，检查总量只能得到 `B+q_remaining>=F`；这可能是本单自己撑住底线，不能据此证明外部承接仍在。实盘若要剔除自有量，必须有可核对的订单可见性与时序，不能盲减ACK数量。无自有订单进入行情的历史模拟则属于另一种量口径，见下一节。

这里只推导模型必要条件。公开L2的数量、成交与取消未必有共同事件时钟；观察到同刻变化时不能虚构精确先后，无法区分则保留UNKNOWN/ORDERING_UNKNOWN。该推导不授权删除任何已经发生的成交。

## 3. 不改历史盘口的反事实模拟要另算

若模拟器保持历史公共book不变，只在假设队列中插入本单，那么公共成交原本消耗的仍是历史外部订单；模拟分配给本单的成交不会自动让历史book少消耗一份。不能把这个book同时当成“已经包含本单真实影响的物理队列”。

在一个便于审查的限定情景中：单笔本单、同价直接SELL、入队时假定前置量A0恰为该价外部可见量Qe0；没有其他本方订单分走流量，也没有跨价穿透撮合。定义：

- H：入队后该价符合时间与身份条件的公共SELL累计量。
- Ca：模型已经在因果可得时刻明确计入的前方撤单量；不得把所有净减量都当作Ca，且不能超过尚存前方队列。
- x：本单在该情景下累计模拟成交量，0<=x<=q。
- Qe：未被本单改写的历史外部可见量。
- N/C：理想完整账本中的外部新增/撤回总量；公开L2通常不能分别识别它们。

在这些假设下，若已经成交 `x>0`，必要量约束是 `H+Ca>=A0+x`。包含未成交情形时，可写一般上界 `x<=min(q,max(0,H+Ca-A0))`；x=0本身不要求前方队列已清完。这不是充分条件：还需正确时序、订单已生效、未取消、质量有效和流量没有被重复分配。未来H不能拿来作当时的下单条件。

若还假设历史数量账本完全一致，则 `Qe=A0+N-C-H`。对于x>0，把底线 `Qe>=F` 与成交必要条件联立，得到 `N-(C-Ca)>=F+x`；它不适用于尚未成交的x=0静态队列。其中N/C不可逐项识别时，这个式子只能解释所需路径，不能从L2假装测出了准确净补单量。

这里出现F+x，而上一节物理队列只要求B>=F，是因为**历史book没有因本单获得x成交而改变**。两种模型的量守恒对象不同；不能挑较宽松的公式来验收较严格模型，也不能由一套模拟的流量残差声称知道实盘本单后的队列。

算例，仅用于解释定义：A0=100、q=5、F=90、Ca=0。反事实完整成交5至少需要入队后H>=105；若历史Qe仍>=90，理想账本便需N-C>=95。只有形成前H=105，或入队后仅H=50，即使book一直很厚，也不能据此判该订单已成交。若某次未知减量被假定为前方撤单，应另记模型情景，不能把它包装成观察事实。

## 4. 失效、成交与撤单的顺序

“先处理输入导致的失效，再发布新候选”约束的是新决策，不意味着已有订单在这条输入之前已被撤销。同一卖单可能消耗外部队列、打破floor，并在撤单真正生效前成交本单。这些成交属于实际经济暴露，不因信号结束就作废。

反过来，只因成交回执先到、深度消息后到，也不能断言成交时支撑一定有效。须保留交易所/模型事件时刻、received、available、cancel_request、cancel_effective及原始输入键；无法确定的顺序单列。不能将程序回调顺序冒充交易所先后，也不能为了让胜率好看改成“先撤再看成交”。

本说明不增加订单动作，不改变3s原截止，更不将取消在途成交从PnL剔除。相同价格和剩余时间的胜率比较，应与全量经济PnL分别报告。

## 5. 本次只读看到的模型边界

工作区[broker.py](../../src/polymaker/m1234_sim/broker.py)明确声明不修改公共book，队列是本地可得时刻的假设。`join_live_order`在模型到达时取可见量加入外部段，再插入本单；`trade`按情景内队列消耗直接SELL。前方撤单比例默认0，非零时有单独的假设归因与等待步骤。该代码还处理低于锚价的成交分配与多订单队列，所以第3节的单价简式**不能原封不动替代完整撮合器**。

另一个[m4_fill_model.py](../../src/polymaker/m4_fill_model.py)是价格触及观察模型，保存了自己的等待政策。触及结果与FIFO排队结果不是同一成交证明；文件中存在某模型也不证明当前服务正在采用它。

这里只读相关定义并记录阅读hash，没有运行、修改或要求重启任何模拟/交易进程，也没有审计完整撮合器是否正确。现有SOP里的成交要求仍由用户测试模块独立实现和验证。

## 6. 对研究顺序与反馈的含义

| 观察到的结果类型 | 能说明什么 | 不能直接说明什么 |
|---|---|---|
| 候选方向好，但有效期内前置队列很少耗尽 | 信息可能未能转化为当前执行下的成交 | 不能把未成交候选胜率当Maker收益，也不能只延长旧证据寿命 |
| 有效期内成交依赖后续量保留 | 观察维度应包含入队后的外部量及排队进度 | 不能把形成前H或本单量当成外部承接 |
| 主要靠前方撤单假设才成交 | 结果对队列模型敏感 | 不能称为由公开成交充分支持的成交 |
| 主要在floor失效后、撤单生效前成交 | 取消竞态是实际执行的重要部分 | 不能删掉这组后宣布策略达标 |
| 触及模型好、FIFO模型机会不足 | 模型选择改变了成交群体 | 不能仅归因于市场变化或信号逻辑本身 |

M17/M18提出的是不同的承接观察，不因存在成交量就自动解决排队问题；M12/M14的对侧证据也不能替本单清理前方队列。下一步研究应同时解释形成信息与有效等待时的成交路径，而不是不断叠加方向过滤。

M20的锚档净增还会扩大入队时前置量。其固定最低数量为q0+G，而三档总量约束又要求当前P量至少q0+D1+D2；代入某一成交时刻的联合下限时，应同时记录后方数量状态，不能把算例中的140当作全程固定阈值。即使后方变化使联合下限降低，原规则和期限也没有重置；信号的厚队列仍需要后续换手才能轮到本单。

交给测试模块的最小反馈字段建议为 `quantity_basis, model_live_at, signal_invalid_at, cancel_effective_at, initial_ahead, post_live_eligible_sell, assumed_ahead_cancel, allocated_fill, external_visible_at_fill, ordering_quality, fill_during_signal_validity`。字段需来自冻结模型或可用数据，缺失标UNAVAILABLE；采用聚合统计和已有事件引用，不另复制逐tick日志。本任务不计算这些结果、不启动测试。
