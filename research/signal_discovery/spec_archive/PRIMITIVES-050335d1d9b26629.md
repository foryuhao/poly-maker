## 原语组合必须区分三种关系

1. **当前重叠：`A + B`。** 同token/generation、引用的原价档关系明确，确认时两者当前有效且可用于新行动。组合可得时刻不早于两者较晚确认；当前态截止取各原截止最早者，不能相加TTL。QR、XR或XW待复核时不能首次发布依赖它的新组合。
2. **新阶段：`A → B`。** B首个事件的received及输入键都晚于A的可得确认。A若已过期，只能作为冻结历史参照；新B不能把过期A重新变成当前支撑。形成期限、失败首轮是否可跳过等必须另写，不由箭头符号补足。
3. **共同证据。** 同一成交、回落或恢复事件可以支持不同诊断，但不是多份独立样本。RF_BID与QR_BID可能共用路径，SR与从峰值起算的LW也可能共用回落。必须保留原始事件引用和重叠关系，不因换了原语名重复计分。

过期、INVALID和UNKNOWN不同：过期只是不能再作为当前事实；明确失效不因数量恢复而复活；未知不当作零成交、零撤单或确认失败。正向新事实与旧root分开，不隐式延长期限。

## 可以表达的新组合语意

| 组合 | 可以表达什么 | 不能直接推出什么 |
|---|---|---|
| QR_BID + SR_ASK | 买方数量耐受卖出，对侧新补供给却短驻 | 不保证后续卖盘是安全回流，也不保证排得到Maker |
| RF_BID + SR_ASK | 多轮承接仍有效，卖方新增厚度留不住 | SR没有足够真实BUY检验时，不能升级成DF_ASK |
| AP_BUY + QR_ASK | 买方持续进攻，但供给在真实成交下仍保量 | 不是两份同向看多信息；可作为进攻受阻的观察 |
| CA + SR_BID | 主动反击出现，但买侧新增挂量短驻 | 不自动否决全部CA，也不能忽略支撑脆弱的可能 |
| BA_BID → 新QR_BID | 一次守价之后，后续独立成交阶段仍保量 | 若复用了BA形成事件，就不是新的验证阶段 |
| XR_BID + DF_ASK | 买入之后买侧跟挂，卖侧恢复转弱 | 同一BUY可能被重复使用；XR不是目标Bid已承接SELL的证明 |
| XR_BID → 新SELL复验 | 未受卖消耗的新挂量，再接受后续实际卖出检验 | 需另定种子、首笔、底线及期限，不能直接冒用现有M23规则或结果 |

这些是组合研究入口，不是已实现的新M策略。优先归入已有研究家族，证明新增信息与完整执行语意后再决定是否需要独立策略编号。

例如研究`QR_BID + SR_ASK → Maker`时，锚取QR原Bid，供给档取SR原Ask；须同token/generation且两事实当前可用，原档和合法post-only条件满足。候选最晚截止为两者原deadline较早者；SR的750ms往往先到，发送时还需满足所选Maker合同的至少400ms余量。等待中QR底线/复核与SR上界均持续约束，任一结束即触发该组合的撤单规则。形成期成交不能给新订单抵扣前置队列，取消在途成交保留。

现已在[M17](M17.md)交付显式备选`m17-qr-sr-ask-v1`「保量配短补」的完整信号与等待SOP：只选QR确认之后第一个全新SR root，失败不换下一个；QR v1.1与SR v1分别绑定版本/hash，保留两原截止。首次准入不通过不重试同QR；执行沿COMMON，队列/延迟/费用等运行profile仍须由测试模块冻结。该分支属于M17家族，未实现或测试；不代表所有更宽泛的QR/SR并行时序都已获得可执行定义。

## 组合审查后的优先顺序

[SR/QR组合审查](PRIMITIVE_COMPOSITION_REVIEW.md)发现明确的时序排除：SR确认后才开始QR时，SR在QR完成前已过期；QR与SR增厚同步开始时，也不足COMMON的400ms提交余量。因此优先研究已有或较早开始的QR与新SR配对。不能为组合成立而给原SR续期。

旧BA与同档SR可能共存，但表达累计回补与新增量短驻的分歧；SR与从峰值起算的LW可能复用同一次回落；SR的初始增厚还可能先结束M12式旧弱供。以上是原规则推导，没有新增原语、策略编号、参数或统计独立结论。

XR与SR在同侧、同一增量事件且同B/Delta时，SR的20%回落低于XR的50%当前留存底线，不能同时当前有效；不同基线则须另查。既有QR_BID与XR_BID组合时，XR的前500ms零SELL条件也会排除刚发生的QR成交，须保留真实时间间隔。具体边界见[XR SOP](P_XR.md)。

XR接续策略现交付在[M23](M23.md)同文件的`m23-xr-seeded-sell-test-v1`「攻后加托复验」：种子完整发布交接及首笔SELL前守80%，首笔合格新SELL时XR转为历史，当前底线切20%，随后500ms复验通过才Maker。不能同时保留XR的50%当前底线，否则复验末段只剩50%一个点。本分支另延长种子零SELL至确认边界，并独立保留逐笔100ms复核；因此不是原M23的纯种子替换，也不能直接继承其结果。原XR和M23主版均未改，仍未测试。

同档QR先、XR后的进一步查重见[组合审查第7–9节](PRIMITIVE_COMPOSITION_REVIEW.md)：相同输入口径且QR持续有效时，XR当前底线必然高于QR旧底线，数量守护可合并解释；QR仍提供早先真实SELL历史和更早原截止。不能据此删掉整个QR，也不另立“双重承接”原语。反向XR先、QR后需按实际新Q0R比较，不能套用前向结论。本轮只归并解释，原语/M规格、订单和收益账不变。

## 继续研究的方向与约束

之后优先研究现有原语未覆盖的观察维度，如补量留存路径、承受成交时的数量稳定性、两侧响应不一致；先做定义查重，区分新增路径、已有策略提取和仅参数变体。不同侧的同名原语不默认同向，更多原语也不等于更多独立证据。

每个新原语独立MD，首个JSON含身份、版本、参数、来源及状态。`catalog.json`的`primitives`现索引15个不同原语ID：AP、AA、RF、LW、EX、DF、CA、BA、SR、QR、XR、RD、XW、QO、SB；M策略仍保留23份、12个方向家族与M11过滤器。本任务不实现原语检测器、模拟适配器或测试，不把未测试组合称为已提高结算概率。

LW的双侧定义补充了一个范围区别：原Bid支撑或QR仍有效时，后两档退量仍可使LW_BID成立。双侧LW仅作为两个侧实例的当前重叠，不另起新名；其截止取两者原截止较早者。具体反例、必要数量区间及“未出现LW”不能等同没有退量的边界，见[LW独立SOP](P_LW.md)。本版明确恰三初始档和首个发布机会，不能冒称旧LW候选等价。

已在[M6](M6.md)交付显式分支`m6-fixed-bid-retention-v1`「撤供期多档留托」：旧RF数值定义采用直接成交，在全新LW_ASK root开始前就绪；同起点冻结Bid三档并各守90%，与Ask形成同步，不另等500ms。它既不是M11已有母分支，也不是`NOT LW_BID`；老Bid撤量基线与新基线不同，两个标签仍可共存。分支完整定义一次准入、原截止及撤单，未改原语/主M6或运行测试。

新增[RD回补回吐](P_RD.md)区分“已真实受击并恢复，之后在零新增原档打单记录下回吐”的历史路径。原轮必须有材料性损失、真实成交、严格50%恢复及尾段来源；回吐到20%后保持100ms，750ms形成硬截止不延长。它到达20%时，同一轮COMMON支撑的40%底线必已失守，不能组合成同一支撑仍有效。RD_ASK与其他当前Bid支撑的组合需另写完整Maker交接；新原语未测试，也不证明撤单归因。

RD_ASK与Bid支撑现已交付完整分支[M12卖补回吐留托](M12.md)，版本`m12-rd-ask-supported-v1`：在RD恢复种子发布时冻结更早且750ms内的合格Bid，之后一直维护，不在最终回吐时才挑好轮。RD确认后一次准入Maker，原750ms截止限制首次发送至确认后最多350ms。Ask按原RD40%上界维护，不继承主M12对另一新轮的50%恢复退出。不是主M12成交的事后过滤；RD和主M12规格未变，未测试。

RD_BID到新SELL修复已交付[M8回吐后重建](M8.md)，版本`m8-rd-level-rebuild-v1`：首笔新SELL前RD仍当前有效，在该笔处转历史；新冲击资格须在原截止前取得，复验末100ms补至原轮50%恢复量，等待守原40%量界。新轮100%恢复可能只回到较低起点，所以不能直接复用M8主版相对恢复条件。原RD/M8主版未改，不新建原语或M编号；尚未测试。

[组合审查v1.3](PRIMITIVE_COMPOSITION_REVIEW.md)追加RD组合的基线核对：同一复验窗内M8重建的末段Q>新初量，M23缓冲的末段Q<新初量，不能同时作形成确认。M8的原量界和较早期限已覆盖同轮普通S，但普通S反过来不能保留重建语意。新Ask轮即使恢复100%，仍可低于RD旧上界；若该500ms轮从RD确认后才开始，也没有COMMON400ms余量可用于新的当前态组合首次发送。全部是既有规则推导，不新增原语或测试。


最新新增[XW攻后退挂](P_XW.md)，与XR合并为“攻击后对侧数量响应”研究家族，保留各自明确的数量方向、确认及当前期限。它与M21的两轮承接并不等价，也不与LW复用的同次退量重复计分。不新建M编号；完整组合已作为[M21「旧托先行」](M21.md)显式备选交付，见下文。XW之后才启动500ms承接轮会缺少400ms发送余量，不延长原750ms以凑组合。


XW_ASK的Maker接续现交付在[M21](M21.md)，版本`m21-xw-prior-support-v1`：在XW首笔新SELL前冻结最近750ms内已确认的原Bid S，持续守旧floor、3s原支撑期限及后续合格轮稳定退出；形成/等待另加每笔新SELL100ms复核。XW首个发布时两侧均可行动才一次准入，待复核不等下一次。原XW750ms截止先到，不能把新的500ms Bid轮未来成功作为早先准入依据，失败后已发生的成交仍计入经济账。主M21、XW和COMMON不变；本分支属于旧家族，未实现或测试。


[组合审查v1.4](PRIMITIVE_COMPOSITION_REVIEW.md)补充阶段分类：旧floor从未破的新轮，其40%底线严格高于旧floor；M8失守后重建则相反。因此M21保持旧floor与M13接替新floor是不同政策，不能按最新S统一替换。M23同一缓冲复验的恢复率最多50%，只有q=80%预增线、m=20%缓冲线、末100ms恰在50%线时才可能与同轮稳定S并存，不增加重复确认原语。提前准入后按未来新轮成功筛选成交也不能当作等待确认策略。本轮未改原语或M参数，未测试。


最新交付[QO挂量回摆](P_QO.md)：净变化小但固定网格的数量路径反复改变方向。用三个250ms节点与原始批次来源避免把拆包回调数当证据，仍须承认采样相位与传输节奏会影响观察。它优先作上下文，不直接代表买卖方向；首笔同档消耗会结束当前QO，所以QO_BID若接Maker应研究明确的历史交接与新受击验证。同档QO之后的新XR/XW/SR材料性变化也会先破QO带宽，不能拼成两个当前确认。现已另附M17完整备选SOP，仍无经济验证或自动执行授权。


QO_BID的接续现交付为[M17「回摆后扛卖」](M17.md)，版本`m17-qo-then-retained-sell-v1`。首笔新SELL前QO须仍有效；该笔把QO转历史、撤掉旧带宽/零SELL维护，以实际前量q开启本策略独立750ms验证，完整复用QR v1.1规则。全局旧QR即使仍有效也不能拿来代替新窗口，不能重置其他观察器。新确认必晚于QO原到期；候选硬截止仍是cQ+3s，名义余1.45–2.25s。QR90%q门槛可能低于旧QO下界，故不称原水平已修复。该分支只是探索性前史条件，不能重复计独立承接或沿用主M17收益；原语文件保持冻结，未实现或测试。


恢复后交付[SB短退回补](P_SB.md)，与SR按“短暂数量偏离后返回”家族归并。先减后补与先加后退不能按名字当两份独立优势；若复用同一SR峰值回落作SB起点，SB回补达标会先突破旧SR上界，另一个不同基线的后续SB却可能与旧SR共存。局部SB与后两档仍退量的LW也可能共存。若旧S从SB初减量起一直有效，新SB数量底线更高、覆盖旧数量guard，但旧受卖历史和截止仍须保留。未新增M编号或执行分支。
