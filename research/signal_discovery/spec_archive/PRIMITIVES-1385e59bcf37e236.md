四份均为SPEC_ONLY；LW是已有名称的独立规格及Bid推广，不计作第四种新机制。SR的短时数量变化也可能只是普通报价更新；QR也可能因数据不同步而被误判；XR的先后顺序不证明因果或参与者身份。字段、原始顺序和质量合同未核验时应标UNAVAILABLE/UNKNOWN，不能为增加工具数量把输入能力假设成已实现。

QR v1.1补回M17已有的发布点90%当前保量检查；v1只保留末段90%和交接70%，两者在发布点量为70%至90%之间时行为不同。旧稿已按hash归档，原3秒寿命、70%当前底线和100ms复核不变，不将两版混池。

## 原语组合必须区分三种关系

1. **当前重叠：`A + B`。** 同token/generation、引用的原价档关系明确，确认时两者当前有效且可用于新行动。组合可得时刻不早于两者较晚确认；当前态截止取各原截止最早者，不能相加TTL。QR或XR待复核时不能首次发布依赖它的新组合。
2. **新阶段：`A → B`。** B首个事件的received及输入键都晚于A的可得确认。A若已过期，只能作为冻结历史参照；新B不能把过期A重新变成当前支撑。形成期限、失败首轮是否可跳过等必须另写，不由箭头符号补足。
3. **共同证据。** 同一成交、回落或恢复事件可以支持不同诊断，但不是多份独立样本。RF_BID与QR_BID可能共用路径，SR与从峰值起算的LW也可能共用回落。必须保留原始事件引用和重叠关系，不因换了原语名重复计分。

过期、INVALID和UNKNOWN不同：过期只是不能再作为当前事实；明确失效不因数量恢复而复活；未知不当作零成交、零撤单或确认失败。正向新事实与旧root分开，不隐式延长期限。

## 可以表达的新组合语意

| 组合 | 可以表达什么 | 不能直接推出什么 |
|---|---|---|
| QR_BID + SR_ASK | 买方数量耐受卖出，对侧新补供给却短驻 | 不保证后续卖盘是安全回流，也不保证排得到Maker |
| RF_BID + SR_ASK | 多轮承接仍有效，卖方新增厚度留不住 | SR没有足够真实BUY检验时，不能升级成DF_ASK |
| AP_BUY + QR_ASK | 买方持续进攻，但供给在真实成交下仍保量 | 不是两份同向看多信息；可作为进攻受阻的观察 |
| CA + SR_BID | 主动反击出现，但买侧新增挂量短驻 | 不自动否决全部CA，也不能忽略支撑脆弱的可能 |
| BA_BID → 新QR_BID | 一次守价之后，后续独立成交阶段仍保量 | 若复用了BA形成事件，就不是新的验证阶段 |
| XR_BID + DF_ASK | 买入之后买侧跟挂，卖侧恢复转弱 | 同一BUY可能被重复使用；XR不是目标Bid已承接SELL的证明 |
| XR_BID → 新SELL复验 | 未受卖消耗的新挂量，再接受后续实际卖出检验 | 需另定种子、首笔、底线及期限，不能直接冒用现有M23规则或结果 |

这些是组合研究入口，不是已实现的新M策略。优先归入已有研究家族，证明新增信息与完整执行语意后再决定是否需要独立策略编号。

例如研究`QR_BID + SR_ASK → Maker`时，锚取QR原Bid，供给档取SR原Ask；须同token/generation且两事实当前可用，原档和合法post-only条件满足。候选最晚截止为两者原deadline较早者；SR的750ms往往先到，发送时还需满足所选Maker合同的至少400ms余量。等待中QR底线/复核与SR上界均持续约束，任一结束即触发该组合的撤单规则。形成期成交不能给新订单抵扣前置队列，取消在途成交保留。

现已在[M17](M17.md)交付显式备选`m17-qr-sr-ask-v1`「保量配短补」的完整信号与等待SOP：只选QR确认之后第一个全新SR root，失败不换下一个；QR v1.1与SR v1分别绑定版本/hash，保留两原截止。首次准入不通过不重试同QR；执行沿COMMON，队列/延迟/费用等运行profile仍须由测试模块冻结。该分支属于M17家族，未实现或测试；不代表所有更宽泛的QR/SR并行时序都已获得可执行定义。

## 组合审查后的优先顺序

[SR/QR组合审查](PRIMITIVE_COMPOSITION_REVIEW.md)发现明确的时序排除：SR确认后才开始QR时，SR在QR完成前已过期；QR与SR增厚同步开始时，也不足COMMON的400ms提交余量。因此优先研究已有或较早开始的QR与新SR配对。不能为组合成立而给原SR续期。

旧BA与同档SR可能共存，但表达累计回补与新增量短驻的分歧；SR与从峰值起算的LW可能复用同一次回落；SR的初始增厚还可能先结束M12式旧弱供。以上是原规则推导，没有新增原语、策略编号、参数或统计独立结论。

XR与SR在同侧、同一增量事件且同B/Delta时，SR的20%回落低于XR的50%当前留存底线，不能同时当前有效；不同基线则须另查。既有QR_BID与XR_BID组合时，XR的前500ms零SELL条件也会排除刚发生的QR成交，须保留真实时间间隔。具体边界见[XR SOP](P_XR.md)。

XR接续策略现交付在[M23](M23.md)同文件的`m23-xr-seeded-sell-test-v1`「攻后加托复验」：种子完整发布交接及首笔SELL前守80%，首笔合格新SELL时XR转为历史，当前底线切20%，随后500ms复验通过才Maker。不能同时保留XR的50%当前底线，否则复验末段只剩50%一个点。本分支另延长种子零SELL至确认边界，并独立保留逐笔100ms复核；因此不是原M23的纯种子替换，也不能直接继承其结果。原XR和M23主版均未改，仍未测试。

同档QR先、XR后的进一步查重见[组合审查第7–9节](PRIMITIVE_COMPOSITION_REVIEW.md)：相同输入口径且QR持续有效时，XR当前底线必然高于QR旧底线，数量守护可合并解释；QR仍提供早先真实SELL历史和更早原截止。不能据此删掉整个QR，也不另立“双重承接”原语。反向XR先、QR后需按实际新Q0R比较，不能套用前向结论。本轮只归并解释，原语/M规格、订单和收益账不变。

## 继续研究的方向与约束

之后优先研究现有原语未覆盖的观察维度，如补量留存路径、承受成交时的数量稳定性、两侧响应不一致；先做定义查重，区分新增路径、已有策略提取和仅参数变体。不同侧的同名原语不默认同向，更多原语也不等于更多独立证据。

每个新原语独立MD，首个JSON含身份、版本、参数、来源及状态。`catalog.json`的`primitives`现单独索引SR、QR、XR、LW四份；M策略仍保留23份、12个方向家族与M11过滤器。本任务不实现原语检测器、模拟适配器或测试，不把未测试组合称为已提高结算概率。

LW的双侧定义补充了一个范围区别：原Bid支撑或QR仍有效时，后两档退量仍可使LW_BID成立。双侧LW仅作为两个侧实例的当前重叠，不另起新名；其截止取两者原截止较早者。具体反例、必要数量区间及“未出现LW”不能等同没有退量的边界，见[LW独立SOP](P_LW.md)。本版明确恰三初始档和首个发布机会，不能冒称旧LW候选等价。
