## 1. 读法和版本边界

组合必须同时说明**什么事实、发生顺序、当前还须保留什么、在哪个阶段等成交**。仅写`RF+EX`无法表达M1与M9的区别。

| 记号 | 含义 |
|---|---|
| `A → B` | B使用A之后的新输入；具体首笔、received/available及输入键条件以对应SOP为准；不表示A必须一直当前有效 |
| `A ∥ B` | 两者可以并行形成，组合发布时都须可用；没有擅自增加谁先谁后的限制 |
| `hist(A)` | 冻结形成历史；自然到期不自动否定后续阶段，但原档、质量和策略明确继承的硬失效仍检查 |
| `live(A)` | 原版本下当前有效；不是永久方向判断，也不一定包含连续数量底线 |
| `handoff(A→history)` | 只在SOP指定的合法事件上解除当前原语要求，转入新的策略状态；不能用它挽救之前已经失败的root |
| `M(P;G;d)` | 在固定Bid锚P按本策略执行合同挂Maker买单，以G维护等待，原截止为d；实际成交才进入结果账本 |

`live`的含义取决于版本：旧BA/RF是有限寿命事实，未承诺持续守COMMON的40%数量底线。新严格S才有自己的固定floor。不能把“当前RF有效”翻译成“当前每一笔SELL已经成功承接”。

### 原语与策略内构件字典

| 写法 | 权威版本／来源 | 映射限制 |
|---|---|---|
| AP、EX | [P_AP](P_AP.md)、[P_EX](P_EX.md)，策略中标记`legacy/shared`或`@M1/M2` | M1/M2各自消费端和替换机制保留，不能仅凭数值相同认为同一实现；同一个父AP与其后EX不是当前双重确认 |
| RF2 | [P_RF](P_RF.md)共享两轮500ms主版；`RF2@M1/M2`为各自旧策略来源 | 两轮稳定、8秒寿命；旧滞回held不等于末100ms严格≥50%；输入镜像及正向事实替换按各策略 |
| CA、BA | [P_CA](P_CA.md)、[P_BA](P_BA.md)所选M3版本 | CA是SELL后BUY反击，BA是受卖、减损后累计正增量；均不能改写成AP或严格S |
| DF_ASK@M4 | [P_DF](P_DF.md)所选frequency-v2 | Ask强参考→下一可比冲击相对恢复减弱；稳定弱轮可先清旧DF、再产生新DF。M4相对退出备选另选 |
| LW@legacy / LW@COMMON / LW@P_LW | [LEGACY_COMMON](LEGACY_COMMON.md)、[COMMON](COMMON.md)、[P_LW](P_LW.md) | 共同观察固定多档残余减量，但发布、累计、生命周期有版本区别；旧M6不自动升级为独立P_LW |
| QR_BID@M17 | [M17主版](M17.md)；信息对应[P_QR v1.1](P_QR.md)的Bid保量分支 | 形成与70%/90%量界对应；原语抽取后的双侧、首次发布/可行动规则不能抹掉主M17允许待复核后准入的生命周期 |

| `R_C` / `S_C` | COMMON严格500ms受击轮／末100ms恢复≥50%的支撑 | **局部构件**；按策略冻结floor与寿命，不能把两轮S_C直接称作旧RF2，也不是AA原型750ms轮 |

| `pause@M7`、`retention@M11`、`profile@M20/M22`、`buffer@M23` | 对应M文件 | **局部构件**；分别为暂停、后档留存、多档构成、先加托后受卖，不新分配原语ID |

AA、SB在这23份主版和8份显式备选中均没有完整独立调用。它们保留在工具箱，不能为凑齐字母强加确认条件。SR、QO、RD、XR、XW主要用于已有显式备选；M21主版只有XW式语意、M23主版只有预加托语意，均不等于直接调用对应原语主版本。

## 4. 合并结论：合并研究入口，保留可执行分支

沿用并复核[FAMILY_CONSOLIDATION](FAMILY_CONSOLIDATION.md)的**12个方向家族＋M11公共过滤器**。23个编号不是23份独立信息。当前没有证成任何两个完整策略可删除一个、另一个原样替代。

| 决策 | 策略 | 共同骨架与保留项 |
|---|---|---|
| 已归并：卖压承接 | M1/M5/M9 | 持续强压／衰竭余波／衰竭后新复验三个阶段；保留当前AP、当前EX、历史EX的不同身份 |
| 已归并：买攻后回流 | M2/M7/M10 | 基础承接／暂停再攻／回流递减；M2与M10最接近，但AP重置及等待压力退出不同 |
| 已归并：承接与弱供 | M4/M12/M14/M19 | 相对弱化／当前恢复差／连续弱响应／轻攻增损；弱供的参考、强度比较和寿命不能合为一个DF布尔值 |
| 已归并：撤供与留托 | M6/M13/M15/M21 | 当前LW／撤供后受卖复验／撤供后BUY验证／两次SELL时单Ask无BUY净减；M21不强行等同LW/XW主版 |
| 公共过滤器 | M11 | 仅既定M4/M9/M10母版本；保留过滤开始时刻、原截止和实际成交政策 |
| 可复用规格骨架，暂不合并方向分支 | M16/M18 | 同档“历史严格支撑→第二次严格支撑→原Bid Maker”；分别比较时间和受损幅度。可共享定义章节，不能用RF替代两种增量 |
| 保留独立语意 | M3/M8/M17/M20/M22/M23 | 反击再守、失守修复、耗而不薄、买托前聚、供给后移、预增缓冲；阶段、数量路径或跨档范围有明确差别 |

M2/M10若以后统一为一个SOP入口，应有明确`BASE/DECAY`模式并冻结共用AP更新政策、轮次选择及等待规则；这会产生新执行规格，不能沿用旧成交结果。本次不创建这种尚未定义完整的运行模式。其他家族同理，不默认OR、AND、优先取胜率高的分支或共享提交额度。

### 可以直接去掉的重复表达

- EX已包含父AP历史；M1再写一个独立`AP_SELL成立`不能重复计分，更不能要求父AP仍当前有效。
- RF2内含两轮旧稳定；M5的r2/r1是附加比较。不能再将同一轮的“恢复≥50%”另命名BA作为第三份确认。
- M17主版的保量路径与QR_BID抽取的是同类信息；`M17+同一QR`不增加证据。
- M19的损失/成交比恶化、M18的该比值改善、M20前档占比提高、M22近档占比下降都是既有条件的推论，不再列为新原语确认。
- M11是执行前附加等待政策；它不创造一个独立买入方向，也不自动增加母信号的可用寿命。

这些简化只作用于本文的逻辑表示，不删除原冻结参数字段，不改变旧实现或统计口径。

## 5. 冲突审查：必须带上“同事件、同基线、同阶段”

| 易误合的组合 | 具体冲突／限制 | SOP处理 |
|---|---|---|
| M1当前EX与M5当前AP | 同父AP的EX确认不早于AP750ms寿命结束 | 作为先后阶段，不能做同父事实的当前AND；不同历史根不能泛称互斥 |
| M2被解释成EX_BUY→RF | `all_candidates`没有买压衰竭门槛 | 不增加EX；原策略的“受控”只由实际承接及生命周期表达 |
| M3被缩写为AP_BUY→RF | CA短窗反击不是持续AP，BA累计增量不是严格稳定或两轮RF | 保留CA→新BA，不能并入M2作为同一参数模式 |
| M7被写成AP→EX→AP | 暂停500ms的量界不同于EX750ms；AP2必须从联合就绪后新起 | 保留pause局部构件，早起AP2失败不能延后窗口冒充新AP |
| M8先弱后强，同时要求旧DF_BID当前 | 旧弱轮会因修复而自然结束；P_DF也不是该单弱轮 | 主版把弱轮当历史；RD备选另设明确历史交接 |
| M9复验后仍要求原EX750ms当前 | 新受击资格需在原种子有效期内取得，但复验可在其后完成 | 按M9历史接替，不把M1当前EX退出整体复制过来；反向AP结束旧EX的规则也依M9例外 |
| M10与M16/M18，同一对Bid轮 | M10 H2/H1≤0.90；M16≥1；M18≥2 | 同轮比较互斥；不同轮对可先后出现，不能用多信号票数理解 |
| M16与M18，同一对Bid轮 | H比区间分别[1,2]与[2,4]，只有2可能相交，还需其余量和时间条件 | 保留速度／幅度两维，不称完全互斥，也不称可替代 |
| M14与M19，同一对Ask轮 | u比[0.5,2]与[0.25,0.5]仅0.5相交；旧参考guard不同 | 允许有限交集；不推出整个候选集合重合或互斥 |
| M13旧托复验与M8 RD重建 | M13全程守旧floor并换更高新floor；M8先失守后重建，较低新floor不足维持旧量界 | 两种恢复路径分开，不能都简化为“最新S接管” |

## 6. Maker成交的统一解释

完整语意是：形成事实已可得→按对应版本的当前guard和原deadline准入→原Bid Maker真实成交。形成期的SELL/H不抵扣后来订单的前置队列；可见托量也不等于本单后方保护。价格只标识固定档位、合法挂单及评价分层。

“有效期间成交”只能说在**当时可知信息和冻结等待政策**下被动买入。M17等复核预算内、后续500ms轮尚未关闭时，以及撤单确认之前，都不能提前知道结果。候选成立、订单发送、生效、部分成交、信号失效、撤单确认必须分开；全部真实成交进入经济账，不能事后用恢复失败或结算亏损剔除。

先区分三种等待合同，避免所有Maker策略被统一成一种“托仍有效”：旧事实TTL与后续失败轮维护（M1–M10各自版本）；严格支撑floor＋策略当前guard（M12–M16/M18/M19/M21/M22）；自定义保量／结构／缓冲底线（M17/M20/M23）。M3还有原最优价身份约束，M11继承母合同。COMMON的5USDC、400ms、T15–T240等也不回填旧历史版本。

研究合并仅使同一问题有一个入口。若未来由用户模块实施合并订单政策，须先定义同根并发、只许一次提交时的归属、重复触发取消规则及费用/部分成交归并，再冻结独立版本。不能相加分支交易凑101笔或用各分支最佳价格段拼接trimmed PnL。任何结算概率或盈利改善仍待用户模块验证。
