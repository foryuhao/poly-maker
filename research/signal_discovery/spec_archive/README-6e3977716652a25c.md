# 盘口信号 SOP 工具箱

本任务的交付物是**盘口原语、信号组合研究与独立 Markdown SOP**。测试、回放、模拟器适配和交易验证由用户的信号测试模块负责；本任务不运行或修改它们。价格只用于识别档位、合法挂价和分层评价，信号不使用价格涨跌、外部 BTC 价格或未来结算。

## 先区分原语与策略

用户已要求同时探索DF、BA这类底层模式。[原语工具箱](PRIMITIVES.md)单独登记：[SR「短补回落」](P_SR.md)、从M17提取并扩展Ask侧的[QR「耗而不薄」](P_QR.md)，以及新跨侧顺序假说[XR「攻后跟挂」](P_XR.md)。新增已有LW的独立双侧规格：[LW「疑似退量」](P_LW.md)，Ask为疑似撤供、Bid为疑似撤托。另新增[RD「回补回吐」](P_RD.md)，研究真实恢复后无新增打单时的回吐。五份均SPEC_ONLY；LW是已有名称推广，QR不重复计为M17之外的新独立证据。旧AP/AA/RF/LW/EX/DF/CA/BA沿各自版本引用，不强行统一旧参数。

当前仍有23份M分支SOP，另有5份原语SOP。原语没有自动执行权限；组合还需冻结根事件、原锚、等待和经济账本。小时简报分别列出两类文件。

最新原语：[RD「回补回吐」](P_RD.md)要求500ms真实受击轮严格恢复至少50%，尾段起零新增原档打单；随后首次回吐至原轮20%恢复线并保持100ms，须在种子后750ms内发布。确认后最多750ms、守40%恢复上界。旧同轮支撑在跌破40%时已失效，不能等RD确认才撤单，也不能将两者算作当前双重确认。它是观察路径，不是精确撤单或结算优势证明。

最新完整组合：[M12「卖补回吐留托」](M12.md)（`m12-rd-ask-supported-v1`）在RD_ASK恢复种子确认时，只选此前750ms内已有效且强度可比的Bid支撑，冻结后等RD最终确认，再按原P一次准入Maker。中途Bid失效不换轮；RD原750ms先到，首次发送最多有350ms窗口。Ask按RD原40%恢复上界维护，不套主版新Ask轮50%恢复退出。主M12/RD均不改，新分支未测试。

已有LW交付：[LW双侧SOP](P_LW.md)保留30%总减量、20%残余减量、50%残余占比和100ms保持，明确严格750ms形成发布截止、确认后750ms寿命、累计打单不滚动，以及首个发布失败不重选。原买一守住时，后两档退量仍可使LW_BID成立；因此M6式原档留托不等于买侧整体深度保留。本版独立选用，未改变旧M6或COMMON，不新增“双侧退量”编号。

最新M6家族备选：[撤供期多档留托](M6.md)（`m6-fixed-bid-retention-v1`）在新Ask LW开始前冻结已有直接成交RF，并同步保留Bid原三档各90%数量，LW确认时一次准入，沿用两组件原截止。它替代的是含糊的“未出现LW_BID”判断，没有在750ms寿命后再追加500ms等待；相同总量不能替代逐档保留，旧基线LW_BID仍可能共存。主M6及原语规格不变，分支尚未测试。

最新查重：[QR/XR组合审查](PRIMITIVE_COMPOSITION_REVIEW.md)证明，在同档同量口径、QR先确认且持续有效的固定配对中，XR数量底线更高，QR旧数量底线重复；但QR的历史受卖证据与更早原截止仍须保留。反向XR先、QR后按真实成交前Q0R比较，两种顺序不能混用。SR、QR、XR继续独立保存，不新增“双重承接”编号或改变执行规则。

跨侧原语XR：一侧主动成交先达规模，另一侧此前平稳、形成期未受消耗的原档再净增并留存；BID/ASK对称，未把时间先后当因果。确认理论范围为首笔后大于100ms、小于650ms，确认后最多3s；不称已承接目标侧卖压，也不自动执行。与M20/M23、SR/QR的同窗冲突及来源边界写入独立SOP。

最新接续组合：[M23](M23.md)增加`m23-xr-seeded-sell-test-v1`「攻后加托复验」。XR种子在发布交接及首笔新SELL前守80%；首笔合格SELL时转历史种子、切20%底线，经500ms真实受卖验证后才Maker。另加种子发布前零SELL及逐笔100ms复核，原3秒截止不变。不能同时要求XR的50%当前底线，否则末段只剩50%单点。M23主版和XR原语未改，未运行测试。

已有组合交付：[M17](M17.md)同文件增加`m17-qr-sr-ask-v1`「保量配短补」显式备选：已有QR确认后只选首个新SR_ASK，失败不换后一个，保留QR与SR原截止，并冻结一次准入及Maker退出。QR同时升至v1.1，补回M17原有的发布点90%数量检查；旧QR v1与新版可能产生不同样本，不能混池。M17主版与SR参数未变，未新增M编号或运行测试。

[原语组合审查](PRIMITIVE_COMPOSITION_REVIEW.md)排除“SR确认后再启动完整QR且要求两者当前有效”的时序；QR与SR增厚同步开始也不足COMMON的400ms提交余量。后续优先已有/较早形成的QR配新SR。BA与SR的同档分歧、SR与LW共享回落，以及SR增厚可能提前结束旧弱供也已写清；本轮不改原语/M参数，不新增编号。

## 家族优先级与历史分支顺序

当前先研究“承接与弱供”和“撤供与留托”的分支增量，以M4/M6初筛为待核对参照；随后梳理“卖压承接”“买攻后回流”的阶段差异，再依能力与反馈安排其余独立机制。新编号先做家族查重，本轮考虑的“换手偏买”暂不分配M24。以下M12–M23数字顺序保留为历史交接记录，不能当作当前独立主线排序。

历史首批顺序为M12、M13、M14、M15、M16，M17、M18、M19、M20、M21作为新机制依次追加交接；收到测试模块的能力与频次反馈后再调整。依据是完整交易语意与可观测性，**不是已测收益排名**。M12/M14研究两侧真实冲击后的恢复差；M13研究撤供后的新增承接；M15研究撤供后的真实买入接替；M16研究受击不减时的恢复提速；M17研究无需明显低谷也能成立的成交后队列保量；M18研究卖量加大但数量损失不增；M19研究买量减小而Ask损失扩大，并配近期Bid承接；M20研究真实SELL后固定三档中的买量前聚；M21研究两次SELL观察窗对应同Ask无直接BUY时的净减量。M16时间路径、M17/M20逐笔复核、M18/M19/M21轮末来源、M20三档连续结构及M21零BUY的完整性都需要输入能力支持，不能从SOP预测交易数。

历史交接中M22追加为第11顺位：研究真实BUY后固定Ask三档的近端减量、后方增量与总量近似保留。需要原Bid支撑、固定四档路径及成交来源；不会因多看档位而默认提高胜率，也当时未调整前十项顺序；当前研究组织按上方家族索引。

历史交接中M23追加为第12顺位：先增量并保留，再由种子后的首笔SELL验证缓冲；可在没有恢复时成立。原种子起3秒到期，末段上界仅用于形成，等待只守固定下界；需要直接SELL完整性、原档数量来源和阶段顺序。没有收益或频次验证。

已有信号的新执行过滤、已有条件的简单交集不会自动获得新的M编号；后续新增前先查重。新候选必须解释Maker成交发生在什么阶段、等待期间什么仍然有效、何种观察会否定机制。

2026-11-11定义自查：M12–M15升至v1.1，补清配对前失效、联合种子之后的新受击和形成期限端点，不能与v1混池。M13联立旧floor与相对冲击门槛，明确区间为空时无法形成；该推导没有新增数值阈值。M4补充源码先清旧DF、再判断新DF的状态顺序，信号版本不变。旧文本按hash归档。
