## 定义边界

- [LEGACY_COMMON.md](LEGACY_COMMON.md)供M1–M11引用，忠实区分已有AP/RF/EX/LW、旧滞回保持和不同实现的替换行为。以2026-11-11本次读到的源码及最近运行版本为依据；“代码中存在”不等于“正在部署”。
- [COMMON.md](COMMON.md)供M12–M22引用，是新假说的轮次、等待guard和建议Maker执行合同；M17使用750ms保量窗及固定初量底线，M20使用500ms三档结构窗及联合数量条件，两者均明确替换RF形成和恢复率退出。M21另有非RF的Ask净减量上界，等号允许；M22以固定Ask三档结构代替Ask RF，Bid仍用旧支撑。不得自动套到M1–M11历史样本上。
- [INPUT_CAPABILITIES.md](INPUT_CAPABILITIES.md)列明直接/镜像成交、混合时钟和深度新总量的交接陷阱；读到字段不等于已验证录制支持。
- [TRADE_TIMING_CAPABILITIES.md](TRADE_TIMING_CAPABILITIES.md)说明同批消息、接收/采集时间及缺失成交身份的限制；成交时间结构方向暂不单独编号。
- [COMPLEMENT_PROVENANCE.md](COMPLEMENT_PROVENANCE.md)审查互补盘口是否只是同一经济事件的多个视图；当前暂缓新增跨侧共振信号。M19属于单token的Ask响应比较，不是该暂缓方向。
- [MECHANISM_MAP.md](MECHANISM_MAP.md)比较M12–M22的信息增量、非父子样本、同轮互斥条件及配对前的失效检查。
- [CAUSAL_HANDOFF_REVIEW.md](CAUSAL_HANDOFF_REVIEW.md)统一解释窗口终点、可得发布和新阶段首笔的边界；逐策略区分当前支撑与历史参考。
- [MAKER_FEASIBILITY.md](MAKER_FEASIBILITY.md)说明固定底线与排队成交的共同可行条件，区分形成前成交量、入队后流量及物理/反事实队列；不新增信号或修改执行参数。
- [MAKER_ADMISSION_REVIEW.md](MAKER_ADMISSION_REVIEW.md)汇总形成、组件、信号及撤单四种期限，说明候选确认但剩余不足400ms时为何不能提交；不新增执行模式。
- [ABSENCE_EVIDENCE_REVIEW.md](ABSENCE_EVIDENCE_REVIEW.md)区分零记录、输入完整性与市场无成交，说明M21 v1.1的直接来源、同批发布和晚发现BUY边界；不改变旧信号。
- [DEPTH_BATCH_SEMANTICS.md](DEPTH_BATCH_SEMANTICS.md)区分快照状态、逐项增量与批次发布，给出M20/M22总量条件的数组顺序依赖；不把输入序列当交易所内部顺序证明。
- [RESEARCH_PROTOCOL.md](RESEARCH_PROTOCOL.md)说明交付、逻辑自查、对测试模块的验收需求和小时简报边界。

## 新信号优先级

首批顺序M12、M13、M14、M15、M16暂保留，M17、M18、M19、M20、M21作为新机制依次追加交接；收到测试模块的能力与频次反馈后再调整。依据是完整交易语意与可观测性，**不是已测收益排名**。M12/M14研究两侧真实冲击后的恢复差；M13研究撤供后的新增承接；M15研究撤供后的真实买入接替；M16研究受击不减时的恢复提速；M17研究无需明显低谷也能成立的成交后队列保量；M18研究卖量加大但数量损失不增；M19研究买量减小而Ask损失扩大，并配近期Bid承接；M20研究真实SELL后固定三档中的买量前聚；M21研究两次SELL观察窗对应同Ask无直接BUY时的净减量。M16时间路径、M17/M20逐笔复核、M18/M19/M21轮末来源、M20三档连续结构及M21零BUY的完整性都需要输入能力支持，不能从SOP预测交易数。

M22追加为第11顺位：研究真实BUY后固定Ask三档的近端减量、后方增量与总量近似保留。需要原Bid支撑、固定四档路径及成交来源；不会因多看档位而默认提高胜率，也不调整前十项顺序。

已有信号的新执行过滤、已有条件的简单交集不会自动获得新的M编号；后续新增前先查重。新候选必须解释Maker成交发生在什么阶段、等待期间什么仍然有效、何种观察会否定机制。

2026-11-11定义自查：M12–M15升至v1.1，补清配对前失效、联合种子之后的新受击和形成期限端点，不能与v1混池。M13联立旧floor与相对冲击门槛，明确区间为空时无法形成；该推导没有新增数值阈值。M4补充源码先清旧DF、再判断新DF的状态顺序，信号版本不变。旧文本按hash归档。

机制审查还明确：M14不天然属于M12的子集；M10的冲击递减与M16的冲击不减不能由同一对轮次同时确认。M16新增的时间比较不能混用received与available，也不能用被后续跌破的早期回补冒充最终稳定恢复。全部M12–M20仍为SPEC_ONLY，没有测试或结算概率提升结论。

M16/M17随后升至v1.1：排除用其他档位或BBO刷新时间代替锚档数量事件；核对关闭窗口到发布之间的中间失效。M17还明确该阶段的新成交复核、首次提交前的待复核门槛，以及100ms接收起算且可得时刻须严格早于截止的规则。它们会改变可交易样本，须按版本分开；旧稿已归档。

新增M18把“更大成交下的减损幅度”与M16的恢复速度、M17的绝对保量分开。L/H改善是已有数量门槛的派生结果，不作为第二条独立证据，更不称为精确吸收效率。M18仍为SPEC_ONLY；两轮约1秒形成、确认后最多3秒等待是定义，不是频次或收益证明。

Maker可行性审查：在明示的FIFO假设下，固定正底线与有效期内成交需要后续队列更替，单靠初始厚度不足；形成前H不能给新订单抵扣前置队列。本单自有量与外部量、未改写历史book的模拟与物理队列必须区分。该推导不证明任何候选的成交率，也不改变M1–M18参数。

现有反馈核对：本次有限读取的是M5–M10启动清单、阶段进度与内存核对摘要。21时复查读到候选进度24/25、内存核对26/288；另有288窗口PASS明确是人工加速生命周期检查，并非连续24h经济验证。尚未取得与本目录新候选版本对齐的实际成交经济结果。signals计数不能代替已结算订单数，规格文件也不能证明运行实例采用了它。核对范围和来源hash见[反馈记录](../signal_discovery/feedback_latest.json)；这不表示其他路径不存在结果，也不推断进程存活。当前新增候选的研究顺序继续按机制与可观测性保留。

此前新增M20买托前聚，保持三个原价档固定，比较锚档增厚与后方有限减量，并要求固定总量不减；不称同一订单搬家。已明确该结构增加前置队列的执行代价，暂列第9研究顺位。
